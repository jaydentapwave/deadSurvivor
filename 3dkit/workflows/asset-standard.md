# 에셋 규격과 정식 제작 경로 (틀)

게임에 들어가는 3D 에셋(캐릭터·몬스터·소품·지형 재질)에 적용한다. [핵심 규칙](core-rules.md)이 우선한다. 이전 프로젝트의 050 에셋 규격에서 틀과 공통 규칙을 옮겼다(2026-11-03). **미드폴리 숫자는 아직 정하지 않았다.** 출발 계획(프로젝트의 `docs/plan/001-출발-계획.md`)의 룩데브 단계에서 정하고 이 문서를 고친다.

- 숫자의 원본은 에셋 카탈로그(JSON, H3에서 만듦) 하나다. 이 문서의 표는 카탈로그에서 뽑은 출력으로 바꾼다.
- 카탈로그의 등록 목록이 **채택 목록**이다. 빌드 장면은 등록된 폴더의 에셋만 쓴다.

## 1. 규격표

### 숫자를 정하는 방법 (이전 050에서 쓴 방법)

1. 게임 카메라(종류·각도·거리 또는 직교 크기)를 먼저 고정한다.
2. 목표 화면(예: 1080p 폰)에서 캐릭터가 몇 픽셀 높이로 보이는지 잰다.
3. 텍스처는 "몸이 화면보다 2~3배 촘촘한" 크기로 정한다. 더 크면 보이지 않는 데 메모리를 쓴다.
4. 삼각형은 [성능 예산](performance.md)에서 거꾸로 나눈다: (웨이브 최대 화면 삼각형 예산 − 맵) ÷ 동시 등장 수.
5. 정한 값을 룩데브 장면에서 목표 셰이더·조명으로 보고 사용자가 고른다.

### 미드폴리 출발 제안 (에이전트 제안, 사용자 확인 전)

모바일을 유지한다는 가정의 출발값이다. 플랫폼이 PC로 바뀌면 다시 정한다.

| 종류 | 삼각형 목표/상한 | 텍스처 | 뼈 | 재질 | 그림자 |
|---|---|---|---|---|---|
| 영웅 | 6,000 / 10,000 | 1024² 기본색(+ 필요 시 노멀) | 70 | 1 | 실제 |
| 몬스터 | 2,500 / 4,000 | 512² | 필요 시 | 1 | 바닥 원 또는 실제(측정 뒤 결정) |
| 보스 | 10,000 / 15,000 | 1024² | 70 | 1~2 | 실제 |
| 작은 소품 | 300 / 1,000 | 아틀라스 공유 | 0 | 1 | 없음 |
| 큰 소품(나무·큰 바위) | 1,500 / 3,000 | 아틀라스 공유 또는 512² | 0 | 1 | 실제 |
| 랜드마크(맵당 3개 이하) | 5,000 / 8,000 | 1024² | 0 | 1~2 | 실제 |

### 이전 로우폴리 값 (참고)

| 종류 | 삼각형 목표/상한 | 텍스처 | 근거 |
|---|---|---|---|
| 영웅 | 1,500 / 2,000 | 256² | 직교 크기 6·55°에서 영웅 약 41px(1080p) |
| 몬스터 | 600 / 1,000 | 128² | 약 27px |
| 소품·지형 | 200~5,000 | 없음(팔레트 칸 UV) | 면마다 팔레트 칸 하나 |

## 2. 공통 규칙 (이전에서 그대로)

- **원점**은 발밑 가운데다.
- **정면**은 +Z이고, 프리팹 안 `Visual` 아래 모델에 굽는다. 회전 보정값(yaw offset)을 코드에 두지 않는다. 이전 프로젝트에서 표시 코드가 `Visual` 회전을 매 프레임 덮어써 방향 사고가 두 번 났다(046-15, S3-21).
- **프리팹 구조**: 루트(발) → `Visual` → 높이를 맞춘 모델.
- 새 모델은 정면 카메라 줄 세우기 캡처로 앞 방향을 확인한다.
- 텍스처 가져오기: 밉맵 켬, Bilinear(또는 Trilinear), Clamp. Android·iPhone은 ASTC(크기·블록은 규격값). 알파 사용 여부는 셰이더 규칙과 함께 정한다.
- Tripo 원본은 삼각형이 매우 많다(이전 시험 바위 약 50만). `face_limit`을 규격 목표로 주고, 상한을 넘으면 Blender로 줄인다. 생성 옵션과 인수 기준은 [Tripo 생성 기준](tripo-generation-standard.md)을 따른다.

## 3. 색과 셰이더 (결정 필요)

이전 프로젝트는 **팔레트가 유일한 색 원본**이었다. 소품·지형은 면마다 팔레트 칸을 UV로 가리켰고, 캐릭터는 텍스처를 팔레트 색으로 바꿨다(OKLab 최근접 + 3×3 다수결). 셰이더는 공용 1개였다. 기록은 `docs/art/previous/`.

미드폴리에서는 텍스처 세부가 핵심이라 그대로 쓰기 어렵다. 룩데브에서 고를 후보:

| 후보 | 하는 일 | 장점 | 단점 |
|---|---|---|---|
| A. 팔레트는 색 기준으로만 | 텍스처는 자유, 팔레트는 색 대조 검사·조명 톤 기준 | 미드폴리 세부 유지, 화면 통일감 검사 가능 | 색이 흩어질 수 있음 |
| B. 손그림풍 텍스처 + 공용 툰/스타일 셰이더 | 셰이더가 음영 단계·림·색 보정을 통일 | 스타일 통일을 셰이더가 맡음 | 셰이더 개발이 먼저 필요 |
| C. 이전 방식 유지(텍스처 팔레트화) | 이전 도구 그대로 | 빠름 | 미드폴리 세부가 뭉개짐 |

허용 셰이더 목록은 이 결정 뒤에 정한다(이전: 공용 팔레트 셰이더, 물 셰이더, URP Unlit·Particles/Unlit).

## 4. 정식 경로 (H3에서 만듦)

에셋은 정식 도구 하나로만 만든다([하네스 설계도](harness-blueprint.md) H3). 만들기 전까지는 수동으로 만들되 아래 순서와 기록을 지킨다.

**새 에셋 하나를 넣는 순서**

1. 카탈로그에 항목을 추가한다: 종류, 폴더, 원본(직접 제작 또는 Tripo 요청).
2. 유료 생성이면 사용자 승인 원문과 상한을 카탈로그 예산에 적는다(핵심 규칙 7절).
3. 생성: 요청 고정 → 드라이런 → 제출 → 받기. 동작이 필요하면 리깅·애니메이션.
4. 삼각형이 상한을 넘으면 Blender로 줄인다.
5. 텍스처 처리 → Unity 가져오기 → 규격 대조.
6. 정면 줄 세우기 캡처와 짧은 Play 1회로 확인하고, 사용자가 화면을 본다.
7. 성능 한 줄을 잰다(핵심 규칙 1절).

## 5. 위치와 소유

- 정식 에셋은 `Assets/<게임>/Art/` 아래 종류별 폴더에 둔다. 시험 에셋은 `Assets/<게임>/Art/Tests/` 또는 시험 장면 폴더에 두고 빌드 장면이 참조하지 않는다.
- 폴더마다 내용을 만드는 도구(소유자)를 이 절에 표로 적는다. 소유 도구가 아닌 곳에서 내용을 고치지 않는다.
- 에셋을 옮길 때는 `.meta`와 함께 옮겨 GUID를 유지한다.
