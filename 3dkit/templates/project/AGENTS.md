- `<개인 프로젝트 / 회사 프로젝트>`다. 문서·계획·결정·검증 결과는 이 프로젝트 폴더 안에만 기록한다.

- 전역 Codex/Claude 설정을 바꾸지 않는다. 이 프로젝트 규칙은 여기서만 유지한다.
- `<참고 원본으로 읽기만 하는 이전 프로젝트가 있으면 경로와 함께 적는다>`
- 이 지침은 에이전트의 작업 범위를 제한한다. 운영체제 백업·앱 자체 기록까지 막는 보안 장치를 뜻하지 않는다.

## 작업 절차

- 먼저 [핵심 규칙](3dkit/workflows/core-rules.md)을 읽는다. 다른 문서와 부딪히면 핵심 규칙이 우선한다.
- [현재 상태](docs/현재상태.md) → 해당 계획·기획 → 코드 → 필요한 검증 순서로 읽는다.
- 확정된 사용자 결정, 첫 구현 기준안, 미정 수치를 구분한다. 제안이나 테스트 통과 기록을 구현 완료로 올려 말하지 않는다.
- 문서만 바꾸면 링크·일관성을 확인한다. 런타임 변경은 컴파일과 짧은 Play로 확인하고, 시각 변경은 캡처를 남긴다.
- Unity 조작은 unity-cli 스킬을 읽고 `--project-path`로 대상 프로젝트를 지정한다. 여러 편집기가 동시에 열려 있을 수 있다.
- 기존 작업물을 덮어쓰지 않는다. 지우거나 덮어쓰기 전에 대상을 확인한다.
- 검증 결과는 PASS/FAIL/BLOCKED/NOT_RUN을 구분하고 실행 시각과 근거 경로를 남긴다. 과거 로그를 현재 성공으로 쓰지 않는다. 도구가 없거나 실행할 수 없으면 성공으로 보고하지 않는다.

## 작업 방식 선호 — 에이전트 공통

Codex·Claude 등 어느 에이전트를 쓰든 이 절이 원본이다. 에이전트별 메모리에 따로 두지 않는다.

- 사용자에게 하는 답변·보고는 한국어로 쓴다. 코드 식별자·파일 경로·명령은 원문 그대로 둔다.
- 단계마다 놓친 것(검토자나 사용자가 찾았거나 뒤늦게 발견한 것)을 그 작업의 기록에 원인과 "워크플로우 갱신 후보"와 함께 남긴다. 작업이 끝나면 후보를 워크플로우 문서에 반영하고 반영 여부를 표시한다.
- 전체 작업 시간과 단계·활동별 시간, 토큰 사용량(Claude·Codex·하위 에이전트)을 기록한다. 오래 걸리고 효율이 낮은 곳, 토큰을 많이 쓴 곳을 개선 후보로 남긴다. 집계 도구는 [하네스 설계도](3dkit/workflows/harness-blueprint.md)의 `session_time`이다.
- 긴 작업은 중간에 진행 상황을 공유한다. 실행 중·완료·중단·대기를 구분해 말하고, 끝난 작업을 계속 진행 중인 것처럼 말하지 않는다.
- 평가는 냉정하고 솔직하게 한다. 부족한 점을 성과 표현으로 덮지 않는다.
- 세부를 다듬기 전에 전체 느낌을 먼저 확인할 수 있게 진행한다.
- 워크플로우·검사 항목은 다시 넣을 필요가 없다고 확실할 때만 뺀다.
- 검사를 추가할 때 뺄 수 있는 검사도 함께 적는다. 비용이 큰데 결함을 한 번도 잡지 못한 검사는 단계 회고에서 빼기 후보로 사용자에게 제시한다.
- 사용자는 여러 에이전트를 동시에 쓴다. 작업 시작과 커밋 전에 Git 상태와 최근 커밋을 확인하고, 다른 세션의 변경을 덮거나 같은 파일을 동시에 고치지 않는다.
- 하위 에이전트의 모델·effort는 메인이 작업 성격에 맞게 정한다. 사용자가 지정하면 그 지정을 따른다.
- 독립 검토는 가능하면 만든 쪽과 다른 모델 계열에 맡긴다. 예: GPT가 생성한 이미지는 Claude가, Claude가 바꾼 문서·코드는 Codex가 검토한다. 쓸 수 없으면 같은 계열의 독립 하위 에이전트로 검토하고 그 사실을 기록한다.
- 도구 위치·명령·에이전트별 차이는 [도구 연결](3dkit/workflows/tools.md)과 이 프로젝트의 [개발 환경](docs/개발환경.md)을 따른다.
