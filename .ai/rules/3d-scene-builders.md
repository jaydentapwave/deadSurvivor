# 장면 빌더 공통 규칙

장면·자산을 코드로 다시 만드는 빌더(Editor C# 스크립트)에 공통으로 적용한다. 핵심 규칙(art 팩 `.ai/rules/art-core-rules.md`)이 우선한다. 이전 프로젝트의 빌더 규칙(046 놓친 것, 047 기록, 048 하네스 갱신)에서 프로젝트 이름을 빼고 옮겼다(2026-11-03). 사례는 art 팩 스킬의 `references/교훈-이식.md`에 있다.

## 1. 장면 소유와 순서

- 한 장면은 **소유 빌더** 하나가 만든다. 다른 빌더가 같은 장면에 붙이는 것(캐릭터 세트, 효과, 조명·밤 화면 등)은 소유 빌더가 다시 붙인다.
- 다시 만드는 순서는 그 장면의 기록 문서에 한 줄로 적는다.
- 새 빌더가 소유 장면을 고치면 소유 빌더의 다시 붙이기 목록에도 넣는다. 넣지 않으면 다음 전체 빌드에서 조용히 사라진다.
- 대체된 빌더는 지우지 말고 실행하면 거부하고 새 경로를 안내하게 둔다.

## 2. 저장 뒤 다시 열어 확인

- 빌더는 장면을 저장한 뒤 **다시 열어** 핵심 참조(캐릭터 세트, 효과 재질, 조명, 후처리 볼륨 등)가 실제로 저장됐는지 확인하고, 아니면 예외로 멈춘다(예: `ACTORS_NOT_SAVED`).
- 메시·재질 처리 뒤에는 저장된 프리팹을 다시 읽어 잰다.

## 3. GUID 유지

- 다시 만드는 빌더는 장면·자산 파일을 지우고 새로 만들지 않는다. 같은 경로에 **내용만 덮어써** GUID를 유지하고, GUID가 바뀌면 멈춘다(예: `SCENE_GUID_CHANGED`).
- 빌드 설정의 장면 경로·GUID 일치는 커밋 전 gate의 정적 참조 검사가 본다(하네스 설계도 H4, 3d-art 팩 스킬의 `references/harness-blueprint.md`).

## 4. 부작용 파일 되돌리기

- Play·장면 저장·캡처 뒤 동적 글꼴 캐시 등 원하지 않는 파일이 바뀐다. 목록은 하네스 설정의 `side_effect_files`다.
- 빌더·캡처 명령은 `protect.py run -- <명령>`으로 감싼다. 실행 전 깨끗했던 파일만 되돌리고, 실행 전에 이미 바뀌어 있던 파일(사용자 작업일 수 있음)은 건드리지 않고 알린다.
- 근본 해결 후보: UI 글꼴을 정적 아틀라스로 만든다. 새 프로젝트는 처음부터 정적 아틀라스로 시작하는 것을 권한다(이전 프로젝트에서는 사용자 결정 전으로 남았다).

|---|---|
| 겹치는 평면(지면·흙·길·물)은 높이 순서를 표로 정하고 빌더 상수로 둔다 | 046-4 |
