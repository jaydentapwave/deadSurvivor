# 화면 배치 — 안전 영역·화면비·방향 (모바일)

UI(Canvas, 표시줄, 팝업, 버튼, 판넬)나 카메라·게임 판 배치를 **만들거나 바꿀 때마다** 이 문서를 확인한다. 레포 규칙이 있으면 그것이 우선이다.

- 상태: 새 규칙(킷 0.14.3). 출처 사례: 타워 디펜스 검증 프로젝트에서 9:16(540×960) 캡처만 보고 UI·카메라를 완료로 보고했는데,
  사용자가 안전 영역이 빠진 것을 발견했다. 확인해 보니 위 표시줄은 노치 밑에, 아래 판넬은 홈 표시줄 밑에 깔렸다. 직교 카메라가 높이를 고정해서
  9:19.5 화면에서는 9칸 지도의 양끝 0.8칸이 잘려 끝 열의 출현 지점·건설 자리가 가려졌고, 자동 회전도 켜져 있었다. 리뷰 4종과 Play 캡처가 모두 통과했지만, 아무도 다른 화면비를 보지 않았다.

## 규칙

1. **안전 영역**: 화면 가장자리에 붙는 UI(위 표시줄, 아래 판넬, 모서리 버튼, 전체 화면 팝업의 닫기 버튼)는 `Screen.safeArea` 안에 둔다.
   Canvas 루트 아래 안전 영역 판넬 하나가 앵커를 맞추고, 가장자리 UI는 그 판넬을 기준으로 앵커한다. 배경(색·그림·딤)은 안전 영역 밖까지 채운다.
   화면 크기나 `safeArea`가 바뀌면(회전, 창 크기, 기기 시뮬레이터 전환) 다시 맞춘다.
2. **화면비**: 9:16 하나만 가정하지 않는다. 최소 **9:16, 9:19.5(노치), 9:21, 3:4(태블릿)**에서 게임 판(지도·보드)과 UI가 잘리거나 겹치지 않아야 한다.
   - 직교 카메라의 `orthographicSize`는 높이 기준이라, 세로로 긴 화면에서는 양옆이 잘린다. 판 전체(가로·세로)가 들어가도록 크기를 계산하고, 남는 공간은 바닥·배경으로 채운다.
   - 계산할 때 UI가 덮는 영역(위 표시줄, 아래 판넬)과 안전 영역 여백을 뺀다. 판이 UI 밑에 깔리면 잘린 것과 같다.
   - 카메라·UI 배치 계산은 화면 크기와 안전 영역을 입력으로 받는 순수 함수로 두면 엔진 없이 시험할 수 있다.
3. **방향**: 세로 게임이면 Player Settings의 기본 방향을 세로로 고정하고 자동 회전을 끈다(가로 게임이면 반대). 프로젝트 템플릿 기본값(자동 회전)을 그대로 두지 않는다.
4. **CanvasScaler**: Scale With Screen Size의 기준 해상도와 match 값을 의도해서 정하고, 왜 그 값인지 한 줄 남긴다. 픽셀아트면 정수 배율이 깨지는 화면비를 적어 둔다.
5. **기획서**: 화면이 바뀌는 기능은 수용 기준에 "노치 기기에서 가장자리 UI가 가려지지 않는다, 긴 화면·태블릿에서 판이 잘리지 않는다"를 넣는다.
6. **확인과 보고**: UI·카메라 변경의 보고에는 2절 화면비 목록을 어떻게 확인했는지 적는다(Game 뷰 해상도별 캡처, Device Simulator의 노치 기기, 또는 배치 함수 시험).
   한 화면비만 봤으면 나머지는 "화면비·안전 영역 미확인"으로 적는다. 사용자가 확인을 맡겠다고 하면 확인할 화면비·기기 목록을 보고에 넘긴다.

## 하지 않는 것

- 가장자리 UI를 Canvas 루트(화면 끝)에 바로 앵커하기
- 9:16 캡처 한 장으로 "UI 완료"라고 보고하기
- 화면 끝 열·행에 게임 요소가 있는데 카메라를 높이만으로 맞추기
- 자동 회전을 켠 채 한 방향 전용 화면을 만들기
