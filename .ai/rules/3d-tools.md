# 도구 연결 — 3D 생산 도구

3d-art 팩 규칙. 3D 에셋 정식 경로가 쓰는 외부 도구(Unity CLI·Tripo·Blender)와 키트 도구 명령의 사용법과 함정이다. 확인한 버전은 표에 적고, 버전이 바뀌어 다르게 동작하면 고친다. 프로젝트별 경로(설치 위치, 키 파일)는 `3dkit.config.json`과 프로젝트의 개발 환경 문서에 둔다. Codex(이미지 생성·검토)는 art 팩의 `.ai/rules/art-tools.md`에 있다. 키트 도구는 `.ai/3d-art/tools/`에 있고, 프로젝트 루트에서 `3dkit.config.json` `harness.python`의 파이썬(numpy·Pillow)으로 돌린다.

| 도구 | 사용법 | 주의 |
|---|---|---|
| Unity CLI (1.0.0-beta.15 확인) | 열린 편집기를 제어한다. `unity status --until-ready --project-path <루트>`, `unity command script eval --project-path <루트> -- --code '<C#>'`, `unity command script run ...`, `unity recompile --project-path <루트>`. 편집기 열기: `unity open <루트>` | **편집기가 여러 개 열려 있을 수 있으니 항상 `--project-path`를 준다.** Claude Unity 플러그인 0.1.6-beta는 옛 명령 이름(`unity command eval`, `editor_play`)을 안내하니 실제 CLI 이름을 쓴다. 로그인하지 않아도 `unity open`은 열린다(경고만) |
| Unity 편집기 화면 | 캡처·성능 측정은 메인 탭이 **도킹된 Game 창**이어야 한다. Device Simulator 모드면 Game 창이 없어 실패한다(`Sequence contains no elements`). 되돌리기: `script eval`에서 `PlayModeView.SwapMainWindow(GameView 타입)` | 새로 연 떠 있는 Game 창은 크기가 맞지 않는다. 게임을 그리는 창이 둘이면 통계가 두 번 잡힌다. 캡처 저장 경로(`capture game_view --save_path`)는 `Assets/` 기준이다 |
| Unity 6.4 API | `FindFirstObjectByType`은 폐기(컴파일 오류) → `FindAnyObjectByType`. `UnityStats`에 `batches`·`trianglesLong`은 없고 `drawCalls`·`setPassCalls`·`triangles`·`shadowCasters`·`frameTime`은 리플렉션으로 읽힌다 | `script run`은 같은 이름의 정적 메서드가 둘이면 진입점을 거부한다 |
| Unity Play 측정 | `PlayerSettings.runInBackground`를 켜고 재고 끝나면 되돌린다 | 끄고 재면 백그라운드에서 3fps 같은 값이 나온다 |
| Tripo CLI (0.8.1 확인) | npm으로 프로젝트 `output/tools/tripo/`에 설치(Git 제외). 환경변수 `TRIPO_HOME=<루트>/output/tripo-state TRIPO_ANALYTICS_ENABLED=0 TRIPO_NO_UPDATE_CHECK=1`. 키는 `.env.local`의 `TRIPO_API_KEY` | 키를 출력·기록하지 않는다. `.env.local`은 Git 제외. 유료 생성은 [Tripo 생성 기준](3d-tripo-generation-standard.md)과 핵심 규칙(`.ai/rules/art-core-rules.md`) 7절. 네트워크 오류 뒤 재전송 금지 |
| Tripo 응답 대기 | `assets.py gen submit`은 기다리지 않는다. `assets.py gen fetch <에셋> --wait 600 < /dev/null`을 백그라운드로 돌린다. 끝나면 알림이 온다 | 지난 58건: 중간값 3.1분, 최대 5.4분(2026-11-06). `--wait`는 900초까지(`guard.py`가 막는다). `FETCH_PENDING`이면 `gen status`로 보고 fetch를 다시 부른다(추가 과금 없음). **다시 제출하지 않는다.** 제출 뒤 15분이 지나도 결과가 없으면 `guard.py`가 턴을 끝낼 때와 새 메시지 때 확인을 시킨다. hook은 잠든 에이전트를 깨우지 못하므로 깨우는 것은 `--wait` 만료다. `SUBMITTING`·`SUBMISSION_UNKNOWN`은 제출 여부를 모르는 상태라 `gen reconcile` 뒤 사용자에게 알린다 |
| Blender | `/Applications/Blender.app/Contents/MacOS/Blender`(배경 실행 `-b -P <스크립트>`) | 감량·아틀라스·뼈대 등 모델 자체를 바꿀 때만 쓴다. 그림자·인스턴싱·묶음은 Unity에서 끝난다. 스크립트 오류를 종료 코드로 받으려면 `--python-exit-code 1`을 붙인다(없으면 오류에도 0으로 끝난다, B53) |
| Blender 후처리 명령 (2026-11-04) | `assets.py convert <in.glb> <out_dir>` (GLB → model.fbx·basecolor·normal). `assets.py fit <id> --height H [--bury 0.05] [--corner] [--out DIR]` 지형 모듈을 기준서 3.2대로 정확한 박스(1m 폭, 높이+묻힘, 윗면 y=0, 칸 가운데)로 맞추고 x=±0.5(`--corner`면 z도) 2cm 안 정점을 경계에 붙인다. 높이·`corner`는 카탈로그 자산의 `"fit": {"height":..,"bury":..,"corner":..}`로 줄 수 있다. 결과 `<work_root>/<id>/fit/model.fbx`+`fit.json`(바운드 전후, 붙인 정점 수, 재가져오기 검증) → 카탈로그 `source.model`을 그 파일로 바꾼다 | 높이는 기준서 3.1 값을 직접 준다(도구에 기본값 없음). 축끼리의 비율(각 축 scale ÷ 세 축 중앙값)이 1에서 15% 넘게 벗어나면 `SCALE_DISTORTION:<축>=<비율>` 경고(`--strict`면 중단). 절대 배율(`fit.json` `scale`)은 정보로만 남는다(모델이 통째로 크거나 작은 것은 왜곡이 아님). 가로·깊이 비가 칸 모양(0.8~1.2)인지는 사람이 `bounds_before`로 본다. 절벽 윗면 캡 돌출은 박스 안에 들어간다고 본다 |
| 캐릭터 동작·부착 명령 (2026-11-04) | `assets.py armfix <in.fbx> <out_dir> [--target-degrees 15 \| --add-degrees D] [--actions walk] [--no-rest-fingers] [--no-rest-wrists]` 팔 벌림을 클립 평균과의 차이만큼만 돌려 목표 각도(기본 15°, K15)로 맞춤. 침투 게이트: 최악 프레임 손 침투 0.05 초과면 1°씩 올려 20°까지, 그래도 넘으면 `fix.json` `gate: FAIL`+이유(컨셉 문제)로 끝내고 모델을 쓰지 않음+손가락 뼈 바인드 고정(기본 켬)+손목(`Left_Hand`·`Right_Hand`)을 아래팔 기준 바인드 회전으로 고정(기본 켬, S7 r3: 리타깃이 자동 뼈대 왼손목을 112~135° 돌려 두고 손가락 반대 회전으로만 가려져 있었음. `fix.json` `rest_wrists`·`rested_wrists`)+프레임별 손 몸통 침투 측정(`fix.json`의 `hand_in_body_*`: 손 정점 중 몸통 볼록 껍질 안 비율). `assets.py attach <char.fbx> <out_dir> --hat hat.fbx --prop prop.fbx [--prop-bone Right_Hand] [--hat-offset x,y,z] [--prop-offset x,y,z]` 모자는 머리 뼈, 쥘 물건은 손 뼈에 별도 메시로 붙인다(K13·K14). 부품 메시 이름은 `Hat`·`Prop`(여러 개면 `_1`..). 카탈로그 캐릭터 항목의 `"parts": {"Hat": "<모자 id>", "Prop": "<물건 id>"}`가 있으면 Unity 빌드가 그 렌더러에 부품 자기 재질을 준다(없으면 모든 렌더러에 몸 재질 = 모자가 몸 아틀라스로 얼룩덜룩하게 칠해짐, S7 r3). `attach.json`의 `drift`가 0이면 뼈를 정확히 따라간다. 동작 가져오기: 카탈로그 `"anim": {"clips": ["idle", "walk"], "default": "idle"[, "loop": [...]]}`가 있으면 Unity가 Generic으로 클립을 가져오고(이름은 `Armature\|` 접두를 뺀 평범한 이름), 모델 오브젝트(`Visual/<이름>`)의 Animator에 `<폴더>/<이름>.controller`(클립마다 상태, 기본 상태, idle·walk가 둘 다 있으면 float `Speed` > 0.1 → walk, < 0.1 → idle)를 붙인다. 루트 모션 끔. `anim`이 없으면 예전과 같다(동작 끔, Animator 제거) | `--add-degrees`는 기존 각도에 더하는 옛 방식(게이트 없음). `--actions walk,idle`이면 두 클립에 같은 회전을 주고 목표·상한은 두 클립 평균에 걸린다(클립마다 각도가 다르면 한 클립이 20°를 넘을 수 있으니 `fix.json` `gate.tries[].abduction_mean`을 본다). armfix는 attach 전에 돌린다(첫 메시를 몸으로 읽으므로 모자·삽이 붙은 파일에는 쓰지 않는다). 동작 클립 이름은 재저장할 때마다 `Armature\|` 접두가 붙는다(부분 일치로 찾음). 비율 기본값은 S5 컨셉·명세 값이니 프로젝트 값을 직접 준다. 프리팹 크기: 카탈로그 `fit` 자산(지형 모듈)은 실제 크기(높이+묻힘, 윗면 y=0)를 유지하고, `height`(m)가 있는 자산은 그 높이(발 y=0), 둘 다 없으면 높이 1 |

| 키 입력 자동 플레이 (2026-11-06) | 패키지의 `Kit3D.KeyPlaySession`(Input System이 있을 때만 컴파일). 프로젝트 프로브 파일에 시나리오만 쓴다: `session = KeyPlaySession.Start(onFrame, onPlayEnded)`, 프레임마다 `session.Send(keys)`, 끝나면 `session.Stop()`. 이동은 `KeyPlaySession.PickMoveKeys(방향, 카메라 Y각)`, 캡처는 `KeyPlaySession.Capture(카메라, 경로)`. 실행: `play_check.py short <클래스.메서드> <결과 파일> --probe-file <파일> --probe-dir <부모 폴더> --pass '^fails=none'` | 주인공을 옮기거나 게임 메서드를 부르지 않는다. 가상 키보드가 플레이어와 같은 입력 경로를 지난다. WASD로 카메라 기준 이동하는 게임을 전제로 한다(다른 입력은 `Send`에 키를 직접 준다). 프로브 클래스에는 `Stop` 메서드가 있어야 한다. `--probe-dir`에는 `probe` 폴더의 부모를 준다. 경로·목표·통과 조건은 게임마다 다르므로 키트에 넣지 않는다 |
