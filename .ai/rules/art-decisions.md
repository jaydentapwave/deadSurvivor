# 아트 결정 규칙 (art 팩, 2D·3D 공통)

아트 작업에서 누가 무엇을 정하고, 무엇을 사용자에게 묻는지 정한다. 2026-11-03 제정. 계기: 사용자가 "기본적으로 래퍼런스 게임이랑 동일한 아트 스타일, 규격을 만들거야, 이미 그렇게 하기로했는데 왜 나한테 직접 묻는것들은 다 아트 관련된 부분인거야?"라고 지적했다. 레퍼런스로 정해지는 값과 만드는 방법까지 사용자 질문으로 올라갔고, 그 원인은 아트 작업에 원본 문서와 결정 규칙이 없었기 때문이다.

## 1. 원본 문서는 아트 기준서 하나

- 프로젝트의 아트 결정 값은 **아트 기준서**(보통 `docs/art/아트-기준서.md`, 견본은 `/art-spec` 스킬의 `templates/`)에만 둔다. 기능 개발의 `plan.md`와 같은 역할이다.
- 에셋 명세·요청서·시험 기록에는 기준서 번호(K1, K2…)와 절 번호만 적고 값을 복사하지 않는다. 결정 번호는 기준서에서만 새로 매긴다.
- 기준서와 다른 문서가 부딪히면 기준서를 따르고, 다른 문서를 고친다.

## 2. 레퍼런스 모드

기준서 첫머리에 모드를 하나 적는다. 모드는 사용자가 정한다.

| 모드 | 뜻 | 레퍼런스에서 관찰되는 값 |
|---|---|---|
| `follow` | 아트 스타일과 규격(축척, 구조, 형태 언어, 재질·광택, 색, 카메라, 밀도)을 레퍼런스와 같게 만든다 | 묻지 않고 그대로 기준서에 적는다. 근거(관찰 문서 절, 이미지 id)를 붙인다 |
| `study` | 레퍼런스는 공부용이고 값은 우리가 새로 정한다 | 값마다 추천을 붙여 사용자에게 묻는다 |

`follow`여도 원작 고유 요소(캐릭터, 문장·기호, 석상, 장비, 지도 배치)는 따라 하지 않는다. 그런 항목은 관찰 문서의 "따라 하지 않을 것" 목록을 기준으로 한다.

## 3. 누가 정하나

| 종류 | 예 | 정하는 쪽 |
|---|---|---|
| 레퍼런스에 값이 있음 (`follow`) | 칸과 키의 비율, 절벽 구조, 경계 모양, 재질별 광택, 소품 크기 | 에이전트가 레퍼런스대로 적는다. 사용자는 기준서를 승인할 때 한 번에 확인한다 |
| 만드는 방법 | 메시 분리, 뼈 가중치, 셰이더·마스크, 생성 도구로 만들지 재질로 칠할지 | 에이전트가 정하고 이유를 적어 보고한다. 기준은 "결과가 레퍼런스처럼 보이는가"다. 승인된 기준서·명세 범위 안의 방법만 해당한다. 범위를 넓히는 일(새 에셋·새 시스템·명세에 없는 작업)은 먼저 묻는다(scope-discipline) |
| 레퍼런스를 따를 수 없음 | 원작 회피 대상, 우리 고유 기호·석상·장비 | 에이전트가 레퍼런스의 형태 규칙 안에서 제안하고, 사용자가 컨셉 이미지를 보고 고른다. 기준서 단계에서 미리 묻지 않는다 |
| 기존 사용자 결정과 부딪힘 | 예: 예전 "지형도 생성 도구로" ↔ 레퍼런스의 이음새 없는 바닥 | **사용자에게 묻는다.** 두 결정의 원문과 날짜를 함께 보여 준다 |
| 사용자 결정을 그 결정이 말한 대상 밖으로 넓힘 | 예: "주인공 외곽선을 더 깔끔하게"를 시설·소품의 선에도 적용 | **사용자에게 묻는다.** 원문과 넓히려는 범위를 함께 보여 준다. 기준서 결정 목록의 "적용 범위" 칸에 원문이 말한 대상만 적는다. 출처 사례: 주인공에 대한 말을 모든 에셋으로 넓혀, 같은 원문에 있던 "손그림 느낌"이 소품에서 빠졌다 |
| 범위 | 넣을 구역·에셋 종류, 몬스터 포함 여부 | 기획서나 기존 결정에 답이 있으면 따른다. 없을 때만 묻는다 |
| 방향·채택 | 레퍼런스 모드, 컨셉 이미지 채택, 결과물 채택 | 사용자 (아트 디렉터) |

## 4. 묻기 전에 확인할 것

사용자에게 질문을 올리기 전에 차례로 확인한다. 하나라도 해당하면 묻지 않는다.

1. 관찰 문서에 그 값이 있는가 (`follow`일 때)
2. 기획서·현재 상태·기준서에 이미 사용자 결정이 있는가
3. 만드는 방법에 대한 질문인가
4. 원작 회피 대상이라 컨셉 단계에서 고르면 되는가

그래도 남는 질문은 모아서 한 번에 묻는다. 질문마다 레퍼런스 값, 관련 기존 결정 원문, 추천과 이유를 붙인다.

## 5. 승인과 순서

- 순서: 레퍼런스 관찰(`/art-reference`) → 기준서(`/art-spec`) 승인 → 에셋 명세 → 컨셉 이미지 → 유료 생성 승인 → 생성(`/2d-art-produce`, `/3d-art-produce`).
- 기준서는 전체를 한 번에 승인받고, 머리에 `승인: <날짜> — "<사용자 원문>"`을 적는다. 항목별 확인을 미리 받았으면 그 원문은 결정 목록의 답 칸에 남긴다.
- 기준서 해당 절이 승인되기 전에는 유료 생성을 하지 않는다. 위험을 확인하려는 시험 생성도 마찬가지다.
- 생산 단계는 승인된 기준서를 고치지 않는다. 생산하다가 기준이 틀렸다고 보이면 생산을 멈춘다. 기준서를 개정(`r2`)해 다시 승인받은 뒤 이어 간다.
- **범위를 줄일 때**: 기준서·기획서의 목록보다 적게 만들거나(에셋 8종 중 1종만), 하나로 여러 자리를 대신하거나, 뒤로 미루는 지시·작업은
  "기준서 번호와 다른 점"을 적어야 한다 — 기준서 절·번호, 기준서의 내용, 이번에 하는 것, 이유, 정한 사람(사용자 원문과 날짜, 아니면 "에이전트 판단").
  지시를 쓰는 쪽(디렉터 포함)은 지시문에, 일하는 쪽은 핸드오프·보고에 적는다. 적지 않은 축소는 기준서 위반이다.
  출처 사례: 기준서는 길 타일 8종인데 지시문이 "직선 1장으로 꺾이는 칸도 깐다"로 줄였고 어디에도 적히지 않아, 리뷰도 다음 단계도 모른 채 게임에 들어갔다.
  사용자가 정하지 않은 축소가 화면에 보이는 결과를 바꾸면(빠진 타일, 빠진 상태 그림) 만들기 전에 묻는다(3절 "범위").

## 6. 표기

기준서와 명세의 값에는 출처를 붙인다.

| 표기 | 뜻 |
|---|---|
| `[레퍼런스]` | 관찰 문서의 **관찰** 값. 근거 위치를 같이 적는다 |
| `[레퍼런스·해석]` | 관찰 문서의 해석/제안·설계 가이드에서 온 값. 관찰은 아니지만 관찰을 바탕으로 한 것 |
| `[방법]` | 에이전트가 정한 제작 방법 |
| `[우리 것]` | 원작 회피로 새로 정한 것. 채택 전이면 `[우리 것·제안]` |
| `[사용자]` | 사용자 결정. 날짜와 원문을 같이 적는다 |
| `추정` | 측정하지 않은 숫자 |
