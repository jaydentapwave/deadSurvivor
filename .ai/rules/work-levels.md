# 작업 규모와 검토

일을 시작할 때 규모를 정한다. 파일 수보다 상태 소유권·스키마·실행 흐름에 미치는 영향을 본다. 여러 조건에 해당하면 높은 규모를 적용한다. 레포 규칙이 있으면 그것이 우선이다.

| 규모 | 조건 | 필수 절차 |
|---|---|---|
| L0 | 설명·오탈자·링크 정리, 기존 계약 안의 국소 수정, 수치·색·배치 조정 | 관련 원본 확인 → 수정 → 영향 범위 확인 → 결과 기록 |
| L1 | 새 기능·입력 흐름(새 도메인 폴더를 더하고 공유 파일에는 등록 줄·칸만 더하는 것 포함), 여러 부분에 영향을 주는 동작 변경, 워크플로우·검사 도입·변경 | 짧은 설계 브리핑 → 구현 → 검사 → 마감 리뷰 |
| L2 | 구조가 크게 바뀔 때만: 첫 기능(Core 기반·DI 뼈대·판정 진입점), 이미 있는 시스템의 상태 소유권·DI 구조·세이브 형식 변경, 렌더 파이프라인 설정 변경 | 설계 브리핑 → `design-reviewer` 독립 검토 → 구현 → 검사 → 마감 리뷰 |

- **마감 리뷰는 기능 하나에 한 번이다.** 구현과 명령 관문(컴파일·테스트·Play)이 끝난 뒤 그 시점의 리뷰(`spec-reviewer`, `validator-client`, 알고리즘 코드가 있으면 `algorithm-tester`)를 한꺼번에 병렬로 부르고, 지적을 모아 고친 뒤 FAIL이었던 리뷰만 수정 확인을 한 번 받는다. 수정 확인에서도 FAIL이 남으면 더 돌리지 않고 멈춰 일을 시킨 쪽에 묻는다. L1의 설계 브리핑은 마감 리뷰 입력으로 넘긴다.
- 디렉터의 `review_mode`는 추가 검토 강도다. L1·L2 필수 리뷰를 줄이지 못하며 `solo`는 L0에만 적용한다. L2의 `design-reviewer`는 구현 전에 한 번 실행하고(FAIL이면 고쳐 수정 확인 한 번) 최종 핸드오프에 결과를 남긴다.
- 규모와 검사 범위는 별개다. L0도 런타임 변경이면 컴파일·짧은 Play를, 시각 변경이면 캡처를 한다.
- 비주얼 반복(셰이더 값·조명·색·배치 조정)은 대부분 L0다. 화면을 먼저 보여 주고 검토는 생략한다. 셰이더 구조·렌더 파이프라인 설정·에셋 규격 숫자를 바꾸는 일은 L1 이상이다.

## 시작할 때 고정할 범위

- **이번에 쓸 수 있게 될 결과와 완료 조건.** 시험 후보와 정식 채택을 구분한다.
- **변경 범위와 후속 항목.** 바꿀 파일·동작, 이번에 다루지 않을 것.
- **최소 필수 검사.** 변경 → 실패 가능성 → 검사 방법.
- **첫 실제 연결.** 어떤 최소 정상 사례로 입력 → 실행 → 결과를 먼저 확인할지.

검사기·범용화·추가 진단을 만들기 전에 "어떤 현재 요구나 결함을 기존 도구로 판정할 수 없는가"를 적는다. 근거 없는 미래 대비는 후속 제안으로 남긴다.

## 양식

L1·L2 설계는 [설계 브리핑](../templates/design-brief.md), 결과는 [검증 기록](../templates/verification.md), 중요한 선택은 [결정 기록](../templates/decision.md)으로 남긴다. 기존 원본이 있으면 그것을 고치고 중복 문서를 만들지 않는다.

## 실패와 재실행

- 실패는 먼저 게임 동작 결함, 검사기 오판, 환경·권한 차단, 시각 품질 미달로 나눈다. 원인을 확인하기 전에 검사 강도나 기준값을 바꾸지 않는다.
- 같은 환경 차단은 원인 확인용 최소 조회까지만 한다. 조건이 바뀌지 않았으면 같은 전체 검사를 반복하지 않는다.
- 원인을 못 찾은 1회 실패는 실패 시점 상태를 기록하게 고친 뒤 한 번만 다시 돌린다. 재현되지 않으면 UNKNOWN으로 남긴다.
- 검토 지적은 **필수 수정**과 **후속 제안**으로 나눈다. 메인이 필수 지적을 임의로 후속으로 낮추지 않는다.
- 독립 검토 도구를 쓸 수 없으면 BLOCKED로 기록하고 가능한 구현·확인을 계속한다. 자기 검토를 독립 검토로 표시하지 않는다.

## 완료 기준

범위 안의 구현, 필수 검사, 독립 검토 필수 지적 해소, 관련 문서 갱신까지 끝나야 완료다. 검증하지 못한 항목은 사유와 다음 조치를 적는다. 커밋·원격 게시는 이 절차로 자동 승인되지 않는다.
