# 레퍼런스 기반 시각 설계

2026-10-30 제정 · 2026-11-01 문구·구현 경계 갱신. 개발 규모 분류와 독립 검토는 프로젝트의 개발 워크플로우를 따른다. 이 문서는 근거를 기록하는 방법만 정한다. 승인 지점은 [아트 결정 규칙](art-decisions.md) 5절의 것만 쓰고, 이 문서 때문에 승인 절차나 외부 연동을 더하지 않는다.

## 반드시 구분할 근거

설계 문서에 사용자 요구, 원본에서 관찰한 사실, 에이전트 제안, 미정을 구분한다. 에이전트 제안은 문서에 기록되거나 검사에 통과해도 사용자 확정으로 승격하지 않는다. 다만 레퍼런스 모드가 `follow`이면 관찰된 레퍼런스 값은 제안이 아니라 `[레퍼런스]` 값이다. 기준서 승인으로 확정되며 따로 묻지 않는다([아트 결정 규칙](art-decisions.md)). 원본의 외형만으로 충돌·높이·축척·스폰·통과 가능성을 확정하지 않는다.

## 작업 순서

1. 원본 이미지 직접 확인: 출처 URL(사용자 제공 파일이면 제공 경로), 파일명, 해상도, 확인 날짜·SHA-256과 로컬 입력 파일을 기록한다. 원본은 수정하지 않는다. 자르기·주석·색 변환은 파생 파일로 보존하고 원본과의 변환·지문을 연결한다. 확보 불가 시 BLOCKED인 범위를 명시하고 추정 이미지로 대체했다고 숨기지 않는다.
2. 외곽·장애물 분포와 크기·방향·열린 공간·연결 경로를 분석한다. 관찰과 해석을 분리한다.
3. 유지할 특징과 변경할 특징을 명시한다. 표현 스타일 변경 요청을 맵 구조 단순화로 해석하지 않는다. 구현 편의로 사용자 핵심 요구를 바꾸려면 방향 변경임을 설명하고 기존 승인이 없는 경우 확인한다. 통상적인 제작·비교에는 별도 승인을 요구하지 않는다.
4. 이미지 생성 도구를 사용할 때는 생성 입력에 실제 원본 이미지를 전달하고 입력 경로·사용 도구·최종 프롬프트를 보관한다. 공통 배치 데이터로 도면을 그리거나 메시를 직접 제작할 때는 원본→배치/스크립트→결과 대응과 도구·설정·지문을 기록하고 프롬프트는 해당 없음으로 표시한다. 이전 생성 시안을 원본 대신 넘긴 채 원본 직접 참조라고 보고하지 않는다.
5. 원본과 결과를 동일 항목으로 시각 비교한다. 외곽, 지역별 밀도, 크기·형태 다양성, 길 연결, 열린 공간, 표시 정확성을 각각 기록한다. 정확한 개수·면적·축척을 측정하지 않았다면 수치 일치라고 주장하지 않는다.
6. 핵심 특징이 누락되면 FAIL로 기록하고 원본을 다시 확인한 뒤 설계·생성 결과를 새 개정으로 수정한다. 보존 원본과 과거 실패 결과를 덮어쓰지 않는다. 글자·범례가 정확하거나 문서 링크 검사가 PASS여도 요구 충족 PASS를 대신하지 못한다. 결과물 검토와 런타임 검증은 구분한다.
7. 피드백이 기본 전제를 부정하면 전제와 최신 문서 연결부터 수정한다. 실패 시안은 과거 비교용으로 보존하고 현재 기준으로 계속 사용하지 않는다.

## 완료 기록

입력 원본·프롬프트·결과 파일·항목별 비교·잔여 차이·실행 시각·SHA-256·검사 결과를 프로젝트 안에 기록한다. 이미지 생성 결과는 별도 정밀 좌표 검증 없이 구현 도면이나 충돌 데이터가 되지 않는다. 외부 공유·회사 서비스 기록은 금지하며 AGENTS 저장 경계를 유지한다.

비교에는 대상/제외 영역, 정렬·자르기·카메라·해상도·조명 차이, 기준별 근거와 미측정 항목을 남긴다. 조건이 다른 원본과 Unity 화면은 정성 비교로 표시한다. 형식 확인, 원본 특징 충족, 런타임 동작, 사용자 최종 채택을 각각 기록한다. 로컬 원본 확보는 외부 서비스 업로드나 재배포 허가를 뜻하지 않는다. 이미 허용된 요청 범위 안에서는 반복 승인을 요구하지 않는다.
