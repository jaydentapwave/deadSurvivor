# UI 그림체 견본 — 출처·측정 (대기열 20261117-art-samples 항목 sample-ui, 시도 1, 2026-11-17)

- 무엇: UI 종류(기준서 3.3 UI 행, K16 "가죽 테두리 + 양피지 칸")의 그림체 견본이다. 강도 3단계로 만들었다.
  단계마다 버튼 1(글자 없는 틀, 9-slice), 가죽 테두리 판넬 1(9-slice), 양피지 가방 칸 1(16×16 도트)을 만들었다.
  양산이 아니다. 사용자가 단계 하나를 고른다. HP 바, 쿨타임 막대, 조이스틱, 피해 숫자 글꼴은 이 항목의 범위 밖이다.
- 상태: **그림체 견본이며 사용자 선택을 기다린다.** identity가 없는 종류라 measure.py 판정이 없다. 시트는 `--unverified "그림체 견본 — 사용자 선택"`로 만들었다.
  PASS는 "기준과 어긋나지 않음"이라는 뜻이다. 자연스러움은 판독과 사용자 판정으로 정한다.
- 회차: 2/2(이 종류의 상한)를 썼다. 1회차에는 단계마다 세 조각을 만들었다. 2회차에는 버튼만 다시 만들었다. 전체 작업은 약 50분 걸렸다.

## 도트 크기와 9-slice
- 도트 1개는 가상 해상도(K2) 640×360의 1px이다. UI 캔버스 1920×1080에서는 3px다. 견본은 모두 도트 단위 PNG(1도트 = 1px)라서 최근접 3배로 놓는다.
  합성도 이 배율을 썼다. 캐릭터 그림과 도트 크기가 같다.
- 버튼: 32×16 도트이고 테두리는 4도트(= 1920에서 12px)다.
  이유는 이렇다. 지금 버튼 자리의 높이는 18~24도트다(전투 ×1·일시정지 18, 정비 다음 웨이브 22, 회전·선택 취소 24). 테두리가 4도트면 위아래를 빼고
  가운데가 10~16도트 남는다. 글자(지금 글꼴 28~30px ≈ 10도트)가 테두리에 덜 걸린다. 바깥 선 1, 가죽 1, 바늘땀 1, 안쪽 선 1로 네 줄이면 바늘땀까지 담긴다.
- 판넬: 48×48 도트다. 테두리는 s1·s2가 6도트(= 18px), s3가 12도트(= 36px)다.
  재 보니 s1·s2의 가죽 테두리는 5도트이고, 6도트째부터 안쪽 칠이다. s3는 안쪽 주황 선이 6~7도트에 있고 안쪽 모서리 눈금이 8~11도트에 있다.
  그래서 s3는 12도트로 잡아야 가운데에 장식이 들어가지 않는다. 가운데에 장식이 들어가면 늘릴 때 반복된다.
- 가방 칸: 16×16 도트이고 9-slice가 아니다. 아이콘 칸(1칸 16×16 도트, 1단 작업범위 ⑦)과 같은 격자다.
- 합성에서는 모서리를 그대로 두고, 변과 가운데는 반복(타일)으로 늘렸다(build_ui.py `nine`). Unity로 옮길 때는 Image Type을 Sliced 또는 Tiled로 하고,
  Sprite Editor의 Border를 위 값으로 둔다. 늘림(stretch)으로 하면 바늘땀 간격이 늘어난다. 이것은 넣기 단계가 정한다.

## 도구·생성
- 생성: codex-cli 0.167.2, 모델 gpt-6.1-sol(추론 medium), 내장 이미지 도구. 유료 크레딧은 쓰지 않았다.
  실행: `perl alarm 1200 + codex exec -m gpt-6.1-sol -c model_reasoning_effort="medium" -s workspace-write -C <단계 폴더> "<프롬프트>" -i <참고> < /dev/null`
  결과물은 레포 밖 output/2d-art/sample-ui에 마젠타 배경으로 있다. 커밋하지 않았다.
- 1회차(세 조각, 프롬프트 = common.txt + s*/prompt.txt의 단계 문장):
  - s1 세션 01a1e7e7-263b-7731-a4ed-e885065120cf. 참고는 최신 정비 캡처 조각이다(03-G3 (780,180)-(1920,800), 지금 임시 버튼·칸. sha256 cc2714f8647dfdd5).
  - s2 세션 01a1e7e7-2639-7a03-8815-3a1343089e3d, s3 세션 01a1e7e7-2639-79c3-8955-037cdcdbc91f. 참고는 컨셉 조각 bag_corner·bag_bottom·cell이다.
  - 그림체 입력에 캐릭터·몬스터 그림은 넣지 않았다.
  - raw sha256 앞 12자: s1 button 82d7f3ebcd4a, panel e5ee84b19af1, cell 4b2d1a3a184b / s2 button 16500cd156f9, panel 7fc07db6a545, cell 6e950a164492 /

- 2회차(버튼만, 프롬프트 = button_r2_common.txt + 단계 문장 = s*/prompt_button_r2.txt):
  - 1회차 버튼을 32×16으로 내리자 바늘땀이 사라지고 변이 고르지 않았다. 그래서 버튼만 다시 만들었다. 지시는 줄 구성(바깥에서 안으로 한 줄씩)이다.

- 도트 정리는 K11 방식으로 했다: `pixelize.py one <raw> --size <목표> --palette <기준서 3.5 r2 팔레트 45색> --bg #ff00ff`. 강조색은 더하지 않았다.

  | 그림 | 본래 격자(점수) | 목표 | 처리 |
  |---|---|---|---|
  | s1 버튼 1회차 / 2회차 | 42×21(0.74) / **32×16(0.95)** | 32×16 | 2회차를 그대로 내렸다 |
  | s2 버튼 1회차 / 2회차 | 189×94(0.38) / 134×67 | 32×16 | 목표로 내린 뒤 직접 손질했다 |
  | s3 버튼 1회차 / 2회차 | 150×75(0.30) / 166×83 | 32×16 | 목표로 내린 뒤 직접 손질했다 |

  | s1·s2·s3 칸 | 24·21·19 | 16×16 | 목표로 내렸다 |
  - 장식·바닥 견본과 달리 `--size auto`(본래 격자)를 쓰지 않고 목표 격자로 내렸다. 이 항목은 도트 크기가 게임 그림과 같아야 한다.
    또 9-slice 테두리 두께(도트 수)가 버튼 자리 높이에 들어가야 한다. 본래 격자로 내리면 버튼이 64~190도트 폭이 되어 테두리가 자리보다 두껍다.
- **직접 손질**(기준서 3.3 UI 행 "Codex + 직접 손질"): s2·s3 버튼은 두 번 모두 격자보다 잘게 그려졌다. 내리면 바늘땀이 군데군데 빠지고 변이 고르지 않아
  9-slice로 늘릴 수 없었다. 그래서 fix_buttons.py로 테두리 4도트를 2회차 프롬프트의 줄 구성대로 다시 칠했다.
  - 바깥 선 #34140e
  - 가죽 #5c493c
  - 바늘땀(#c2864d와 가죽을 번갈아)
  - s2는 가죽 #5c493c, s3는 #2f1108 안쪽 선
  - 모서리 리벳: s2는 #f8b828 1도트, s3는 2×2 #f8b828에 #fff9ed 하이라이트
  - 가운데 24×8은 생성 그림의 가운데 최빈색 한 색이다.
  - s3 프롬프트의 "가운데 위 한 줄 밝게"는 위 테두리 안쪽 줄로 옮겼다(아래 판독 지적).
  즉 s2·s3 버튼의 모양은 생성 그림이 아니라 지시 줄 구성에서 나왔다. 색과 재질 방향은 같은 단계의 판넬을 따른다.
- 테두리 번짐(`matte.py fringe --key #ff00ff --whole`): 버튼·판넬·칸 9장 모두 PASS다(번짐 0). 모든 조각이 캔버스를 꽉 채워 투명 픽셀이 0이다.
- 외곽선: 9장 모두 바깥 선이 #34140e 1도트다. 다만 s3 판넬의 맨 바깥은 #2f1108이 섞여 있다.

## 칠 색 (paint.py measure, ±0.05)
작은 그림은 가족당 50px 하한에 못 미친다. 그래서 최근접 확대 사본(판넬 ×4, 칸 ×8, output/2d-art/sample-ui/x4, 커밋 안 함)으로 쟀다. 최근접 확대라 색 중앙값은 그대로다.
| 그림 | 기준(컨셉 조각, 같은 도구) | 후보 | 판정 |
|---|---|---|---|
| 칸(양피지), --luma-min 110 | parchment_only orange S0.30/V0.91 | s1·s2·s3 모두 orange S0.31/V0.97 | FAIL: dS+0.00, dV+0.07(조금 밝음) |
| 판넬(가죽), --luma-min 40 | leather_only orange S0.37/V0.71, red S0.61/V0.34 | s1·s2 orange S0.50/V0.47 · s3 S0.35/V0.36 | FAIL: s1·s2 dS+0.13 dV−0.24, s3 dS−0.03 dV−0.35 |
- 판넬 값은 대부분 안쪽 어두운 칠(#2f1108)이다. 프롬프트에서 "흰 글자가 읽히게 어두운 가죽 안쪽"을 지시했기 때문이다.
  컨셉 가방의 안쪽은 양피지이고 가죽은 중간 갈색이라 이 차이는 의도한 것이다.
  컨셉 가죽 띠는 바늘땀·하이라이트를 포함해 밝게 잡혔다.
- 손질(pull)은 하지 않았다. 세 단계 칸의 칠 색이 같은 까닭은 K11 팔레트 정리 때문이다. 양피지는 팔레트 #f8daac로 모인다.
  컨셉 양피지(V 0.91)보다 밝은 색만 팔레트에 있다. 당기면 팔레트 밖 색이 된다.
  이 판정은 출발값이라 관문이 아니다. 단계 사이의 차이는 칠 색이 아니라 바늘땀·리벳·음영 단 수에서 난다.

## 다른 계열 판독 (Claude 하위 에이전트 Opus 5.5 medium. 생성은 GPT 계열)
이름을 가렸다. ref1~3은 컨셉 조각이고, A = 단계 2, B = 단계 3, C = 단계 1이다. 낱장 확대와 화면 합성 2장(정비·전투, 1920×1080)을 보여 주었다.
| 단계 | 무엇으로 읽히는가(버튼 / 판넬 / 칸) | 같은 게임처럼(1~5) | 게임 화면에서 | 가장 약한 것 |
|---|---|---|---|---|
| 1 (C) | 평평한 갈색 판 / 테두리만 밝은 어두운 상자 / 평범한 크림 사각 — 나무판이나 단색으로 읽혀 재질이 없다 | 2 — 바늘땀·질감·칸 테두리가 없어 임시 도형으로 읽힌다 | 차분하고 붙인 티가 나지 않는다. 글자가 가장 잘 읽힌다. 캐릭터보다 단순하다 | 재질이 없다 |
| 2 (A) | 바늘땀 점선과 노란 모서리 징이 있는 갈색 버튼 / 바늘땀 테두리와 옅은 결이 있는 어두운 판넬 / 평범한 크림 칸 — 가죽 + 종이 | 3 — 바늘땀은 가방과 맞는다. 칸이 너무 평범하다 | 바늘땀 점이 캐릭터 도트와 같은 크기라 한 게임으로 읽힌다. 큰 판넬의 점선이 조금 번잡하다. 흰 글자는 읽힌다 | 칸에 테두리·음영이 없어 크림색 들판에 묻힌다 |
| 3 (B) | 바늘땀 가죽 + 주황 안쪽 선 / 주황 점선, 모서리 꺾쇠, 긁힌 자국이 있는 판넬 / 왼쪽 위 계단 음영과 황갈 테두리의 양피지 칸 — 가죽·양피지에 가장 가깝다 | 4 — 바늘땀, 테두리, 음영 칸이 컨셉 단서를 가장 많이 맞춘다 | 도트 크기가 맞는다. 테두리가 가장 무거워 HP 카드 넷에서 두드러진다. 글자는 읽힌다 | (판독 당시) 주황 안쪽 선이 버튼 글자를 가로지름 → 고쳤다(아래) |
- 순위: 단계 3 > 단계 2 > 단계 1.
- 세 단계의 공통 차이(컨셉 대비):
  - 컨셉 가죽은 중간 갈색에 부드러운 하이라이트가 있다. 후보 판넬 안쪽은 거의 검정이다. 흰 글자를 읽히게 하려는 의도였다.
  - 컨셉 양피지는 얼룩 질감과 안쪽 홈(베벨)이 있다. 후보 칸은 평평한 크림색이라 노란 들판에 묻힌다.
  - 컨셉은 모서리가 둥글고 도톰하다. 후보는 모두 각진 모서리다.
- 판독이 찾은 결함과 처리:
  - s3 버튼: 가운데 위 밝은 줄이 9-slice 가운데에 있어, 늘리면 반복돼 글자를 가로질렀다.
    **고쳤다.** 밝은 줄을 테두리 안쪽 줄로 옮겨 가운데를 한 색으로 했다. 다시 합성하고 정비 화면의 회전·선택 취소 버튼을 열어 확인했다. 수정 확인 판독은 따로 받지 않았다.
  - s3 HP 카드: 판넬 안쪽 모서리 눈금이 이름·HP 글자 가까이 온다. 고치지 않았다. 넣기 단계에서 판넬 안쪽 여백을 정할 때 본다.
  - s3 긴 판넬: 바늘땀 간격이 끝에서 끊긴다. s2 긴 위 판넬에도 같은 반복 이음이 있을 수 있다.
    반복 단위(36도트)가 바늘땀 주기의 배수가 아니라서 생긴다. 고치지 않았다. 고른 단계를 양산할 때 변 반복 단위를 바늘땀 주기에 맞춘다.
  - 칸 모서리 점: s1에는 어두운 모서리 점, s2에는 흰·검은 모서리 점, s3에는 왼쪽 아래 어두운 점 1개가 있다. 생성 그림에서 그대로 옮겨 왔다. 고치지 않았다.
  - s1 판넬 왼쪽 변에 홈 자국이 있다. 고치지 않았다.

## 합성 (합성 — 게임 화면 아님)
- 최신 캡처 두 장을 썼다: 전투 02-G2(sha256 a77371c29b258abc…)와 정비 03-G3(2f49c86a0820b57c…), 둘 다 1920×1080.
  임시 도형의 자리는 640×360으로 내린 캡처에서 색으로 찾아 쟀다.
  - 전투: 아래 대원 판넬 4개((3,285)-(159,358) 등)와 위 버튼 2개(×1, 일시정지).
  - 정비: 위 판넬, 보관함 판넬, 오른쪽 판넬, 아래 진형 판넬, 버튼 3개(다음 웨이브·회전·선택 취소), 대원 넷의 가방 4×4 칸 64개.
- ×3 합성은 원본 1920 캡처 위에 견본만 최근접 3배로 얹었다.
  - 판넬이 덮은 기존 요소는 캡처에서 그대로 옮겨 붙였다: HP 막대, 아이템 칩, 보관함 카드, 진형 버튼.
  - 글자는 지금 글꼴 Assets/Game/03.Resources/Font/NotoSansKR.ttf로 다시 얹었다. 흰 글자이고 28~44px다.
  - 전투 대원 판넬은 지금 배치에 안쪽 여백이 없다. 그래서 글자·HP 막대·칩을 4도트(12px) 내렸다(PAD_Y). 넣기 단계에서 정할 값이다.
- 가방 칸은 지금 자리(간격 22도트, 임시 칸 18도트)의 가운데에 16×16 도트로 놓았다. 그래서 칸 사이가 6도트 빈다.
  칸 간격과 배치를 16도트 격자로 바꾸는 일은 넣기 단계의 몫이다. 아이템이 놓인 칸(회색 테두리)은 캡처의 표시가 칸 둘레에 그대로 보인다.
- 머리에 "합성 — 게임 화면 아님"을 찍었다. 오른쪽에는 컨셉 조각을 같은 축척(컨셉 1px = 게임 640/1672 px, ×3)으로 두었다.
  같은 축척에서 보면 컨셉 가방 칸은 약 30도트(게임 px)다. 견본 칸 16도트는 아이콘 격자(16×16)를 따른 크기라 컨셉보다 작다.
- 직접 열어 본 것:
  - 단계 3의 정비·전투 ×3 합성 전체
  - 단계 1의 정비 합성 전체
  - 세 단계 전투 대원 판넬 띠
  - 세 단계 정비 가방 칸 부분
  - 고친 뒤의 s3 버튼 부분
  - 낱장 시트 sample-ui-items.png, 합성 시트 sample-ui.png(축소)
  처음 판에서 원본 캡처 글자가 3배 확대로 뭉개진 것, 판넬 안 반복 선(s3 테두리 6 → 12로 고침), 글자와 HP 막대 겹침을 찾아 고쳤다.
  s2의 정비·전투 ×3 전체는 판독 에이전트가 보았고, 메인은 띠와 부분만 보았다.

## 기준서 번호와 다른 점
- 3.3 UI 행(버튼, 판넬, 가방 칸, HP 바, 쿨타임 막대, 조이스틱, 피해 숫자 글꼴) 중 견본은 버튼·판넬·가방 칸만 만들었다. 지시문 범위가 그렇다.
- K16 "가죽 테두리 + 양피지 칸"을 따랐다. 판넬 안쪽은 양피지가 아니라 어두운 가죽이다. 이유는 지금 흰 글자를 그대로 읽히게 하려는 것이다.
  컨셉처럼 양피지 안쪽으로 가면 글자색을 어둡게 바꿔야 한다. 이것은 사용자 판정 항목으로 넘긴다.
- 화면비·안전 영역은 미확인이다. 16:9 캡처 위 합성만 보았다. 9-slice는 화면비가 달라 판넬 폭이 바뀌어도 늘어나게 하려는 장치다.
