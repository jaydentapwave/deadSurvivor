# 배경 미술 병행 준비와 Tripo 활용 계획

- 작성일: 2026-11-01 KST / 문서 개정: r001.
- 상태: 제작 준비안. 스타일·자산 명세의 최종 채택, 새 모델 생성, Unity 적용은 미실행이다.
- 이번 작업: L0 문서 정리. 기존 워크플로우·계약을 참조하며 새 생성/등록 절차나 게임 기능을 도입하지 않는다.
- 사용자 요청: 다른 에이전트와 겹치지 않는 작업과 Tripo 활용 시점을 기존 문서에 근거해 Markdown으로 정리한다.
- 핵심 제안: **스타일 기준 → 최소 자산 목록 → Tripo 요청 명세를 병행 준비하고, 규격이 정해지면 소품 한 개의 품질을 시험한다. 실제 맵 통합은 맵 담당자의 N3 작업으로 진행한다.**

## 1. 현재 작업과의 경계

[024 다음 단계](../../design/map-next-steps-024-plan.md)는 N1 전체 맵 검증 → N2 전투·성능·빌드 → N3 대표 구역 미술 순서다. [025 준비](../../design/map-n1-025-preparation.md)는 경로 재고와 지원/누락을 정리했고, 조회 시점의 [026 실행 설계](../../design/map-full-026.md)는 N1~N3와 현재 개발 Mac 검증을 다룬다. 따라서 N3 구현을 별도로 중복 착수하지 않는다.

| 영역 | 이 병행 작업에서 준비할 내용 | 실제 구현·통합 담당 범위 |
|---|---|---|
| 스타일 | 레퍼런스별 역할, 형태·색·재질·가독성 제안 | 026의 대표 구역·조명·카메라 적용 및 인수 |
| 자산 | 기존 자산 재사용과 신규 필요 여부, 최소 품목·변형 방식 | 026의 OB별 실제 배치·씬·성능/동작 확인 |
| Tripo | 소품별 참고 자료·프롬프트·옵션 확인 항목·예산/검사 명세 | 별도 허용된 자산 시험, 이후 검증된 개정의 맵 통합 |
| 맵·게임·하네스 | 담당 문서를 읽기 전용으로 참조 | Runtime/Editor, Tools/Verify, layout·충돌·통로, 빌드·검증은 기존 담당 |

이번 작성 파일은 이 문서 하나다. README·현재 상태·할일·024/025/026·공통 워크플로우·원본 자료·Unity 자산은 수정하지 않는다. 문서 수정을 나눠도 같은 Unity Editor의 Play·씬·설정 조작은 충돌할 수 있으므로, 병행 미술 준비에서는 Unity를 조작하지 않는다. 기존 자산의 독립 화면 시험도 담당자의 실행과 겹치지 않는 시점에 한다.

작업 결과는 이 전용 폴더에서 전달한다. 담당자가 채택한 입력 개정과 필요한 자산을 확인한 뒤 공통 문서 연결·씬 적용을 통합한다. 후속 공동 인덱스/커밋에는 다른 에이전트의 미완료 파일을 함께 포함하지 않는다.

## 3. 병행 산출물 A — 스타일 기준안

다음은 에이전트 제안이며 직접 화면 비교와 사용자 검토 뒤 채택한다. 최종 팔레트·수치·자산 승인으로 보지 않는다.

| 항목 | 제안 방향 | 확인할 화면·실패 조건 |
|---|---|---|
| 돌·벽 실루엣 | 큰 면이 읽히는 비대칭 바위, 깨진 상단·모서리, 낮은 잔해. 긴 직선/사선/곡선 조각을 구분 | 한 모듈의 크기·회전만 바꿔 지역별 형태 차이가 사라지면 재설계 |
| 표면 디테일 | 큰 형태를 먼저 읽고 작은 균열·요철은 절제 | 작은 돌·무늬가 적·아이템·공격 표시처럼 보이면 축소 |
| 색·재질 | 녹색 지면과 구분되는 저채도 돌, 과도한 광택을 줄인 표면을 우선 비교 | 정확한 색상값은 미정. 캐릭터·위험 표시보다 배경 대비가 강해지면 조정 |
| 지면·길 | 색·질감으로 구분하고 큰 연결과 열린 공간을 읽히게 함 | 길 색이 곧 통과 가능/불가능을 뜻한다고 오해하게 만들면 수정 |

| 화면 가독성 | 고정 게임 카메라에서 파티·적·명중/위험 표시를 함께 확인 | 소품 단독 확대 화면만으로 합격 처리하지 않음 |

작성할 자료는 유지/금지 특징표, 출처가 붙은 참고 이미지 목록, 팔레트·재질 제안과 비교 항목이다. 지도 전체의 배치·충돌·카메라는 이 스타일 작업에서 재설계하지 않는다.

## 5. 병행 산출물 C — 첫 Tripo 요청 명세 초안

### 5.1 낮은 돌벽 모듈의 형태 요구

- 대상: 독립된 정적 돌벽/유적 잔해 모듈 하나. 주변 풍경 전체를 생성하는 요청이 아니다.
- 제안 실루엣: 수평 방향이 읽히는 길쭉한 덩어리, 비대칭의 깨진 상단, 게임 카메라에서 구분되는 큰 면, 땅에 닿는 안정적인 하부.
- 제안 재질: 저채도 무광 돌, 큰 형태를 방해하지 않는 균열·표면 요철.
- 제외: 글자·로고·캐릭터·붙어 있는 넓은 바닥판·불필요한 식생, 떠 있는 파편, 과한 광택, 강하게 구워진 그림자, 불필요한 리깅/애니메이션.
- 접합: 양끝·측면·바닥을 관찰해 반복 배치의 틈/겹침과 크기 변경 시 왜곡을 확인한다. 생성 한 번으로 매끄러운 접합이 보장됐다고 판단하지 않는다.
- 충돌: 생성 모델에 맞춰 C를 새로 만들지 않는다. 통과할 수 있어 보이는 구멍이 논리상 막힌 벽에 생기면 시각 요구 불일치로 기록한다.

### 5.2 요청 전에 채울 표

| 구분 | 작성할 값 | 지금 상태·결정 근거 |
|---|---|---|
| 자산/범위 | asset ID·개정, 기존 양식의 scope·용도, 실제 참고 파일/해시 | 미정. 미채택 품질 시험임을 명시 |
| 크기 | 폭·깊이·높이, 비율, 단위, 정면, 지면 접점/원점과 오차 | 미정. 021 몸체·카메라와 선택한 배치 용도 기준으로 결정 |
| 기하 예산 | Unity 삼각형 상한·메시/재질 수·예상 인스턴스 수 | 미정. 현재 전투/성능 담당자의 예산을 참고. 기존 바위 시험 상한을 공통값으로 복사하지 않음 |
| 텍스처 | 슬롯·최대 해상도·UV·재질/shader 기준 | 미정. 대표 구역의 동시 사용 비용과 시각 목표로 결정 |
| 실제 옵션 | geometry/texture 모델 버전, 지원되는 face_limit·quad·texture/PBR 등 | 미확인. [생성 기준](../../workflows/tripo-generation-standard.md)의 옵션표에 따라 실제 경로에서 확인 |
| 요청 원문 | prompt·negative 요구·입력 이미지·각 지문 | 아래는 문장 틀만 제시. 완성 요청 아님 |
| 실행 경로 | 국제 계정 구분·프로젝트 로컬 CLI/API·다운로드/후처리 지원 | 기존 [CLI/API 결정](../../decisions/3d-cli-workflow.md)을 유지. 실행 전 설치/지원 기능 확인 |
| 비용/공개 | 현재 사용 가능한 API 비용·상한·허용 시도 수·참고 자료 업로드·공개 여부 | 미확인. Studio 크레딧과 API 사용 가능액을 동일시하지 않음 |
| 검사 | 예상 검사·비교 조건·실측/화면·복구·보류 기준 | [작업 양식](../../templates/ai-3d-asset-package.md)과 [자산 하네스](../../design/ai-3d-asset-harness.md)로 구체화 |

위 미정 값이 생성 요청에 필요한 필수 항목이면 A0 준비 상태로 둔다. 빈 값이나 UNKNOWN을 임의 숫자·0·무제한으로 바꿔 제출하지 않는다. 본문 표는 실행용 API JSON이 아니다.

### 5.3 프롬프트 문장 틀 — 미제출

```text
One isolated static stylized low ruined stone-wall module.
Silhouette and proportions: [APPROVED_REFERENCE_FEATURES_AND_RATIO].
Large readable stone planes, an irregular broken top, and a stable ground-contact base.
Palette, roughness and detail density: [APPROVED_ART_SPEC].
Exclude characters, lettering, attached scenery and a surrounding ground platform.
Avoid floating debris, exaggerated gloss and strong baked directional shadows.
```

대괄호는 실제 요청 전 채울 항목이다. 참고 이미지는 출처·사용 범위를 확인한 허용 입력만 전달한다. 수치 제한은 지원되는 실제 옵션으로 전달하며, 치수·원점·텍스처·최종 삼각형 수·미술 충실도는 결과를 실측/비교한다. 별도 negative-prompt 필드가 없는 경로에는 미지원 필드를 보내지 않는다.

**소품 단독 시험을 먼저 할 수 있다는 제안은 024/026의 실제 맵 적용 선후관계를 바꾸지 않는다.** 이번 문서는 앞당긴 생성을 실행하도록 승인하거나, 미검증 모델을 N3에 바로 넣도록 허용하지 않는다.

현재 프로젝트 문서에는 기존 원본의 처리·Unity 전송 도구와 전체 생성 제출/등록 자동화의 미구현 범위가 구분돼 있다. CLI 선택만으로 모든 제출·재개·다운로드 기능이 구현됐다고 가정하지 않는다. 실행에 필요한 지원이 없으면 별도 개발 절차로 보완하고 검증한다.

## 7. 품질 시험 결과를 판단하는 기준

1. **형태:** 요청한 개수·큰 실루엣·비율·끝단·바닥이 참고 자료/요청과 맞는지 기록한다.
2. **전달:** 원본을 보존하고 필요한 처리 전후 차이, 다운로드된 모델/텍스처와 실제 Unity 재로드 결과를 연결한다. Blender는 필요한 후처리 사유가 있을 때 사용한다.
3. **게임 화면:** 고정한 카메라·화면·조명에서 기존 바위·캐릭터·신규 후보를 비교한다. 단독 확대와 실제 게임 카메라 검토를 구분한다.
4. **수치:** 삼각형·정점·메시/재질·텍스처·bounds·원점·접지와 허용 컴포넌트를 검사한다. 미측정은 NOT_RUN이다.
5. **적용:** 자산 A0~A5와 맵 G단계의 실제 증거를 구분한다. 불필요한 스크립트/Rigidbody/Animator/생성 MeshCollider를 임의로 붙이지 않는다.
6. **판정/복구:** PASS/FAIL/BLOCKED/NOT_RUN, 실제 task/파일/원자료·시간·소스 지문과 미정/차이를 기록한다. 실패/취소 뒤 소유 자원만 복구하고 이전 원본·다른 작업을 보존한다.

최종 채택은 [A0~A5 절차](../../workflows/ai-3d-assets.md)의 필수 증거와 등록 조건에 따른다. 생성 완료, 다운로드 성공, 과거 바위 전송 시험, 문서/gate PASS 각각을 자산 채택으로 승격하지 않는다.
