# 첫 맵 최소 자산 목록과 제작 순서

2026-11-01 · r001 · **제작 준비 제안** · L0 문서 계획

사용자 요청에 따라 GPT-6.1 Sol / medium 서브에이전트가 프로젝트 자료를 읽기 전용으로 조사했고 메인이 근거를 대조해 저장했다. 사용자 최종 승인, 신규 생성, 자산 채택, Unity 검증 완료 기록이 아니다. 임시 ID는 제작 관리용 제안이며 실제 asset ID·개정·채택 등록을 대신하지 않는다.

> **현재 방향 — 035 후속:** 사용자가 원본과 다른 형태를 지적하여 [원본 직접 대조 기준 후보](../../reviews/reference-reset-035-review.md)로 미술 방향을 재설정했다. 028/r004와 ENV-S01/r001은 기능 시험 이력이며 새 생성의 형태·재질 입력으로 쓰지 않는다. 아래 최초 r001의 제작 방법/우선순위는 다음 현행 순서로 대체한다: 지면·연속 자갈길 → 녹색 상부/얇은 석재 외곽의 둥근·곡선 잔해 → 원본 배치의 Unity 비교. 전체 생성 수량·새 모델 치수·최종 채택은 미정이다.

연결 근거는 제작 시 참조할 영역이며, 자산별 실제 배치 승인·정확한 크기·수량 명세가 아니다. [005 객체 등록부](../../design/map-meadow-005-r001-objects.csv)와 [007 후보 layout](../../design/map-meadow-007-r001-layout.json)을 대조했다. 검색 박스의 픽셀 폭/높이를 확정 모델 치수로 전용하지 않으며 V/C/U도 원작 접지면 실측 정답이 아니다.

큰 나무는 보류 목록으로 분리한다. 꽃·표지판·동굴·새 건축물·상호작용 소품은 현재 근거가 요구하는 최소 범위에 추가하지 않는다.

## 64개 군집과 재사용 모듈의 관계

**64군집은 신규 모델 64개가 아니다.** 한 군집에 여러 소품이 필요할 수 있고, 같은 소품을 여러 군집에서 재사용할 수 있다. OB-G01은 비충돌 부모 묶음이므로 추가 모델·원판으로 세지 않는다. OB-B01~04도 외곽 조사 영역이지 벽 네 개가 아니다.

| 군집 유형 | 조합 제안 | 유지할 특징 |
|---|---|---|
| 단독 둥근·큰 군집 | R01/S02의 크기·방향·조합 비교 | 작은/큰 군집 차이, 지역별 밀도·열린 공간 |
| 직선·사선·세로 잔해 | S01/S02의 길이·끝단·배열 조합 | 우하 RF-08의 공통 사선 방향과 길이 차이. 무작위 회전으로 없애지 않음 |
| 좌상·하부 굴곡 | C01 또는 굴곡을 따라 짧은 조각 배치 | 굽은 형태와 열린 쪽. 직선 하나를 늘려 대체하지 않음 |
| 좌하 끊어진 원형 | C01의 호형 조합을 OB-060~063 각각에 대응 | 조각 사이 개구부와 내부 빈 지면. 부모 원판/연속 링으로 채우지 않음 |
| 외곽·부착 군집 | E01 구성으로 R01/S01/S02 연결 | 불규칙 외곽·부착 관계. 직사각 벽으로 단순화하지 않음 |

같은 상단·균열·끝단의 반복이 눈에 띄고 회전/크기만으로 해결되지 않으면 별도 실루엣을 추가한다. 반대로 형태마다 무조건 새 모델을 만들지 않는다. 변형 수는 대표 구역과 전맵 축소 화면의 반복성 비교로 결정한다.

모듈 외형은 C·경계·통로를 재정의하지 않는다. 장식에 Collider를 자동 부여하지 않는다. 논리상 막힌 곳에 통과 가능한 구멍이 있는 것처럼 보이면 시각 불일치로 수정한다.

## 최초 r001의 Tripo 품질 시험 제안 — 현재 미술 기준에서 제외

**추천: ENV-S01 낮은 직선 돌벽·잔해 1개.** 기존 바위와 다른 길쭉한 실루엣, 상단·측면·끝단·접지와 반복 배치를 확인하기 좋다. 사용자 확정 발주는 아니다. 전체 풍경이나 64군집을 한 번에 생성하지 않는다.

대표 구역의 곡선 개선이 우선이라면 C01이 대안이다. 곡률·끝단 제어가 필요해 첫 시험의 판단 항목이 더 많다. 기존 바위 재생성은 구체적 부족함을 확인한 뒤 검토한다.

S01의 제안은 큰 면이 읽히는 낮고 길쭉한 덩어리, 불규칙하게 깨진 상단, 안정적인 바닥, 저채도 무광 돌이다. 문자·로고·캐릭터·넓은 바닥판·붙은 풍경·떠 있는 파편·강한 고정 그림자는 제외한다. 정확한 높이·폭·색·질감은 미정이다.

비교 준비:

1. 단독 회전 화면에서 끝단·측면·바닥·구멍·불필요한 부착 요소를 확인한다.
2. 021 개발 프로필 s4/55도/ortho6과 실제 캐릭터로 기존 바위·028 자체 돌·신규 후보를 비교한다. 최종 카메라 승인이 아니다.
3. 같은 카메라·해상도·조명·파티 위치에서 단일 배치와 반복 조합을 비교한다. 직선 후보를 OB-002~004 곡선 전체에 억지로 맞추지 않는다.
4. 접지·반복·큰 형태·C와의 시각 일치·파티/적/공격 식별성을 각각 기록한다. 후보 적용 후 실제 프레임·입력·가림·전투 검사는 별도 실행한다.
5. Unity 삼각형·메시/재질·텍스처·크기·원점·의존 파일을 측정한다. 생성/다운로드 성공과 자산 채택은 구분한다.

[018 바위 입력](../../design/map-blockout-018-rock-input.json)은 TEST 자산의 위치·지문이다. [전송 도구](../../../Tools/Assets/README.md)는 기존 원본의 처리·FBX 전송 시험을 지원한다. 새 요청 제출/다운로드와 전체 A5 자동화가 완성됐다고 가정하지 않는다.

현재 계정·모델·옵션·API/Studio 비용·잔액·허용 시도 수는 **미확인**이다. 과거 일반 바위 한 건의 허용이나 Git 공개 예외를 새 생성·입력 업로드 허용으로 확대하지 않는다. TRANSFER_TEST의 10,000삼각형·2K·크기 기준도 공통 게임 예산으로 복사하지 않는다.

## 다음 실행 순서와 최소 결정

1. 첫 시험 대상과 목적을 선택한다. S01은 추천 후보이며 확정 발주가 아니다.
2. 그 한 품목의 형태·비율·팔레트, 목표 치수/원점, 기하·재질·텍스처 예산과 비교 화면을 [자산 양식](../../templates/ai-3d-asset-package.md)에 작성한다. 전체 목록의 모든 수치를 먼저 확정할 필요는 없다.
3. [Tripo 생성 기준](../../workflows/tripo-generation-standard.md)에 따라 실제 경로·모델·지원 옵션·비용/시도 한도·공개/업로드 허용을 확인한다. 로컬 원본 보유는 외부 업로드 허가가 아니다.
4. 허용된 요청 범위가 갖춰지면 한 후보를 생성·보존하고 필요한 처리만 수행한다. 지원 부족은 해당 제한으로 기록한다. 전체 자동화 신규 개발을 기본 작업에 추가하지 않는다.
5. 다른 Unity 작업과 겹치지 않는 시점에 격리 후보를 가져와 비교한다. 028/r004·원본 바위·C·기존 씬은 보존한다.
