## 측정 방법

도구와 출력은 `output/reference/hd2d-dq-20261121/char/`(Git 밖). 실행: `/usr/bin/python3`(PIL+numpy가 사용자 site-packages에 있어 `-I` 없이 돌린다).

| 도구 | 하는 일 |
|---|---|
| `../tools/zoom.py`, `../tools/dotpitch.py`, `../tools/measure.py color` | 배경 관찰 문서와 같은 도구(확대 판독, 도트 한 칸 크기, 영역 대표색) |
| `tools/charmetrics.py` + `tools/cfg.json` → `metrics.json` | 캐릭터 지표. 화면 자르기 → 마스크(테두리에서 배경색 범람, 최대 덩어리, 구멍 메움, 그림자·겹친 것은 제외 상자) → 도트 격자로 되돌리기(잰 도트 크기 p, 위상은 칸 안 분산 최소, 칸 가운데 50% 평균) → Lab 군집(k-means 24개 → ΔE<10 병합) → 지표. 우리 원본은 알파 마스크·픽셀 그대로 같은 지표 |
| `tools/relight.py` | 같은 캐릭터(S006 밝은 알현실 / S007 횃불 던전)를 기울기 상관으로 겹쳐 RGB 비를 잰다 |
| `tools/ourtint.py` | 시험 화면 A의 대원 픽셀을 원본 스프라이트(2.0~2.05배 최근접)에 맞춰 겹쳐, 장면 빛으로 색이 바뀌었는지 잰다 |
| `A-main-q80.jpg` | 시험 화면 A를 JPEG 품질 80으로 저장한 사본. 드퀘 원본(JPEG)과 같은 압축 조건에서 지표가 얼마나 흔들리는지 보는 대조군 |

지표 정의(`charmetrics.py` 머리말과 같음). 모두 **도트 칸 단위**로 잰다.

| 지표 | 뜻 | JPEG 대조(A 원본 → A JPEG80) |
|---|---|---|
| `lum_step20` 밝기 단차 밀도 | 캐릭터 안 이웃 도트 쌍 중 밝기(L*) 차가 20 넘는 쌍의 비율. 선·잔무늬가 많을수록 높다 | 0.39 → 0.41 (**안정**) |
| `lowfreq` 큰 명암 몫 | 도트 밝기 분산 중 5×5칸 평균(큰 덩어리)이 설명하는 몫. 명암이 큰 면으로 묶여 있을수록 높다 | 0.13 → 0.13 (**안정**) |
| `dark_L22` 어두운 칸 비율 | L*<22인 칸의 비율(외곽선·안쪽 선·깊은 그늘) | 0.30 → 0.32 (안정) |
| `edge_sharp` 가장자리 날카로움 | 화면 px에서 실루엣 좌우 경계 ±3px 안의 최대 한 칸 단차 / 총 변화(1 = 한 픽셀에 딱 떨어짐) | 1.05 → 0.92 |
| `ncol_cover90` 색 수 | 면적 90%를 덮는 색 군집 수 | 9 → **19 (JPEG에 크게 부풂)** |
| `isolated` 고립 도트 | 이웃 4칸과 모두 다른 색인 칸의 비율 | 0.15 → **0.37 (부풂)** |
| `big_share` 큰 색 덩어리 | 캐릭터 면적 3% 이상인 같은 색 덩어리가 덮는 몫 | 0.11 → **0.05 (줄어듦)** |

### 해석/제안

- 사용자의 "지저분하고 형태가 안 읽힘"은 숫자로 설명된다: 우리 대원은 이웃 도트 사이 큰 밝기 단차가 드퀘의 **약 2~4배**(0.36~0.46 대 0.05~0.22)이고, 밝기 변화 중 큰 덩어리로 묶인 몫이 드퀘의 **약 1/3**(0.12~0.19 대 0.42~0.75)이다. 즉 드퀘는 "큰 면 몇 개 + 그 안의 부드러운 명암"으로 읽히고, 우리는 "잔 선과 1~2칸짜리 무늬"가 몸 전체에 고르게 깔려 있다.
- 원인 후보(해석): ① 화면의 약 30~40%를 차지하는 진한 갈색 선(외곽선 + 안쪽 선, 4절), ② 배낭·주머니·벨트·버클 같은 작은 소품, ③ 재질당 2~3단계라 명암이 면이 아니라 선으로 표현됨, ④ 4명이 같은 갈색 가족을 13~17색씩 공유해 직업색 면이 작다.
- 고립 도트·색 수는 JPEG 때문에 비교하지 못했다(미확인).

## 5. 배경과의 어울림 — "배경과 따로 놂"

### 관찰

**장면 빛을 받는가(측정).**
- 같은 용사를 밝은 알현실(S006)과 횃불 던전(S007)에서 겹쳐 쟀다(`relight.py`, 기울기 상관 0.73). S007/S006 RGB 비: 몸 전체 **R 1.00 · G 0.97 · B 0.83**(파랑이 빠져 따뜻해짐), 횃불 쪽(화면 왼쪽) 절반 R 1.07 · 밝기 1.00, 반대쪽 절반 R 0.84 · G 0.89 · B 0.79 · **밝기 0.86**. 즉 같은 스프라이트가 장면 빛 색으로 물들고, **광원 반대쪽이 어두워진다**.
- 밤(V001-017, 확대 판독·측정): 흰 머리·흰 옷·흰 머리띠가 **청록**(#7ac6d9, S 0.44)으로 보인다. 낮 S004에서 흰 머리띠·분홍 조끼였던 부분이 밤에는 푸르게 바뀐다. 발밑 그림자는 L* 1.5(주변 바닥 24.9의 0.06배)로 거의 검정.

- "배경과 따로 놂"의 측정 근거는 셋이다: ① 우리 스프라이트는 장면 빛 색을 받지 않는다(비 0.94~1.02, 드퀘는 같은 그림이 B 0.83·반대쪽 0.86배로 바뀜), ② 해 받는 풀밭에서 우리 대원이 바닥보다 L* 15~20 어둡다(드퀘 4~10), ③ 우리 가장자리만 딱 떨어진다(1.0 대 0.57~0.87) — 배경은 흐림·번짐이 있는 고해상 3D라 날카로운 테두리가 "붙여 넣은 것"처럼 보인다(해석).

## 6. 방향·반전·동작

- 드퀘: 위·아래·왼쪽·오른쪽 4방향을 확인(배경 관찰 8절 재사용). 이번에 본 S009(옆·뒤), S006·S007(앞), S004·V001-017(뒤), S005(전투 뒷모습·몬스터 정면)도 같다. 대각선 그림, 좌우 반전, 걷기 프레임 수는 **미확인**.

### 방법 후보 `[해석/제안]` (만드는 방법 — 결과가 레퍼런스처럼 보이는지로 고른다)

1. **격자 48 → 더 큰 칸 수**(계산, 1080 기준):
   - 64칸, 키 9.5% 유지 → 102.6px ÷ 64 = **1.60px/칸**(비정수 — 최근접 확대면 칸 크기가 1·2px로 섞여 고르지 않다).
   - 64칸, 2px/칸 정수 → **128px = 11.9%**(드퀘 가까운 카메라 13%보다 작고 탐험 기본 10.5%보다 큼).
   - **56칸, 2px/칸 → 112px = 10.4%**(드퀘 S006 112px·55칸과 거의 같음, 탐험 범위 상단). 지금 카메라·화면 크기를 거의 그대로 두고 칸만 늘리는 후보.
   - 캔버스: 키 56칸이면 80×80 또는 72×72 캔버스(무기 여유).
2. **장면 빛 입히기**(우리 게임은 URP 3D 장면 + 세운 스프라이트):
   - (가) 스프라이트에 장면 조명을 받는 재질(Lit 스프라이트/알파 잘림 Lit 재질) — 주광 색·그늘·밤 색이 자동으로 묻는다. 반대쪽 어두워짐(드퀘 0.86배)은 법선을 몸 둥근 면처럼 휘거나 간단한 노멀맵으로.
   - (나) 셰이더에서 장면 주광색·환경광을 곱하고 해 방향 쪽 가장자리를 밝히는 림(1도트).
   - (다) 화면 전체 색 보정·안개가 캐릭터에도 걸리도록 렌더 순서 확인(S009처럼 같이 바래게).
3. **가장자리 부드럽게**: 최근접 대신 칸 경계만 1px 섞는 표본(예: 픽셀아트용 부드러운 최근접 필터, 또는 2배 렌더 후 축소). 목표 `edge_sharp` 0.7~0.87.
4. **명암 구조**: 외곽선을 면색별 진한 값으로 바꾸고 안쪽 선을 명암 단계로 대체, 배낭 등 공통 소품 축소. 바꾼 그림은 이 문서의 `charmetrics.py`로 `lum_step20`·`lowfreq`·`dark_L22`를 다시 재서 위 목표와 비교한다.
