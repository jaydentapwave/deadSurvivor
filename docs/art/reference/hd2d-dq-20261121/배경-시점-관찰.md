# 배경·시점 관찰 — 드래곤 퀘스트 HD-2D (DQ3 / DQ1&2)

- 대상: DRAGON QUEST III HD-2D Remake(DQ-S001~S005, 트레일러 DQ-V001), DRAGON QUEST I & II HD-2D Remake(DQ-S006~S010, 트레일러 DQ-V002)의 공식 Steam 상점 스크린샷 10장(1920×1080)과 트레일러 프레임 22장(1280×720). 목록·출처·해시는 [manifest.json](manifest.json), 원본은 `output/reference/hd2d-dq-20261121/`(Git 제외).
- 모드: **follow** — 배경과 시점(카메라)의 기준. 캐릭터·몬스터 도트는 우리 것을 그대로 쓴다. 원작 고유 캐릭터·몬스터·건물·지도 배치·UI는 가져오지 않는다. 원본은 생성 입력·게임 에셋·따라 그릴 원본으로 쓰지 않고 외부 서비스에 올리지 않는다.
- 이 문서가 새 아트 기준서의 배경·시점 근거다. 이전 옥토패스 관찰([hd2d-bg-octopath-20261118](../hd2d-bg-octopath-20261118/배경-관찰.md))의 값은 가져오지 않았다. 끝에서 두 번째 절에서 다른 점만 잰 값으로 비교한다.
- 관찰자: Claude(하위 에이전트, 2026-11-21). 스크린샷 10장 전부와 고른 프레임 22장을 원본 크기로 열었고, 캐릭터·원형 물체·그림자·나무 등 25곳 남짓을 2~10배로 확대해 읽었다(맨 끝 "본 그림").
- 표기: **측정** = 파일에서 스크립트로 잰 값. **확대 판독** = 확대 그림에 원본 좌표 눈금을 얹고 사람이 읽은 값(±2~3px). **계산** = 측정값을 식에 넣은 값. **추정** = 눈대중. 정지 그림이라 움직임은 **미확인**.
- 좌표: 스크린샷은 1920×1080, 프레임은 1280×720 화면 좌표 `(x0,y0)-(x1,y1)`. 비율(%)은 화면 세로 대비라 해상도와 상관없이 비교된다.

## 측정 방법

측정 스크립트는 `output/reference/hd2d-dq-20261121/tools/`에 있다(PIL+numpy가 있는 `/usr/bin/python3`).

| 도구 | 하는 일 |
|---|---|
| `zoom.py` | 영역을 최근접으로 키우고 원본 좌표 눈금(10px·50px)을 얹는다. 캐릭터 키·타원·나무 키는 이 그림을 읽었다(확대 판독) |
| `dotpitch.py` | 영역의 색 경계가 몇 px 간격으로 몰리는지(위상 일치도 0~1)로 도트 한 칸 크기를 잰다. 도트 그림은 일치도가 솟고, 매끈한 질감은 0.07 이하 |
| `measure.py rows` | 가로 띠별 선명도(밝기 라플라시안 절댓값 평균)와 최댓값 대비 %. 프레임은 자막 구간(y 615~700)을 뺐다 |
| `measure.py color` | 영역 대표색 = RGB를 16단계로 묶은 최빈 묶음의 평균(괄호 % = 그 묶음 비율), HSV 채도(S)·명도(V) 중앙값, 가장 진한 값(밝기 하위 1%) |
| `measure.py grain` | 가장 잔 세부: 큰 명암(13px 상자 평균)을 뺀 고주파 성분의 자기상관이 0.5로 떨어지는 거리×2(px), 고주파 세기(SD) |
| `measure.py vig` | 네 모서리(12% 상자)/가운데(30% 상자) 평균 밝기 |
| `measure.py cover` | 숲 덩어리(청록 잎)와 밝은 풀의 면적 비율 |
| `strip_vp.py` | 바닥 위 곧은 띠 가장자리의 소실점(자동 가장자리 찾기가 금색 술 때문에 흔들려, S006 양탄자는 확대 판독 값을 썼다) |
| `camera.py` | 지평선 높이 + 바닥 원의 타원 비 → 내려다보는 각(pitch)·시야각 풀이, 수직선 기울기 예측 |
| `make_manifest.py` | manifest.json 생성(크기·SHA-256 재측정) |

### 해석/제안

- 드퀘 HD-2D 탐험 카메라는 **좁은 시야각(세로 약 18~22°)의 원근 카메라를 낮게(15~19°) 기울여 멀리서 찍는** 방식이다. 이전 우리 카메라(정사영 30°)와는 원근 유무와 각도 둘 다 다르다.
- 기준서 카메라 출발값: 마을·숲 기준 pitch 약 18°, 세로 시야각 약 20°, 캐릭터 키 화면 세로 약 9~10%. 오버월드식(10~15°, 먼 풍경·하늘)은 화면 위쪽 판독 문제가 커서 우리 전투에 그대로 쓰기 어렵다(맨 끝 절).

## 2. 배경 질감 밀도

### 관찰

**캐릭터 도트 한 칸(측정, `dotpitch.py`).** 1080 화면에서 캐릭터 도트 한 칸 = **약 1.9~2.5px**(S004 머리 2.10[일치도 0.32], 사제 2.45[0.28], S009 2.2·2.1[0.35~0.40], S006 2.0[0.67], S007 2.2[0.39], S010 1.85[0.33]). 10배 확대로 S004 용사 머리털 계단이 2px 단위임을 눈으로도 확인했다. 캐릭터 키를 도트로 환산하면 약 **45~60칸**(S006 106px÷2.0 ≈ 53칸, S009 약 45, S004 사제 약 58).

**배경은 도트가 아니다(측정).** 같은 방법을 배경에 돌리면 일치도가 0.07 이하로 도트 격자가 없다(S004 풀 0.06, 숲 0.04, 흙 0.06 / S009 풀 0.04, 모래 0.07 / S010 풀 0.03~0.05). S006 양탄자(0.21)·S007 돌바닥(0.18)에서 보이는 4·8px 주기는 JPEG 8×8 블록 흔적이다. 확대해 봐도 풀·흙·돌·물·잎 모두 **매끈한 고해상 질감과 3D 모형**이다(**확대 판독**).

### 해석/제안

- 전투 들판(오버월드식)은 빈 풀밭 위주로 두고 나무를 덩어리로 화면 가장자리에 모으면 몬스터 수백 마리가 다닐 공간과 판독이 산다. 가까운 축척(실물 비례)과 줄인 축척(오버월드) 중 무엇을 쓸지는 기준서에서 정한다.

## 7. 캐릭터와 배경의 관계

### 관찰

- 외곽선: 캐릭터는 **1도트 어두운 색 외곽선**(검정이 아니라 남색·적갈색 등 칠 색의 어두운 값)을 두른다(S004 용사 머리, S009 세 명, V002-059 확대). 배경 물체에는 외곽선이 없다.
- 그림자: 발밑 둥근 얼룩(4절). 실루엣 그림자는 보지 못했다.
- 분리되어 보이는 이유(측정 근거): ① 캐릭터만 도트 격자가 있다(일치도 0.16~0.67 대 배경 0.07 이하), ② 캐릭터 고주파 세기가 배경의 3~8배(2절), ③ 초점 띠가 캐릭터 높이에 있고 위아래가 흐리다(4절), ④ 캐릭터는 여러 색(보라·분홍·파랑·주황)이고 바닥은 거의 한 색 계열(초록 S 0.7~0.9)이다, ⑤ 외곽선과 둥근 그림자.

### 해석/제안

- 우리 도트 캐릭터·몬스터는 지금 외곽선을 그대로 두고, 배경은 외곽선 없는 매끈한 질감 + 낮은 고주파 세기로 만들어 같은 분리를 얻는다.

4. 위아래 흐림 세기: 드퀘값(맨 위 15~30%)을 쓰면 화면 위쪽 몬스터가 흐려진다 — 전투 판독과 함께 정한다.
5. 하늘·먼 풍경을 화면 위에 둘지(오버월드식) 바닥만 채울지(마을식).
6. 해 방향 하나를 정할지(드퀘는 장면마다 다름).
7. 가장자리 어둡게 사용 여부(측정이 약해 우리 쪽 결정).

## 우리 게임에 옮길 때 부딪히는 것 (해석/제안)

- **화면 위쪽 몬스터가 작고 흐려진다.** 측정한 마을 카메라(pitch 18.6°, 세로 시야각 17.8~21.8°)를 16:9에 그대로 쓰면, 같은 크기 몬스터가 화면 맨 위에서 가운데의 **0.42~0.53배**, 맨 아래에서 1.45~1.54배로 보인다(위/아래 크기 비 0.27~0.36, `camera.py`와 같은 식으로 계산). 보이는 땅은 가운데 폭의 2.2~2.6배 깊이로 길게 뻗고, 위쪽 끝 폭이 아래쪽 끝의 약 3배다. 여기에 위쪽 흐림(맨 위 선명도 15~30%)이 겹친다. 사방에서 수백 마리가 오는 우리 전투에서는 위쪽(먼 곳)에서 오는 몬스터를 읽기 어렵고, 같은 거리의 몬스터가 화면 위아래에서 다른 크기로 보인다. 오버월드식 더 낮은 각(9~15°, 추정)이면 더 심하다(12°에서 맨 위 0.26배).
- 같은 시야각에서 각도만 올렸을 때(계산): 26°(V002-051·S010 수준) 맨 위 0.67배 / 맨 아래 1.31배, 30° 0.72 / 1.26배, 45° 0.83 / 1.14배. 깊이/폭 비도 26°에서 1.43, 30°에서 1.21로 사방이 고르게 보인다.
- **드퀘 안에서 더 높이서 보는 장면**: 마을 V002-051(약 26°)과 숲 제단 사건 S010(약 29°)이 있다. 이 둘은 하늘 없이 바닥이 화면을 채우고, 원형 광장·제단이 덜 납작하게(타원 비 0.43~0.50) 보여 둘레 전체를 한눈에 본다. 사방에서 오는 적을 보는 우리 전투에는 탐험 기본값(18°)보다 **이 26~30° 카메라가 더 맞다**(제안). 같은 좁은 시야각을 유지하면 "멀리서 망원으로 찍은 디오라마" 느낌은 남는다. 다만 이것은 드퀘 탐험 카메라와 다른 값이므로 기준서에 "레퍼런스와 다르게 가는 것"으로 적는다.
- 위쪽 흐림을 드퀘만큼 세게 걸면 위쪽 몬스터 판독이 떨어진다. 흐림은 화면 맨 위 가장자리(먼 배경 장식)에만 걸고 몬스터가 다니는 띠에는 걸지 않는 쪽을 제안한다.
- 드퀘 오버월드의 넓은 빈 풀밭과 덩어리 숲(숲 0~27%)은 몬스터 수백 마리가 지나갈 공간과 잘 맞는다. 반면 마을·숲길의 빽빽한 덤불·소품·풀 덤불은 몬스터 발밑을 가리므로 화면 가장자리에만 둔다.
- 배경 고주파 세기를 캐릭터의 1/3 이하로 누르는 드퀘 방식은 수백 마리 몬스터를 배경에서 떼어 보이게 하는 데 그대로 도움이 된다.
- 모바일 세로 화면이면 세로 시야각이 커져(가로 시야각을 같게 둘 때) 위아래 크기 차가 더 벌어진다(추정). 화면 방향을 정한 뒤 다시 계산한다.
