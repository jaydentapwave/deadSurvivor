### 3.2 화면·지형 구조 (r6)

- 카메라와 물건 모양: 카메라는 K2. 앞뒤 정렬은 **깊이 버퍼**(불투명 + 알파 클립). (r5: 2D 겹, Transparency Sort Axis (0,1,0))
- 겹(뒤 → 앞): ① 3D 땅(도트 질감, 가장자리 높낮이) → ② 3D 소품·세운 식물 판(가장자리) → ③ 실제 그림자(대원·소품·식물)·눕힌 그림자 판(몬스터) → ④ 세운 도트 판(대원·몬스터·투사체) → ⑤ 효과 → ⑥ 화면 효과(흐림·Bloom·톤·가장자리 어둡게) → ⑦ HP 막대·피해 숫자(월드 세운 판, 후처리 뒤, 늘 위) → ⑧ UI 캔버스(Screen Space Overlay, 화면 효과 밖) [방법, design-brief 3.8·3.10].
- 가운데 비우기: 그대로 — 화면 가운데는 비우고 키 큰 것·높낮이는 가장자리 띠에 [레퍼런스·해석: PE-G001, 관찰 1절]. 지형 배치는 **시안 F 그대로**(사용자 11-18 "지형자체는 우선 기존에 만든 걸 그대로 사용").

### 3.5 색·광택

- 광택 없음(도트 평면 채색, 면당 2~3단 음영). **r6: 빛은 3D 해·하늘빛(K10)이 맡는다**(r5: Light2D). 세운 판 재질은 툰 3단(명암 램프 0.58/0.80/1.0, 문턱 0.25/0.68, 시안 2회차).
- 대비: 캐릭터·몬스터·효과 > 바닥. 바닥 재질 자체는 대비를 낮게, 큰 명암은 빛 얼룩·그림자 쪽에서 [레퍼런스·해석: 배경 관찰 6절].

### 3.6 성능 예산 (r6, K27)

측정 조건 `[방법]`: 실제 API로 확인한 **Mobile 품질**(`Mobile_RPAsset`, Render Scale 1.0, SRP Batcher 켬, AA 끔), 1920×1080, 몬스터 300마리, 20초, 표본은 진행한 프레임마다, Editor UnityStats. **측정 중·뒤에 화면 캡처하지 않는다**(사용자 11-18 "이거 300마리를 검증을 할떄 굳이 캡쳐를 왜하는건지 좀 의문이야") — 증거는 측정 JSON의 품질 이름·파이프라인·활성 몬스터 수·렌더러 수·값. 판정은 **렌더·프레임 시간을 그리기 호출 수보다 먼저** 본다(예전 049: 그리기 호출은 줄었는데 렌더 시간이 늘었다).

### 3.7 프롬프트 틀

- 공통 스타일(캐릭터·몬스터·효과·아이콘·세운 식물 판): `warm high-bit pixel art, anime SD character about 3 heads tall with a big head and big eyes, 1-pixel dark brown outline (#34140e, not black), flat 2-3 tone shading, no anti-aliasing, no gradients`
- 캐릭터 추가: `carries a big brown travel backpack as large as the torso, single character on flat #ff00ff background` + **방향(r6)**: `facing down toward the camera` / `3/4 view facing lower-right` / `side view facing right` / `3/4 back view facing upper-right` / `back view facing away (up)` — 카메라는 30° 내려다봄
- 격자(K11): `exactly <W>x<H> pixel grid, every pixel is one <B>x<B> flat block, canvas <W*B>x<H*B>` — W·H는 3.1절 캔버스
- 몬스터: `simple round monster with two glowing eyes, purple or teal body that stands out from olive-yellow grass`
- **배경(r6)** — [배경 관찰](reference/hd2d-bg-octopath-20261118/배경-관찰.md) "생성·질감 스타일 문구"를 그대로 쓴다. 단 "no outline" 대신 K19(갈색 외곽선)를 따르고, 나무는 아래 문구:
  - 바닥: `hand-pixeled ground texture for a 3D diorama, muted olive-yellow grass with short diagonal blade strokes, 3-4 value steps, no visible tiling, very low-contrast large brightness variation (no camouflage blobs), dirt path with horizontal grain and stepped pixel edge, sparse upright grass tufts along the edge`
  - 턱·돌: `rounded grass-topped terrain block, grass lip curling over the edge with one bright rim row, earth-and-stone side face in 3 stepped bands at about 30-50 percent of the top brightness, fieldstone with darker joint lines painted in the texture, 2-4 flat shading bands, no speckle noise`
  - 나무: `upright pixel-art tree billboard, blue-green leaf body 0.2-0.3 darker than the grass, lighter yellow-green leaf clusters on the lit side, 1-pixel dark brown outline, stepped pixel silhouette`
  - 물: `dark teal-olive pond water darker than the grass, soft pale ripple highlights in pixel clusters, stone edge entering the water directly, no foam line`
  - 제외(배경): `no smooth untextured low-poly surfaces, no flat single-color faces, no repeating tile grid, no saturated orange-yellow ground, no bright flat water, no straight hard-edged path bands, no photo textures, no painterly brush texture, no black outlines`
- 제외(공통): `no text, no UI, no gems or coins, no bird mount, no logos, no characters from existing games`. 레퍼런스 원본 그림은 생성 입력으로 넣지 않는다.

### 3.10 동작

방식은 `2d-animation.md` 6절의 네 질문으로 골랐다(r1). 흔들림·깜빡임처럼 단순한 것은 변환만(정수 픽셀 이동, 5절). **r6: "1px"은 세운 판 위 도트 한 칸 = 1/48m(화면 n px)이다.** **r6: 방향은 K14 — 대원 클립은 5방향 그림 + 반전으로 8방향.**

### 3.13 UI (r6 새, K16) — UI 관찰 "기준서 r6 UI 절 초안" A~H를 그대로 옮김

- 옮긴 원본: [UI 관찰](reference/hd2d-ui-octopath-20261118/UI-관찰.md) 마지막 절 A~H. 문장은 바꾸지 않았다. 이미지 id만 검사 도구가 구별하도록 접두어를 붙였다(예: 가운뎃점 뒤 번호에도 `OU-` 접두어). (H의 "이 초안"은 그 관찰 단계 범위를 뜻한다).
- **K16 원문 두 개**: r5(대체됨) 2026-11-17 "3번 (Recommended)", "지금처럼 어두운 가죽 (Recommended)" / r6(대체) 2026-11-18 "추가적으로 이미지 래퍼런스 나왔으니 ui도 해당 3d 래퍼런스랑 동일한 디자인이면 좋을것 같아 가능하다면 작업을 해주고". 같은 대상(UI)의 더 새 지시라 충돌이 아니라 대체로 보고 묻지 않았다(디렉터 판단, UI 관찰 "메인 확인"). 최종 보고 때 사용자에게 함께 보인다.

#### E. 만드는 법 — 도트 UI에서 고해상 UI로 [방법]

- 레퍼런스 UI는 **도트가 아니다**. 선이 1080에서 1~2px로 매끈하고(계단 없음), 판넬은 그라데이션이다. 도트는 초상·캐릭터에만 있다(OU-S002·OU-S005 확대). HD-2D의 "도트 캐릭터 + 고해상 UI" 조합이다.
- 지금 캔버스는 640×360 기준·높이 맞춤이고, 빌더 주석이 "UI 도트 크기가 월드와 같다"로 도트 UI를 전제한다(`Assets/Game/02.Scripts/Editor/MainSceneBuilder.cs` CreateCanvas). 배치 단위(640×360 기준px)는 그대로 두고, **틀 그림만 고해상(기준px당 3~4 텍셀, 필터 Bilinear)**으로 그려 `Pixels Per Unit Multiplier`로 맞춘다. 레이아웃 코드는 거의 그대로다.
- 도트 초상·아이템 아이콘은 Point 필터 그대로 두고, 칸 크기를 화면 정수 배율에 맞춘다(아래 F).

#### F. 모바일 규칙

이 게임은 **가로 고정**이다(ProjectSettings: 기본 방향 자동 회전 + 가로 왼쪽·오른쪽만 허용, 세로 금지). 그래서 화면비 목록(`screen-layout.md` 2절)을 가로로 읽는다.

| 화면비(가로) | 예 해상도 | 기준 캔버스 폭(높이 360 맞춤) | UI 배율(높이/360) | 정수? |
|---|---|---|---|---|
| 16:9 | 1920×1080 | 640 | 3.0 | 정수 |
| 19.5:9(노치) | 2340×1080 / 2532×1170 | 780 | 3.0 / 3.25 | 앞만 정수 |
| 21:9 | 2520×1080 | 840 | 3.0 | 정수 |
| 4:3(태블릿) | 2048×1536 | **480** | 4.27 | 아님 |

(계산값, 측정 아님)

- **안전 영역**: 가로 iPhone은 노치·다이내믹 아일랜드가 **왼쪽 또는 오른쪽 끝**에, 홈 표시줄이 **아래**에 온다. 이미 있는 `UI_SafeAreaPanel`(`Assets/Game/02.Scripts/UI/UI_SafeAreaPanel.cs`, `SafeAreaLayout`) 안에 글자·버튼·초상을 두고, **판넬 바탕·빛 번짐·위아래 띠는 안전 영역 밖 화면 끝까지** 채운다(레퍼런스 9절: 바탕은 끝까지, 내용은 안쪽).
- **4:3이 가장 좁다(기준 폭 480)**: 로비 카드 4장(지금 묶음 폭 460)과 정비 가방 4개가 480 안에 들어가야 한다. 21:9(840)에서는 가운데 묶음을 늘이지 말고 양옆을 배경으로 둔다. 메뉴의 세로 띠 판넬(OU-S001, 폭 47%)은 폭을 비율이 아니라 **기준px 고정**(예 300)으로 두어 4:3·21:9 모두에서 같은 모양을 유지한다([방법]).
- **최소 터치 크기**: 레퍼런스는 패드용이라 명령 줄 높이 37px(화면 높이 3.5%), 버튼 60px(5.6%)로 터치에는 작다. 터치 영역은 **44기준px 이상**(가로 폰 높이 약 360~430pt/dp에서 약 44~53pt, Apple 44pt·Android 48dp 근처, 계산값)으로 둔다. 보이는 판은 레퍼런스 비율 쪽으로 얇게(버튼 판 26~30기준px) 두고, 투명한 누름 영역을 44로 넓힌다. 지금 ×1(36×18)·일시정지(52×18)·출발(140×30)은 누름 영역이 모자란다.
- **글자 최소**: 기준 글꼴 크기 9 이상(꼬리표), 본문 10~12. 지금 아이템 칸 글자 6·대원 HP 8은 올린다. 레퍼런스 비율(대문자 1.8~2.1% H)은 크기 10~11과 같다(5절).
- **도트 정수 배율과의 관계**: 틀 그림이 고해상(E)이면 배율이 정수가 아니어도 깨지지 않는다 — 지금 도트 9-slice는 3.25·4.27배에서 바늘땀 간격이 고르지 않게 보인다(계산상, 화면 미확인). 도트로 남는 초상·아이콘은 **화면 픽셀 기준 정수 배율로 크기를 정한다**(예: 32텍셀 아이콘을 `floor(배율)`배로). 정수가 아닌 배율(3.25, 4.27)에서는 아이콘만 한 단계 내려 정수로 맞추고 칸은 고해상이라 그대로 둔다.
- 확인 방법(UI를 바꾼 뒤): 1920×1080, 2340×1080, 2520×1080, 2048×1536 Game 뷰 캡처 + Device Simulator 노치 기기(가로) 1대. 판정 경로 캡처(`Logs/playable/latest/`)가 이미 앞 넷을 찍는다.
