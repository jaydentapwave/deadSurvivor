# 동작(걷기·공격) 제작 방법 조사 — Aether 없이 만드는 길

- 작성: 2026-11-22. 대상: 대원 4명 × 그리는 방향 5개 × 걷기·공격 = 40클립(왼쪽 방향은 좌우 반전).
- 계기: 사용자 2026-11-22 "그러면 codex를 활용해서 스프라이트를 뽑아볼래" → 1차 시험을 본 뒤 "지금은 너무 어색한것 같아", "만약 에테르를 사용하지않고 우리가 애니메이션을 계속해서 만든다고 한다면 자연스럽게 만들 수 있는 방법이 있을까" → "1번을 먼저 해보고, 추가적으로 에이전트를 호출해서 깃헙이나 오픈소스에 쓸만한 툴이 있는지, 또는 소스가 있는지 좀 파악을 해볼래".
- 이 문서는 조사와 시험 기록이다. 2차 시험(자세 틀 방식)을 사용자가 "훨씬 나아졌어"로 받아 그 방식을 이어 간다(6절). 40클립 양산 방법으로 확정된 것은 아니다 — 걷기 다리와 정면 걷기는 더 다듬어야 한다. 채택되면 [아트 기준서](아트-기준서.md) 3.10절(동작 방식, K17 "Aether로 (손질 포함)")을 개정한다.

## 1. 지금까지의 결론

- 정지 도트 그림 한 장을 넣으면 자연스러운 걷기가 나오는 **무료·오픈소스 도구는 찾지 못했다.** 그 일을 하는 것은 상용 서비스뿐이다(Aether, PixelLab, Retro Diffusion 등).
- 대신 지금 방식(그림 생성 + 코드)을 받쳐 줄 재료와 도구는 있다. 어색함의 원인이 생성기가 아니라 만드는 방식에 있어, 방식을 바꾸면 나아질 여지가 있다(2차 시험으로 확인 중).
- Aether 잔액은 404크레딧(2026-11-22 조회). 40클립을 Aether로 만들면 클립당 5~9크레딧 → 200~360.

## 2. 1차 시험 (Codex 내장 이미지 생성만)

결과: `output/hd2d-dq/codex-sprites/preview.html`, 핸드오프 `.director/outbox/20261122-dq-codex-sprites-1.md`. 전사 한 명, 동작마다 4프레임, 생성 17회, Aether 호출 0.

| 방법 | 걷기 오른쪽 | 걷기 아래 | 공격 오른쪽 |
|---|---|---|---|
| A. 한 장에 프레임 줄 | 다리는 번갈지만 두 프레임이 거의 같음 | 움직임 폭이 작음 | 가장 무난 |
| B. 기준 그림 고치기(머리·몸통은 원본 도트) | 가장 무난 | 다리가 망토에 가려 걸음이 안 읽힘 | 무난, 칼이 조금 얇음 |
| C. 조각 이동(생성 없음) | 뻣뻣함 | 발이 조금 떠 보임 | 팔이 막대처럼 가늘어 어색 |

- 잘 된 것: 머리·몸통을 원본 도트로 덮어 얼굴과 색이 프레임마다 흔들리지 않는다.
- 안 된 것: 생성 그대로는 한 번도 통과하지 못했다. 처음엔 같은 다리만 앞으로 나왔고, 다리 연결·칼·방패 가림을 프레임마다 손으로 고친 뒤에야 걷기·휘두르기로 읽혔다.
- 사용자 판정: "지금은 너무 어색한것 같아".

### 어색한 원인 (디렉터가 프레임을 직접 열어 본 진단)

| 원인 | 설명 |
|---|---|
| 자세를 글로 시킴 | 그림 모델은 걷기의 박자를 모른다. 다리 위치가 제멋대로 나온다 |
| 상체 통째 고정 | 얼굴이 흔들리지 않게 머리·몸통을 원본으로 덮어, 걸을 때 몸이 오르내리지 않는다 |
| 따라 움직임 없음 | 망토·머리카락·칼이 전혀 흔들리지 않는다 |
| 공격에 준비·여운 없음 | 칼 위치만 네 번 바뀐다 |
| 프레임 4장 | 핵심 자세가 맞지 않은 상태에서 장 수까지 적다 |

## 3. Aether 없이 가는 세 가지 길

| 방법 | 어떻게 | 자연스러움 | 비용·부담 |
|---|---|---|---|
| 1. 자세 틀을 넣고 그리기 | 표준 걷기 주기(디딤 → 내려앉음 → 지나감 → 올라섬)의 뼈대 그림을 프레임마다 입력으로 주고 6~8프레임 생성. 상체는 1칸씩 오르내리고, 망토·머리는 따로 2~3가지 흔들림을 그려 붙인다. 공격은 준비 → 휘두름 → 여운에 칼 궤적 효과와 앞으로 내딛는 이동 | 1차보다 나아질 것으로 봄(추정 — 2차 시험으로 확인) | 무료. 클립마다 손질이 조금 남음 |
| 2. 뼈대 애니메이션 | 캐릭터를 머리·몸통·팔·다리·무기·망토 조각으로 나눠 뼈대로 움직이고 도트 프레임으로 굽는다 | 움직임 곡선은 가장 매끄러움. 동작 하나를 네 명이 같이 씀 | 무료. 방향마다 조각을 나눠야 해 준비가 큼. 작은 도트는 회전할 때 자글거림 |
| 3. 3D 모델을 찍어 도트로 | 대원을 3D 모델로 만들어 공개 모션을 입히고 다섯 각도에서 찍어 도트로 내린다 | 가장 자연스럽고 모든 방향이 저절로 맞음 | Tripo 크레딧 필요. 손으로 그린 도트 느낌과 달라질 위험이 큼 |

추천 순서: 1 → 부족하면 2 → 3은 그림체가 바뀔 위험 때문에 마지막.

### 2차 시험 (방법 1) — 진행 중

- 지시문: `.director/runs/20261122-dq-codex-sprites/steps/2-pose-driven.md`. 결과가 나오면 `output/hd2d-dq/codex-sprites-r2/preview.html`.
- 범위: 전사 걷기 오른쪽 8프레임(6프레임 판 포함), 공격 오른쪽 6프레임(칼 궤적 효과, 프레임마다 다른 시간), 시간이 남으면 정면 걷기.
- 볼 것: 다리가 틀대로 번갈아 나오는가, 골반 높이가 오르내리는가, 디딘 발이 미끄러지지 않는가, 망토가 늦게 따라오는가, 공격이 "당김 → 터짐 → 멈춤"으로 읽히는가. 1차 결과와 나란히 재생해 비교.
- 결과(2026-11-22, `output/hd2d-dq/codex-sprites-r2/preview.html`, 핸드오프 `.director/outbox/20261122-dq-codex-sprites-2.md`): 27분, 생성 20회, Aether 0, 커밋 없음. 걷기 오른쪽 8장(+6장 판), 공격 6장(궤적 효과 2장, 프레임마다 다른 시간), 정면 걷기 6장.
  - **공격: 나아짐.** 몸을 뒤로 당겼다가 5칸 앞으로 내딛고, 준비·타격·여운의 시간이 다르다. 궤적 효과가 타격 순간을 분명히 한다. 남은 것: 복귀가 급하고, 휘두름 프레임의 뻗은 팔이 각지다.
  - **걷기 오른쪽: 부분 개선.** 몸 오르내림과 망토 지연이 생기고 다리 순서·발 위치가 고르다. 다만 생성 8장을 그대로 쓰면 장화 폭·정강이 면이 흔들려, 첫 프레임의 다리 조각을 관절 틀에 맞춰 붙이는 손질로 바꿨다 — **생성만으로 자연스러워진 것이 아니다.** 금속 다리가 통째로 굽는 느낌이 남는다.
  - **정면 걷기: 약함.** 발만 드는 느낌, 다리 무늬가 프레임마다 조금 다르다.
  - 제작 쪽 판단: 양산 채택 보류. 40클립 추정 18~36시간(추정, 클립당 손질 20~40분). 구멍 검사 일부 FAIL은 그대로 기록. 다른 계열 판독은 NOT_RUN(`judge/` 묶음만 있음).
  - 디렉터가 본 것: 프레임 줄과 비교 재생 파일을 디코딩한 프레임(걷기 24장). 공격은 1차와 수준이 다르고, 걷기는 "움직임은 맞는데 딱딱함".
  - **사용자 판정(2026-11-22): "훨씬 나아졌어"** → 자세 틀 방식을 이어 간다. 절차와 값은 6절, 킷에 올릴 것과 배운 점은 7절.

## 4. 오픈소스 조사 (2026-11-22)

하위 에이전트가 웹에서 조사했다. **[열람]** = 페이지를 직접 열어 확인, **[검색]** = 검색 요약만 봄. 별 수는 조사 시점 값이고, 저장소 대부분은 마지막 커밋 시기를 확인하지 못했다.

### 4.1 시험해 볼 만한 순서

| 순위 | 무엇 | 왜 | 도입 난이도 |
|---|---|---|---|
| 1 | 공개 모션 데이터(CMU 모션캡처 BVH)나 LPC의 박자 표로 2D 자세 틀 만들기 → 그림 편집 모델에 자세 틀 + 정지 그림 → `proper-pixel-art`로 격자·팔레트 고정 | 어색한 원인("자세가 제멋대로, 오르내림 없음")에 가장 직접적. 방법 1과 같은 방향이고, 자세 틀을 손으로 짜는 대신 실제 걷기 데이터에서 뽑는다. 무료, 파이썬·맥에서 됨 | 낮음 |
| 2 | 정지 그림을 부위로 나눠 정수 칸 이동 + RotSprite 방식 회전으로 굽기(파이썬으로 직접 작성) | 원본 도트 그대로라 그림체가 어긋나지 않는다. 걷기의 바탕 프레임으로 안정적이고 생성 모델이 덧칠할 밑그림으로도 쓸 수 있다 | 중간 |
| 3 | 유니티 2D Animation으로 리깅 → 동작 확인 → 프레임으로 굽고 스냅 | 엔진 안에서 박자를 빨리 고른다. 실시간 변형은 도트를 뭉개므로 반드시 구운 뒤 정리 | 중간 |
| 4 | 3D 대역 모델 + 공개 모션 → `SpriteSheetMaker`나 `GodotPixelRenderer`로 5방향 촬영 → **자세 틀·밑그림으로만** 사용 | 비스듬한 방향의 원근과 망토 흐름을 정확히 얻는다. 3D 대역을 만드는 비용이 든다 | 중간 |
| 5 | `Sprite-Sheet-Diffusion` | "그림 1장 + 자세 → 스프라이트 프레임"을 하는 유일한 오픈소스. 자세 입력 부품이 빠져 있고 맥에서 도는지 불확실 | 높음 |

## 6. 자세 틀 방식 — 절차와 값 (2차 시험에서 쓴 것)

재료와 스크립트는 `output/hd2d-dq/codex-sprites-r2/`에 있다(Git 제외 폴더 — 양산에 쓰기로 하면 도구를 `Tools/`나 킷으로 옮긴다). 실행 순서는 그 폴더의 `build-order.md`, 프롬프트·입력 해시는 `source-manifest.json`.

### 6.1 순서

| 단계 | 하는 일 | 도구·파일 |
|---|---|---|
| 1. 자세 틀 | 생성 없이 코드로 마네킹을 그린다: 머리·몸통·골반 덩어리 + 가까운 다리/먼 다리/가까운 팔/먼 팔을 서로 다른 색 막대. 관절(엉덩이·무릎·발목·어깨·팔꿈치)은 칸 좌표 표로 정한다 | `templates.py`, `templates/` |
| 2. 틀 재생 확인 | 틀만으로 GIF를 만들어 걷기·휘두르기로 읽히는지 먼저 본다. 틀이 어색하면 그림도 어색하다 | — |
| 3. 프레임 생성 | 프레임마다 기준 방향 그림(16배) + 그 프레임의 틀을 입력으로. "캐릭터와 그림체는 첫째 그림, 자세는 둘째 그림, 색 막대는 그리지 말 것" | Codex 내장 이미지 생성 |
| 4. 도트로 내림 | pixelize 72×72 → 기준 그림의 팔레트로 고정(새 색을 더하지 않는다) → 안내 색이 남았는지 팔레트 고정 **전에** 센다 | `reduce.py` |
| 5. 원본 되돌리기 | 걷기: 상체 묶음(머리·몸통·방패·배낭)을 기준 픽셀로 되돌리고 골반 높이 표만큼 정수 칸 이동. 공격: 머리만 기준 픽셀(몸은 생성 자세 유지) | `assemble.py` |
| 6. 다리 통일(걷기) | 프레임마다 생성한 다리는 장화 폭·정강이 면이 흔들린다 → 첫 프레임의 금속 면·장화 조각을 관절 틀에 맞춰 정수 스캔라인으로 붙인다 | `retarget_walk.py` |
| 7. 따라 움직임 | 망토 끝 3가지(뒤로 날림/내려옴/중간), 뒷머리 1칸 흔들림, 칼 든 팔의 작은 반대 흔들림을 주기에 맞춰 붙인다. 망토는 내려앉음 **다음** 프레임에 변한다 | `pieces/` |
| 8. 마감 손질 | 끊긴 칼날 잇기, 머리 밖에 남은 생성 머리 조각 지우기, 망토는 색 마스크로만 변형(사각형으로 지우면 다리까지 잘린다) | `finish_pixels.py`, `repair_attack.py` |
| 9. 내보내기·확인 | 프레임별 지연을 넣은 GIF → **완성 파일을 디코딩해** 순서대로 본다. 1차와 나란히 붙인 비교 GIF | `export.py`, `audit_package.py` |

## 7. 킷에 올릴 것과 배운 점

같은 내용을 번호(P32~P37, A41~A52)로 [작업 개선 기록](../game/hd2d-작업-개선-기록.md) "2026-11-22 대원 얼굴·몬스터·방향·동작" 절에 적었다. 여기는 동작 제작에 닿는 것만 줄여 옮긴다.

| 올릴 것 | 어디에 | 왜 |
|---|---|---|
| "그림 모델로 동작을 만들 때는 자세 틀을 입력으로" 경로(6.1절 순서) | 킷 `2d-animation.md` 6절 방식 표, `2d-art-produce` "반복 동작의 자세 그림" 절 | 글로 시킨 1차는 생성 그대로 한 번도 통과하지 못했고, 틀을 넣은 2차는 사용자 "훨씬 나아졌어" |

| "머리 밖에 남은 생성 조각" 검사 | 킷 도트 동작 검사(`pixelcheck.py motion` 계열) | 머리 불투명 칸 차이 0인데 머리 밖에 생성된 머리카락이 남아 있었다 — 실제 결함을 잡은 검사 |
| 자세가 크게 바뀌는 동작의 구멍 검사는 숫자만으로 반복 수정하지 않는다(빼기 후보) | 킷 `2d-animation.md` 3절 표 | 팔·얼굴 사이의 정상 빈 공간도 FAIL로 센다 |
| `proper-pixel-art` 시험, RotSprite 방식 회전의 파이썬 구현 | 킷 도구 후보 | 조사 4절 — 프레임 간 격자·팔레트 일관성, 도트를 깨지 않는 부위 회전 |
| 유료 서비스 쓰기 전에 잔액과 도구별 1회 비용을 읽기 전용으로 한 번 조회 | 킷 `2d-art-aether` 0절 | 견적을 "지난 시험 가정값"이 아니라 그날 값으로 낸다(이번: 클립당 3~25로 도구마다 다름) |

배운 점:
- 어색함의 원인은 생성기보다 **자세를 누가 정하느냐**였다. 박자와 관절을 표로 먼저 정하고 그림 모델에는 "그 자세로 그리기"만 시킨다.
- 흔들리면 안 되는 것(얼굴, 상체, 디딘 발)은 생성에 맡기지 않고 원본 픽셀을 정수 칸으로 옮긴다. 생성에 맡기는 것은 팔·다리의 모양뿐이다.
- 프레임마다 따로 생성한 부위는 폭과 무늬가 흔들린다. 한 프레임의 조각을 다른 프레임에 재사용하는 쪽이 낫다.
- 공격의 힘은 프레임 수가 아니라 시간 배분(준비 길게·타격 짧게), 몸의 앞뒤 이동, 분리된 궤적 효과에서 나온다.
- 틀 재생을 먼저 본다. 틀 단계에서 어색한 것은 그림 단계에서 고쳐지지 않는다.
- 시험은 "가장 나았던 지난 결과와 나란히 재생"으로 보여야 판단이 빠르다.
