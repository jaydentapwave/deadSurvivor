## 소스 관리 결정

당장은 폴더 이동·소스 원본 전환을 하지 않는다. 먼저 UnityMigration과 실제 Assets/DeadSurvivor의 C#/JSON/아트 차이를 조사한다. 임시 제안은 UnityMigration을 코드·데이터 저작 원본으로 유지하고 실제 프로젝트를 실행 대상으로 삼는 것이다. 씬·프리팹·임포트 설정의 원본은 실제 Unity 프로젝트이므로 코드 복사만으로 전체 백업이 된다고 보지 않는다. 전체 프로젝트 추적 위치는 비교 후 결정기록에 명시한다.

sync.py는 현재 Runtime/Editor 직속 C#을 복사하므로 루트의 InteractionCheck.cs 및 별도 아트 같은 항목을 명시적인 매니페스트로 다뤄야 한다. 폴더를 일괄 복사하는 방식으로 해결하지 않는다.

## 정리 작업과 게임 개발의 경계

하네스를 정리하면서 32종 아이템이나 새로운 회복 규칙을 몰래 구현하지 않는다. 현재 회귀 검사를 먼저 안정화한 뒤, 기능 구현 단위로 새 기획 검사와 코드를 함께 변경한다. 옛 규칙 검사를 삭제해 단순히 통과시키지 않는다.

후속 개발 순서: 데이터 모델/장비 효과 → 주무기와 직업 전환 → 사제 공유 및 생사 처리 → 32종 데이터/모양 → 비교·추천 UI → 웨이브 시간과 측정 → 진형 실험. 각 단계마다 기획·코드·검증·증거를 같이 갱신한다.

## 최종 완료 조건

- 문서에 현재 구현과 다음 계획이 구분되고 주요 규칙마다 원본 문서가 하나다.
- 코드/씬/데이터 원본과 반영 경로가 명확하고 충돌을 덮어쓰지 않는다.
- 하나의 로컬 진입점으로 필요한 검사를 실행하며 누락/실패/타임아웃을 식별한다.
- 실제 Unity 컴파일·실행·입력 확인과 소스 지문이 연결된다.
- 개인 프로젝트 폴더 외 문서 서비스·회사 저장소에 새 기록을 만들지 않는다.
