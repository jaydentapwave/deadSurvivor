# 맵 하네스 실행·판정 경계 선택

- 날짜/상태: 2026-10-31 KST, MAP-HARNESS-009 첫 구현 기준. 설계 검토 통과, 실제 구현/실행은 NOT_RUN.
- 문제: 기존 동기 Simulate 실험만으로는 실제 프레임/장치 입력을 증명하지 못하며, 게임의 충돌 성공 flag만 읽으면 같은 결함을 놓칠 수 있다.
- 대안: 기존 반복 실험을 그대로 확장 / 공유 프레임 진입점과 입력 소유권을 만들기. 게임 C# 판정 재사용 / 저장된 원자료를 독립 Python 기하로 판정하기.
- 선택: DSGame 단일 상태 소유권과 공유 명령/이동 경로를 유지하고, FIXED_REPLAY와 DEVICE_SMOKE를 분리하여 둘 다 인수한다. 별도 Python oracle과 분석 정답·실패 주입으로 교차 확인한다. 사용자의 기존 게임 인스턴스 대신 소유한 격리 씬/인스턴스를 사용한다.
- 첫 이동 알고리즘: 안전 alpha의 단조성을 가정하지 않는 257개 유한 후보 탐색. 연속 최적 해/성능은 보장하지 않으며 정체·조작감·실제 성능 실패 시 새 개정으로 바꾼다.
- 호환성: LegacyNoMap은 기존 게임/회귀를 보존한다. MapRequired는 누락 자료를 차단한다. 기존 공개 동기 명령과 새 UI 명령 큐의 관계는 [구현 설계](../design/map-harness-implementation.md)에 고정한다.
- 검증/재검토: [독립 검토 기록](../reviews/map-harness-009-review.md). 실제 입력/복구/정확성 조건을 만족하지 못하면 구현 완료로 보지 않는다. schema/solver/oracle/환경이 달라지면 영향 증거를 새로 만든다.
