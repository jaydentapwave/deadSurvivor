# DQ 캐릭터 적용 — 이번 단계에서 반영한 검증 절차

8단계 회고의 갱신 후보를 이 작업의 로컬 절차로 반영한다. 승인된 `characters-brief.md`와 수용 기준은 변경하지 않는다. 실행 당시 기록은 `characters-verification.md`, 최종 상태와 이어 받을 열린 지적은 `.director/outbox/20261123-night-1to6-8-r2.md`가 원본이다.

1. **대상 에디터와 저장 상태**: `python3 -B tools/editor_ready.py "$PWD"`로 대상 경로·6000.4.3f1을 확인한다. 명령 직전 active scene의 dirty 여부를 읽고 이행 메뉴가 `SaveOpenScenes()`를 마치게 한다. 다른 프로세스의 창을 이 프로젝트 차단 원인으로 추정하지 않는다. unrelated dirty scene은 저장하지 않는다.
2. **첫 임포트부터 대조**: slice 좌표는 TextureImporter의 원본 텍스처 크기에서 계산한다. 첫 임포트 직후 실제 sprite PPU·발 피벗·Point·종당 texture를 확인한 뒤 메뉴2회 동일·주입 실패 복구를 비교한다. 두 번째 실행 이후만 안정적인 결과를 첫 실행 성공으로 취급하지 않는다.
3. **표시 시계와 수명**: 실제 공격 snapshot→LateTick 적용→대상 Main 카메라 렌더 후 소비를 확인한다. SceneView·추가 카메라·미렌더·여러 Step/방향·동시 무기·같은 Step 재시작을 실제 Main fixture에서 확인한다. 소비/합성/정리는 공격별 id·Step·방향·batch·적용 id·사유를 보존한다. 몬스터 phase 시간은 모델 countdown에서 받고, pause·배속·새 view·동일 캐릭터 새 판·사망/clear/재시작/Dispose를 함께 확인한다.
4. **시험 fixture도 계약 준수**: EnterPlayMode 이전에 만든 캡처 지역 변수를 도메인 재로드 뒤 복원한다고 가정하지 않는다. 전환 뒤 별도 코루틴에서 fixture를 만든다. 두 무기는 실제 BagService로 두 슬롯을 배치한다. 잘못된 fixture의 오류 로그를 LogAssert 허용으로 숨기지 않는다.
5. **캡처의 노출 확인**: 이웃 frame 번호가 다르다는 사실과 몸이 실제로 보인다는 사실을 모두 확인한다. 등장 효과/나무/앞열에 가린 첫 장은 후속 노출 장·횡대형으로 보완한다. 정확한4배 자르기는 sheet.py로 배치하고 본 경로·SHA256·가림 한계를 기록한다. 전체 수천 장을 직접 열었다고 주장하지 않는다.
6. **승인본과 실행 기록 분리**: 승인 파일은 승인 커밋 df10136 기준 불변을 검사한다. 코드 수정 확인 base와 구분한다. 사용자 승인 예외와 결과·현재 상태는 별도 변경 기록/핸드오프에 쓴다. 승인본으로 복구한 diff를 없애려고 미승인 문구를 되살리지 않는다.

검사 비용은 역할로 나눈다. 빠른 계산 시험과 실제 Main 경계 시험은 서로 대체하지 않는다. 단계 기본 판정 경로1회와 메뉴 검사는 유지하고, 이미 통과한 전체 경로·전체 EditMode를 경계 수정마다 중복 실행하지 않는다. 수정이 닿는 시험만 다시 돌리고 이전 결과의 소스 버전과 범위를 명시한다. 이번에 삭제한 검사·낮춘 문턱은 없으며, 범위 밖 실패와 독립 재실행 한계는 최종 핸드오프에 남긴다.
