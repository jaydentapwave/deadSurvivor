# 11단계 T3 설계 브리핑 — 보이는 언덕과 원경 (L2: 지형 grid의 소유·DI 경로 변경)

- 작성: 2026-11-23, Claude(단계 세션). 지시: `.director/outbox` 11단계 지시문 T3.
- 디렉터 결정(사용자 "진행해줘"): **게임 판정 좌표·전투·이동·스폰 로직은 평면 그대로.** 굴곡은 보이는 쪽에만. 대원·몬스터·투사체·효과·발밑 그림자·예고 라인·소품·나무·물가가 **같은 함수**로 보이는 높이를 따른다. 판정 높이 grid는 바꾸지 않는다.

## 1. 지금 구조 (코드 확인)

- `GameSceneLifetimeScope`가 `Data/Field/field_height.json`(1m 칸, 73×73, -3~+23cm)을 `TerrainHeightGrid` 하나로 등록한다.
- 이 grid를 쓰는 곳:
  - **판정·이동 쪽(바꾸면 안 되는 곳)**: `WorldPresenter`가 `ViewRulesData.SetProjection(frame, scale, _terrain)`(→ `PartyMoveService.Step`의 이동 입력 방향 `InputDirection(world, input, Normal(terrain))`), `MonsterService.SetPlacementProjection(..., _terrain, ...)`(→ `MonsterSpawnService`의 화면 가장자리 스폰 투영), 카메라 초점 `_rig.SetFocus(FloorToWorld(center, scale, _terrain))`.
  - **보이는 쪽**: `WorldPresenter`(지형 메시 `FieldView.BuildLandscape`, 대원·몬스터 발 위치 `FloorToWorldSnapped`·`SetGround`·`SetTerrain`·`ApplyProjection`, `_HD2DActorDepthBias`), `CombatWorldPresenter`(투사체), `EnemyShotPresenter`, `DamageNumberPresenter`, `MonsterHpBarPresenter`, `AmbientEffectsPresenter`, `FirstExpeditionPresenter`(표지 위치). 이들 아래 `DQBlobShadow`·`UprightContactShadow`·`ConformedDecal`(예고 라인)·`ProjectileView`·`BurstView`·소품 배치(`FieldView`: `Sample`/`MinUnder`)가 모두 `TerrainHeightMath.Sample(grid, x, z)` 하나로 높이를 얻는다.
- 비평면 grid 경로(`_TERRAIN_HEIGHT` 키워드, 둑 메시 휨, 렌더 큐)는 이미 켜져 있다(지금 grid가 둑 때문에 평면이 아님).

## 2. 바꾸는 것

1. **보이는 grid 하나를 새로 만든다**: `MeadowHillMath.Build(TerrainHeightGrid judgment, FieldLayoutData layout)` → `judgment` 높이 + 언덕 함수 `h(x,z)`를 같은 칸(1m)에 더한 새 `TerrainHeightGrid`(불변, mm). 순수 함수(Features/Field/Utils), EditMode 시험.
   - `h = A · (값 잡음 2옥타브, 파장 약 14m·6m) · mask(x,z)`, A ≈ 0.45m, 목표 최대 경사 ≤ 0.2(지금 배경 이행의 검사 문턱과 같은 값. `TerrainHeightMath.ActorDepthBias`는 경사가 tan 18° = 0.325에 가까워지면 발산하므로 그보다 충분히 낮게).
   - `mask`: 물(`layout.water` 점)과 다리·천막 배치(`layout.placements`의 group `bridge`/`tent`)에서 3m 안은 0, 9m 밖은 1, 사이는 smoothstep. 물가·다리·천막 자리는 판정 grid 그대로라 지금 모습이 유지된다.
   - 판정 grid 파일(`field_height.json`)은 바꾸지 않는다.
2. **DI 경로**: `TerrainHeightGrid` 등록을 **보이는 grid**로 바꾸고, 판정 grid는 새 감싸개 `JudgmentTerrain`(속성 `Grid` 하나)으로 따로 등록한다. 보이는 쪽 6개 Presenter는 고치지 않고 자동으로 보이는 grid를 받는다. `WorldPresenter`만 `JudgmentTerrain`을 더 받아 **이동 투영(`SetProjection`)·스폰 투영(`SetPlacementProjection`)·카메라 초점**에 판정 grid를 쓴다. 나머지(지형 메시·발 위치·깊이 바이어스)는 보이는 grid.
   - 카메라 초점을 판정 grid로 두는 이유: 언덕을 넘을 때 카메라가 위아래로 출렁이지 않게. 대원은 언덕 위에서 화면에서 조금 올라간다(보이는 높이).
3. **빛**: 바닥 재질의 `_TerrainLightSlope`(지금 8, 낮은 둑을 위한 과장)는 실제 언덕 경사 0.2에서 너무 세므로 바닥 재질만 낮춘다(값은 캡처로 정함, 배경 이행 메뉴에서). `_MeadowSlope`(빛만 바꾸는 가짜 굴곡)는 그대로 둔다.
4. **원경**: 카메라(18°, 세로 화각 20°)의 화면 맨 위는 수평선 아래 8°(약 77m 바닥)라 실제 거리의 산은 화면에 들어오지 않는다. 그래서 **카메라에 붙은 먼 배경판** 하나를 둔다: 카메라 앞 약 70m(지금 화면 위쪽 안개 띠 자리)에 세운 판, 불투명·깊이 씀(가까운 숲·바닥이 앞을 가린다), 그림은 하늘·먼 산 능선·바다 띠·대기 원근(Codex 이미지 생성, 유료 아님, 관찰 문서의 말로만 프롬프트). 가로로 이어지는 그림이고, 셰이더가 카메라 x 이동의 일부(약 0.05배)만큼 그림을 밀어 아주 먼 것처럼 천천히 흐르게 한다. 장면 변경은 이행 메뉴로.

## 3. 바뀌지 않아야 하는 것

- 판정·전투·이동·스폰 수치와 결과: `PartyMoveService`·`MonsterSpawnService`가 받는 grid는 지금과 같은 판정 grid. `tools/playable.py` 판정 경로 8/8.
- `field_height.json`, 진형·스폰 데이터.
- 기존 스프라이트 효과(번쩍임·페이드·가림 투명), 예고 라인 24/24.

## 4. 위험과 확인

| 위험 | 확인 |
|---|---|
| 보이는 쪽인데 판정 grid를 계속 쓰는 곳이 남아 떠 있거나 묻힘 | 언덕 넘는 이동 연속 캡처 6장 이상 + 전투 캡처(투사체·예고 라인·피해 숫자) |
| 판정 쪽이 보이는 grid를 받아 이동·스폰이 바뀜 | `WorldPresenter`의 세 호출을 코드로 확인, 판정 경로 전체 1회 |
| 경사로 깊이 바이어스가 커져 대원이 앞 소품 위로 그려짐 | MaxSlope 시험(≤0.2), 캡처 |
| 물가·다리·천막이 어긋남 | mask 시험(물 점 3m 안 높이 = 판정 높이), 캡처 |
| 원경 판이 카메라 이동 때 미끄러져 보임 | 이동 연속 캡처 |

## 5. 하지 않는 것

판정 grid·스폰·이동 수치 변경, 카메라 각도, 나무·꽃·깃발 모델, 유료 생성, 성능 측정.
