# 14단계 T1 설계 브리핑 — 높은 언덕과 정점별 깊이 바이어스 (L2: 렌더 깊이 규칙 변경)

- 작성: 2026-11-23, Claude(단계 세션). 지시: 디렉터 14단계 지시문 T1("깊이 바이어스를 전역값이 아닌 방식으로 바꿔 능선 높낮이를 2m 안팎까지").
- 앞 설계: `11-언덕-원경-설계.md`(보이는 grid / 판정 grid 분리, DR-01~04). 그 구조는 그대로 둔다.

## 1. 지금 구조와 막힌 곳 (코드 확인)

- `WorldPresenter.Initialize`가 `Shader.SetGlobalFloat("_HD2DActorDepthBias", TerrainHeightMath.ActorDepthBias(_terrain, .625, sinTilt))`를 한 번 넣는다.
  값 = `MaxSlope·0.625 / (sinθ − MaxSlope·cosθ) + .018`(θ = 18°). 보이는 grid **전체의 최대 경사**로 정해지는 전역값이다.
- `HD2D_SpriteLit.shader`(대원·몬스터·투사체·효과 스프라이트, UniversalForward·DepthOnly 패스)가 이 값만큼 모든 정점을 뷰 z에서 카메라 쪽으로 당긴다.
  스프라이트는 카메라를 향해 18° 기운 판(`upright.localRotation = Euler(18,0,0)`)이고 바닥 아래 꼭짓점이 옆 경사 때문에 땅에 묻히는 것을 가리기 위한 값이다.
- 그래서 경사를 올리면(0.12 → 0.3) 바이어스가 0.38m → 수 m로 커져, 모든 스프라이트가 그 거리 안의 앞 소품·능선 위로 그려진다. 11단계가 경사 상한 0.12(언덕 0.69m)에 머문 이유.

## 2. 바꾸는 것

1. **정점별 바이어스(전역값 삭제)**: 보이는 grid의 높이를 전역 텍스처 `_HD2DTerrainHeight`(RFloat, grid 크기 73×73, 점 읽기)와
   `_HD2DTerrainGrid`(originX, originZ, 1/cell, 켜짐)로 올린다(`WorldPresenter.Initialize`, 새 순수 도우미 `TerrainHeightTexture`가 grid → Texture2D, Dispose에서 파괴).
   스프라이트 정점 셰이더는 정점의 월드 (x, z)에서 `TerrainHeightMath.Sample`과 **같은 삼각형 분할**로 높이 h와 그 삼각형의 기울기 (gx, gz)를 읽는다.
   - 묻힌 깊이 d = h − y(정점). d ≤ 0이면 바이어스 0(그 정점은 땅 위 — 앞 능선·소품이 정상 깊이로 가린다).
   - d > 0이면 그 정점에서 카메라 쪽으로 나가는 시선이 땅을 빠져나오는 거리 t = d / max(sinθ + gz·cosθ, 0.05) + 0.018, 상한 1.2m. 이 t만큼 뷰 z를 당긴다.
   - 근거: 시선을 카메라 쪽으로 s만큼 되짚으면 시선 높이는 s·sinθ 오르고 땅은 −gz·s·cosθ 오른다(국소 평면). 필요한 바이어스는 (정점 x, y)에 대해 볼록(max(0, 아핀)/상수)이라, 꼭짓점 값의 선형 보간이 삼각형 안 모든 점의 필요값 이상이다(스프라이트 사각형·타이트 메시 모두).
   - 결과: 평지·발이 땅 위인 정점은 바이어스 0. 옆 경사에 선 대원의 아래 모서리만 국소적으로 당겨진다. 앞 소품과의 순서 역전은 그 대원의 아래 모서리 근처로 줄어든다.
   - 이전 전역 경로(`_HD2DActorDepthBias`, `TerrainHeightMath.ActorDepthBias`)는 지운다. 시험 `TerrainDataContractTests`·`TerrainHeightMathTests`의 해당 단정은 새 계약(셰이더가 `_HD2DTerrainHeight`를 읽고 전역 바이어스가 없음, 새 도우미의 순수 계산)으로 바꾼다.
   - 그림자 패스(`ShadowVertex`)는 지금처럼 바이어스를 쓰지 않는다.
2. **언덕을 높게**: `MeadowHillMath` — 진폭 0.6 → 1.3, 큰 파장 14 → 16m, 경사 상한 `MaxSlope` 0.12 → **0.30**(tan 18° = 0.325 아래: 카메라에서 보이는 뒷면은 남되 0.3/0.325 → 뒷면 6m가 화면에서 약 0.5m 높이로 눌려, 능선 뒤 풀밭이 능선에 가려 보이는 모양이 된다).
   보호 구역(물·다리·천막, 칸 대각선 여유)과 판정 grid는 그대로. 목표 높낮이 1.6~2.2m.
   - 0.325보다 낮게 두는 이유: `TerrainHeightMath.SnapOnTerrain`(대원·몬스터 발 화면 칸 맞춤)의 뉴턴 분모 sinθ + gz·cosθ가 0을 지나면 수렴·정렬이 깨져 예외가 날 수 있다. 0.30에서 분모 ≥ 0.024 — 단조 구간이라 기존 뉴턴이 그대로 수렴한다(시험으로 확인).
3. **빛·대기**: 바닥 `_TerrainLightSlope` 3은 실제 경사가 커졌으므로 캡처로 다시 정한다(1~2 예상, 해 쪽/반대쪽 밝기 차는 실제 법선에서 나오게). 대기색: `DQMainSurface`의 거리 안개가 초점 +8m~+48m 하드코딩 → `_DQLightFocus.y/.z`(이미 `DQSceneLighting`이 8, 48을 넣음)를 읽게 하고 값을 4, 36 근처로 당겨 개울 너머가 옅어지게 한다(값은 캡처로 정함).

## 3. 바뀌지 않아야 하는 것

- 판정 grid·이동 입력·스폰 투영·카메라 초점(`JudgmentTerrain`), 전투 수치, `field_height.json`.
- 발 위치·그림자·예고 라인·소품 배치는 지금처럼 보이는 grid의 `Sample`/`MinUnder`를 따른다(코드 경로 변경 없음, 값만 높아짐).
- 가림 투명(`_Fade`)과 예고 라인 24/24.

## 4. 위험과 확인

| 위험 | 확인 |
|---|---|
| 정점 셰이더의 높이 읽기가 C#의 삼각형 분할과 달라 발이 묻히거나 바이어스가 모자람 | 셰이더 함수와 같은 식의 C# 도우미(`TerrainHeightTexture.Bias`)를 시험(평지 0, 옆 경사, 앞 경사, 상한), 언덕 위 대원 확대 캡처 |
| 대원이 능선 뒤에서 앞 능선을 뚫고 보임 / 반대로 발이 잘림 | 언덕 넘는 이동 연속 6장 |
| 발 칸 맞춤(`SnapOnTerrain`) 예외 | 경사 0.30 grid에서 전 칸 표본 시험, 판정 경로 전체 1회 |
| 소품이 경사에서 뜨거나 묻힘(`MinUnder`) | 캡처 |
| 텍스처 읽기 비용 | 스프라이트 정점당 점 읽기 3번. 성능 측정은 범위 밖(마지막 단계) |

## 5. 하지 않는 것

판정 grid·이동 규칙(연못 위 걷기), 카메라 각도, 캐릭터 그림, 성능 측정, 원경 이행 메뉴.

## 7. 구현에서 정한 최종 값 (마감 리뷰 반영, 2026-11-23)

- 스프라이트 바이어스: 아래 변 표본 0.1m 간격(2~32점), 시선 걷기 t = 1.5·k/19(k = 0..19, 끝점 포함), 묻힌 표본이 있을 때만 + 0.08m, 하나라도 1.5m 안에 못 나오면 0(가림 우선), 모두 땅 위면 0.
- 들림: 예고 라인 간격 0.125m·들림 0.03m(대각선 최대 묻힘 0.0265 대응), 투사체 그림자 0.10m(골 ±0.30 × 반폭 0.15 = 0.09 대응).
- 언덕: 옆·카메라를 향한 경사 ≤ 0.30, 카메라에서 멀어지며 내려가는 경사 ≤ 0.80(`SlopeRatio`) — 능선 뒷면이 tan 18°보다 가파르게 할 수 있게 했다(실제 가림은 판독·확대 캡처로 미확인). 발 칸 맞춤(`SnapOnTerrain`)은 게임 경로가 쓰지 않음(DR-05). 능선 z≈22, 앞 폭 5.5m·뒤 폭 1.8m·높이 1.3m, 국소 낮춤 최대 32회.
- 높낮이: 출시 지형 ReliefWithin(32) = 1.375m. 목표 1.6~2.2m **미달** — 개울 보호 구역(z≈16까지)과 북쪽 경계(z≈24~32) 사이 폭에서 앞면 경사 0.30을 지키면 이 높이가 한계. 시험 하한은 1.35m(퇴행 방지)로 두고 미달은 열린 질문.
