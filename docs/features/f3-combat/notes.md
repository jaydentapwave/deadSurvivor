# F3 기획서 근거 메모

[plan.md](plan.md)의 긴 근거. 2026-11-15에 예전 판 파일을 직접 읽어 확인한 것(모두 `Assets/DeadSurvivor/Runtime/`, 읽기 전용).

## 계산식과 발동 (B절)
- 발동 한 칸: `DSGame.EquipmentCombat.cs` `TickAction`(72행~). 쿨 −= dt → 0보다 크면 끝 → 대상 없으면 끝(쿨은 그대로) → 쿨 = 마지막 주기 = 간격 ÷ (1 + 가속), 발동 표시 0.18초.
- 사거리 × 42 × (1 + 사거리 증가)와 피해: 79행, `EquipmentRules.cs` `WeaponPower`(130행) — 회복 방식은 피해 × 등급 배수만, 그 밖에는 × 공격 배수 × (1 + 공격 증가).
- 근접 50°·휩쓸기 90°: 101~103행(`Vector2.Angle(direction, e.pos - c.pos) <= angle`, 반각). 연쇄: 110행~, 3 + chain 번, 다음 적 150 안. 투사체: 129행(속도 440, 관통, 폭발 반경 75 × (1 + radius)), 갈래 각도 (n − extraShots × 0.5) × 0.12.
- 투사체 이동·명중: `DSGame.Combat.cs` `Simulate`의 투사체 부분(374행 폭발: 목표까지 < 걸음 + 5 또는 사거리 끝, 394행 관통: 맞힌 수 > pierce면 사라짐). 명중 판정은 이동 선분과 적 중심의 거리 < 적 반지름.
- 회복 대상: `TickAction` 회복 분기 — 사거리 안, 살아 있고 HP < 최대 HP, HP 비율 오름차순. 단일은 첫 동료, 범위는 모두.

## 능력치 (B3)
- `EquipmentRules.cs` `Stats`(69행~): 모든 아이템의 기본 효과 × 등급 배수를 더하고, `BonusApplies`(27행)가 참인 추가 효과를 더한다. `Scoped`(26행) = `requiresAdjacent || targetMode 있음`. 조건 없는 추가 효과는 늘 참.
- 마무리: 방어 = min(0.8, 캐릭터 def + 합)(79행), 가속 = min(1, 합), HP = 캐릭터 hp + 합, 보호막 상한 = max(shield, startShield). `pierce`·`extraShots`·`chain`은 정수 최대값이고 등급 배수를 곱하지 않는다(`BonusValue`).
- 대상 방식 `attack` = 회복 두 방식을 뺀 발동 아이템(`MatchesMode`).

## 지속 효과 (B6)
- 자기 회복: `TickEquipment` 22~27행. 주기 3 ÷ (1 + 가속), 시계 + 1e-4 ≥ 주기면 회복(같은 걸음에 여러 번 가능).
- 나눔: `EquipmentRules.Provider`(138행) — 받는 대원이 살아 있고, 다른 살아 있는 대원 중 나눔 효과가 켜진 대원의 회복 ÷ 주기가 가장 큰 쪽. `DSGame.Stats.cs` `RefreshProviders` — 제공자·주기가 바뀌면 시계 0.
- 파동: 44행~, 아이템 칸 쿨이 효과 간격(3)마다, 반경 100 안 적에게 bonusValue × 등급 배수.
- 보호막: 62행, 시계 ≥ 8이면 시계 %= 8, 보호막 = max(보호막, 채움 값). 채움 값 0이면 시계 0. 시작 보호막: `DSGame.Run.cs` `NextWave` 89행.

## 피해·쓰러짐·부활 (B4, E절)
- 받는 피해: `DSGame.Combat.cs` `Damage`(9행~) — 피해 × (1 − 방어) 뒤 보호막 흡수.
- 쓰러진 대원: `Simulate`의 대원 반복에서 `hp <= 0`이면 `TickEquipment`를 부르지 않는다(188행 부근) → 쿨 멈춤.
- 장비 잠금: `EquipmentRules.cs` 185·214·226행 "사망자 장비 잠금"(놓기·합성·해제 모두 거절).
- 부활: `DSGame.Inventory.cs` `Revive`(48행~) — 정비에서만, 쓰러진 대원만, HP = 최대 HP, 시계·보호막 0, 아이템 쿨·마지막 주기·발동 표시 0(61행). 비용·횟수 검사 없음.

## 버린 것
- 새 아이템 첫 쿨 난수 0~0.2초(`DSGame.Run.cs` 12행 `MakeItem`): 전리품 난수(`LootRng`)를 전투 상태에 섞는다. 새 판은 쿨 0으로 시작해 결정성을 단순하게 둔다(CA4).
- `MapLine` 시야 검사: 3D 맵 장애물용. 2D 첫 판 들판에는 큰 장애물이 없다(게임 기획서 A10).
- 상태 문자열(`"활성"`, `"더 강한 효과 적용 중"` 등): 정비 화면 설명(F5)의 표시 문구다. 계산은 B3 규칙으로 충분하다.

## 하단 목록 상태 (F절)
- `DSUI.BattleItems.cs` 16행 `BattleItemStatus`: 쓰러짐 → "비활성", 쿨 없음 → "지속 효과", 발동 표시 중 → "발동!", 쿨 > 0 → "n.n초", 그 밖 → "준비". 쿨 있는 칸 = 발동 방식이 있거나 추가 효과가 `pulse`(`DSWorld.Equipment.cs` `HasItemCooldown`).
- 막대 = 남은 쿨 ÷ 마지막 주기(없으면 지금 주기), 0~1(`ItemCooldownRemaining`).

## 수치 출처
- 아이템 32종: `PrototypeData.json` `items`(2026-11-15 추출). plan.md C절의 두 표가 전부다. `effectInterval`·`effectRadius`는 예전 파일에서 모든 아이템에 8·100(파동·나눔 계열 3)이 들어 있었지만 실제로 쓰는 곳은 파동뿐이라 `pulse` 아이템에만 둔다. 보호막 주기 8은 예전 코드의 상수라 `combat_rules.json`의 `shieldPeriod`로 옮겼다.
- 캐릭터 4명: F1 데이터 스키마 그대로(게임 기획서 notes.md 예전 값 표와 같은 값).
- 등급 배수(일반 1, 고급 1.4, 희귀 2, 영웅 3, 전설 4.5)는 합성(S5)이 만드는 값이라 F5가 데이터로 둔다. 이 기능은 배수 자리(B2)만 둔다.

## 흐름 경로의 시드·배율 (H절)
- `<부활 시드>`·`<부활 배율>`: F1 고정 간격 시뮬레이션은 같은 시드면 결과가 같다(F1 AC11). 그래서 "웨이브 1 중 1~3명 쓰러짐, 나머지 생존"인 값을 한 번 찾으면 그대로 재현된다. F4가 몬스터를 바꾸면 결과가 달라지므로 합칠 때 이 두 값만 다시 고른다.
