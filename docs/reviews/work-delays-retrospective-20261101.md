## 1. 핵심 결론

시간이 늘어난 원인은 하나의 게임 버그나 하나의 장시간 테스트가 아니었다. **검증 도구 구현 범위가 계속 확대되고, 그 도구의 오판·초기화 오류를 수정하면서 재실행했고, 단계별 전체 회귀와 증거 갱신까지 누적된 것**이 주된 흐름이다. 대표 구역 미술도 여러 차례 시각 수정이 필요했다.

필요한 검증 기반을 만든 성과는 있지만, 실제 전체 맵 실행을 연결하기 전에 진단·반례·봉인 체계를 세분화하면서 사용자에게 보이는 완성도보다 작업량이 크게 늘어났다. 이는 에이전트의 범위 관리와 진행 설명이 부족했던 부분이다. 모든 지연을 프로젝트 규칙이나 Unity 탓으로 돌릴 수 없다.

사용자가 말한 **“2시간 반”은 사용자 체감/보고 시간**이다. 현재 자료만으로 그 전체를 구현·검사·리뷰·대기 시간으로 정확히 배분할 수 없고, 단일 프로세스가 2시간 반 동안 멈춰 있었다고 단정할 근거도 없다. 아래의 시간은 시작·종료 시각이 있는 개별 실행에만 한정한다.

## 5. 유지할 필요가 있는 검증과 줄여야 할 낭비

유지할 것: 실제 게임 결함을 드러낸 경계 검사, 변경 부위의 컴파일·핵심 동작·실제 입력/프레임, 소유 자원 복구, 필요한 최종 회귀, 독립 검토와 필수 gate. 특히 실패 기록을 남기고 과거 성공을 현재 성공으로 재사용하지 않는 원칙은 유지한다.

줄일 것: 변경 없는 topology 전수 재계산, 같은 환경 오류가 남은 전체 Python 반복, 구현 경로 연결 전에 별도 진단·반례 행렬을 계속 확대하는 작업, 사용자에게 의사결정이나 진행 판단에 도움이 되지 않는 내부 ID/긴 로그 나열. 필수 검증의 면제나 baseline 완화로 해결하지 않는다.

사용자 최신 지시는 **“반드시 필요한 것만 검증”**이다. 032에서는 핵심9사례와 관련 Python42개, 필요한 최종 회귀/local/gate만 실행하고 기존030 전체·topology12·전체 Python suite를 반복하지 않았다.

## 6. 이후 작업에 적용할 개선 방향

다음은 이번 회고의 개선 제안이다. 워크플로우 원본이나 hook을 이 문서만으로 변경한 것은 아니다.

1. 작업 시작 시 구현 산출물·완료 조건·최소 검사 목록을 정하고, 검사를 늘릴 때는 실제 발견한 결함/요구와 연결한다.
2. 작은 진단을 추가하는 것보다 **요청→실제 실행→상태 기록→독립 판정→복구**의 미완료 연결을 먼저 끝낸다.
3. JSON 생략값·Unity 객체 ID·float/double 경계 같은 접점은 작은 smoke로 먼저 확인하고 큰 실행을 시작한다.
4. 수정 후에는 실패한 검사와 영향 범위를 먼저 확인한다. 전체 회귀는 안정된 변경 묶음의 필요한 마감 시점에 실행하며, 이후 새 변경/실패가 있으면 그 영향에 따라 다시 판단한다.
5. 같은 환경 차단이 반복되면 새 원인이나 환경 변화가 없는 한 동일 전체 검사를 재실행하지 않는다. 미해결 결과는 BLOCKED로 보존한다.
6. 진행 보고에는 현재 실행 중인 일, 확인한 결과, 남은 구현, 중단/대기 여부를 쓴다. 최종 응답을 실제 백그라운드 실행의 약속으로 표현하지 않는다.
7. 서브에이전트 요청은 “계산 검토 요청/완료”처럼 역할로 설명한다. 내부 메시지 전송을 구현 완료나 Unity 진행으로 표현하지 않는다.
8. 다음 실행부터 runner 실행 시간과 구현/리뷰 대기 구간을 구분해 기록한다. 합산 시 동시 실행 구간을 중복 계산하지 않는다.
9. N2 실제 빌드·성능 시험은 사용자 담당이라는 경계를 유지한다. Editor 검증으로 실제 빌드 인수를 대신하지 않는다.

## 7. 작성 시점 상태와 이번 문서의 검사

032까지의 제한된 기반 구현·핵심 검사·최종 회귀는 완료다. 전체 v1 실행 연결, 활성 full snapshot 연결, 외부 supervisor/FI, 전체 경로와 필수 MC 인수는 남아 있다. [현재 진행](../design/map-full-026-progress.json)을 따른다.

이번 요청은 기록 문서와 진입 링크만 변경한다. 링크·일관성 local 검사와 필수 gate를 실행하며 Unity 컴파일/플레이·전체 Python은 새로 실행하지 않는다. 문서 검사 통과를 게임 실행 성공으로 보고하지 않는다. 검사 보고서는 `output/verification`에 기록한다.

## 8. 후속 적용 — 2026-11-01 운영 규칙 개선

사용자가 이 회고를 바탕으로 워크플로우 개선을 요청해 L1 문서 변경으로 반영했다. 위 1~7절은 회고 작성 당시의 사실·제안으로 보존한다. 이번 브리핑은 [효율 설계의 운영 개선 절](../design/efficiency-013.md), 실행 규칙 원본은 [개발 절차](../workflows/development.md)다.

| 회고의 문제 | 적용한 규칙 |
|---|---|
| 검증 기반을 늘리며 실제 결과가 늦어짐 | 산출물·완료 조건·제외 범위·최소 검사·확대 조건을 시작 전에 적고, 현재 요구를 판정할 수 없는 경우에만 최소 도구 보완 |
| 실제 연결 전 진단/반례 확대 | 소유권·복구 전제 확인 후 작은 실제 경로를 먼저 연결. 접점 오류를 먼저 발견 |
| 리뷰로 완료 조건이 계속 늘어남 | 필수 수정/후속 제안 구분과 근거 요구. 역할별 책임·중복 ID·변경 부분 재검토 |
| 중간 전체 회귀·같은 환경 오류 반복 | 안정된 묶음의 필요한 최종 회귀. 새 원인/조건 변화 없는 동일 전체 재실행 금지, BLOCKED 보존 |
| 진행/종료 혼선·시간 원인 불명 | 사용 가능한 결과·현재 실행·차단/대기·다음 조건 보고. 기존 기록에 단계 시간/재실행 이유를 남김 |
| 문서 검사 중복·오래된 실행 안내 | gate 내부 새 local을 마감 근거로 연결. 폐기된 sync --apply 안내와 고정 과거 캡처 수 정정 |

새 자동화·하네스·게임 코드·씬·gate 정책·baseline·hook·전역 설정을 변경하지 않았다. 기존 미커밋 파일의 이전 작업을 보존한다. 검증 실행/인수 수준을 낮춘 결과가 아니며 전체 N1/N2/N3 상태는 그대로다.

이번 검사 상태와 시각·시작/최종 지문·이번 diff·독립 검토는 [로컬 마감 기록](../../output/workflow-focus-20261101/final-checks.json)에 결합한다. 문서 local/gate와 독립 검토 범위이며 Unity·전체 Python/자산 시험은 NOT_RUN이다. 아직 다음 제작 작업에 적용하기 전이므로 실제 시간/비용 절감 효과는 **미측정**이다.

## 9. 필수 검사 재실행 조건까지 개선 — 034

이후 사용자 요청에 따라 기존 검사 의무 자체를 재검토해 [034](verification-scope-034-review.md)에서 gate를 수정했다. 문서/데이터/H1/MAP007의 변경 의존성과 원자료를 확인해 필요한 검사만 새로 실행하며 무관한 도구 변경으로 Unity를 다시 실행하지 않는다. 계산 내용만 바뀐 경우의 화면 근거 재사용은 좁은 허용 목록에 한정한다. 현재 규칙은 [검증 gate](../workflows/verification-gates.md)를 따른다. 위 §8은 그 이전 문서 운영 개선 기록이다.
