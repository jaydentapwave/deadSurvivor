# 검증 하네스

상태: 문서/데이터/Unity 통합 실행 구현. 명령과 환경 조건은 [검증 절차](검증절차.md).

Tools/Verify/run.py가 단계와 실행 ID·소스 지문·결과를 관리하고 unity_check.py가 지정된 개인 Unity 세션만 제어한다. DSVerification은 게임 규칙을, InteractionCheck는 실제 프레임을 넘기는 UI 입력·시간 측정을 검사한다.

PASS/FAIL/BLOCKED/NOT_RUN을 구분한다. 실패·타임아웃은 성공으로 처리하지 않는다. 입력 결과는 실행별 새 경로에서 완료 신호를 확인한다. 과거 고정 rules.txt를 현재 검사로 재사용하지 않는다. 실행 도중 파일이 바뀌면 source_stability FAIL이다.

Unity는 미저장 씬·기존 플레이·reload 비활성 상태에서 검사를 시작하지 않는다. 소유한 세션만 종료하며 실패 시에도 가능한 설정 복구를 시도한다. 원래 검사 오류를 정리 오류로 덮지 않는다.

현재 자동 검사 범위: 모양/회전/교체/효과/공유/주기/무기발동/웨이브/진형/입력. 기본 난이도 사람 완주, 실제 모바일 성능, 최종 아트, 초기 로딩은 별도다. 세부 경계 사례의 검사 여부는 검증 기록과 코드의 assertion을 근거로 판단한다.

맵 검증은 [010 H1 기초 분석](design/map-harness-h1-foundation.md)만 구현됐고 실제 맵 입력/복구/전체 인수는 미완료다. [011 자산 하네스](design/ai-3d-asset-harness.md)는 생성 작업/파일·후처리·Unity 실측·고정 화면 비교·원자적 채택/등록의 설계다. [012 최소 전송 도구](../Tools/Assets/README.md)는 기존 바위의 작업 기록/재개·처리·실측·격리 화면/복구를 구현했고 전체 자산 인수/등록은 미구현이다. 기존 맵 request v1와 자산 sidecar를 분리하고 G5에서 결과를 연결한다. local/all/gate PASS에 새 자산 AC/AFI 실행이 포함됐다고 보고하지 않는다.
