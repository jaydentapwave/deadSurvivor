# 044 — 현재 형태 프로토타입 본편 (3D 맵 + 2D 캐릭터)

- 상태: 구현 기준
- 규모: L1. 새 본편 장면과 빌드 첫 장면 변경으로 게임의 진입 흐름 구성이 바뀐다. 런타임 코드·데이터 스키마·상태 소유권은 바꾸지 않는 것을 목표로 한다. 구현 중 런타임 코드 변경이 필요해지면 L2로 올리고 설계 검토를 먼저 받는다.
- 사용자 요구(2026-11-02):
  - 3D 캐릭터 탐색을 멈추고 현재 형태(3D 맵 배경 + 2D 스프라이트 캐릭터)로 개발을 이어간다.
  - "모바일 입력까지 작업을 모두 진행"한다. 맵 크기는 지정하지 않았으므로 메인 추천대로 대표 구역에서 시작한다.
  - **정정(2026-11-02, 완료 후):** 첫 항목은 메인의 해석 오류다. 사용자는 Tripo 3D 캐릭터 형태로 이어가길 기대했다([042 검토 정정](../reviews/char-monster-042-review.md)). 이 문서의 흐름·입력·화면 검증은 캐릭터 표현과 무관하게 유효하다. 캐릭터 표현은 후속 작업에서 다시 정한다.
- 완료 조건([프로토타입 범위](프로토타입-범위.md)의 핵심 루프를 새 형태로 실행):
  1. 빌드 첫 장면이 3D 맵 본편이다.
  2. 그 장면에서 로비(최대 4명 선발) → 전투 → 웨이브 종료 → 정비 → 다음 웨이브 → 10웨이브 승리 → 결과 → 재편성 → 재출전이 실제 프레임으로 진행된다.
  3. 전멸하면 패배 → 결과 → 재편성으로 이어진다.
  4. 터치 조이스틱(실제 InputSystem `Touchscreen` 장치 이벤트)으로 파티가 이동한다.
  5. 가로 화면 3개 비율(1280×720, 1560×720, 1024×768)에서 로비·전투·정비·결과 화면을 캡처해 UI 겹침·잘림이 없다.
- 제외 범위:
  - 전체 맵 미술 확장. 대표 구역 밖은 기존 블록아웃 외형이다.
  - 소품 충돌. 038 Tripo 소품은 시각 전용이고, 충돌은 Layout 64개가 소유한다.
  - 최종 아트, 3D 캐릭터, 종료 보상·성장(메타), 실기기 성능·빌드(사용자 담당), 사람 플레이 밸런스(사용자), 맵 하네스 N1 확장.

## 현재 사실 (조사 근거)

- `DSGame`이 로비부터 결과까지 상태 흐름을 소유한다. 장면에 `DSMapSession`이 있으면 맵 명령 큐 경로(`AdvanceNormalMapFrame`)로 돌고, UI 버튼은 `SubmitMapCommand`로 들어간다(StartRun, Pause/Resume, NextWave, Revive, ReturnLobby, ToggleSelection).
- `Map038_TripoPair_r003`은 Map023과 같은 Layout(SHA `bdce2b…`), 배율 4, 55도, 같은 카메라·가림 설정을 쓴다. 다른 점은 시작 위치 (-1140,-1120)와 `CombatEnabled=0`이다.
- 3D 맵 모드의 10웨이브 완주·승패·결과·재시작은 지금까지 실행 검증된 적이 없다(023 기록의 범위 밖).
- 기존 `run.py all`은 `DeadSurvivor.unity`(2D)에서만 돌고, 맵 모드에서는 직접 호출이 거부된다. 그래서 새 장면에는 전용 검증기가 필요하다.
- 터치 조이스틱은 `DSUI`의 MovementInput + `DSPointer`(UI 포인터 이벤트)로 구현돼 있고 맵 모드에서도 같은 UI를 쓴다. 실제 `Touchscreen` 장치로 시험한 기록은 없다.
- 화면 방향은 가로 고정(`defaultScreenOrientation: 4`, 세로 자동 회전 끔).

## 검증 방법

- **흐름:**
  - UI 버튼 `onClick`(실제 `SubmitMapCommand` 경로)으로 출전, 정비, 다음 웨이브, 재편성을 누른다.
  - 각 웨이브는 실제 시뮬레이션을 수 초 돌려 적 생성(`Spawned` 증가)·전투·프레임 진행을 확인한다.
  - 남은 시간은 기존 디버그 명령 `DebugFinish`(키보드 1과 같은 큐 명령)로 넘긴다. 435초 실시간 완주는 자동 검증에서 하지 않고, 사람 플레이로 남긴다.
  - 패배는 전투 중 파티 HP를 0으로 주입해 만든 뒤, 실제 프레임의 전멸 판정 → 결과 → 재편성을 확인한다. 상태 주입이라는 점을 기록한다.
- **터치:** `InputSystem.AddDevice<Touchscreen>()`로 장치를 만들고, MovementInput 영역에 터치 Began → Moved(오른쪽) → Ended 상태 이벤트를 넣는다. 조이스틱 활성, 파티 중심의 이동 방향, 손을 뗀 뒤 멈춤을 확인한다. 끝나면 장치를 제거한다.
- **화면:** 3개 해상도에서 로비·전투·정비·결과를 game view로 캡처하고 직접 본다.
- **부작용:** 시작·끝의 콘솔 오류, 미저장 장면, `git status`(PrototypeFont.asset, Map037 Foliage*.mat)를 확인하고 Play를 종료한 뒤 원래 장면 구성을 복구한다.
- **회귀:** Assets·ProjectSettings 변경으로 gate가 2D 본편의 `run.py all --screens`를 요구한다. 043 Assets 작업이 끝난 뒤 함께 한 번 실행한다.
- **독립 검토:** 메인(Claude)이 구현했으므로 Codex에 맡긴다(AGENTS 공통 선호).

## 알려진 한계 (이번에 고치지 않음)

- **맵 명령 기록 상한:** `MapEventLimit=4096`. 명령마다 기록되고, 넘으면 세션이 멈춘다(`MAP_SESSION_TERMINAL`). 한 판에 수십 건 규모라 연속 수십~백여 판에서 닿을 수 있다. 030/031 검증 기반의 핵심이라 이번에는 바꾸지 않고, 사람 플레이에서 문제가 되면 L2로 다룬다.
- **적 생성:** 시작 위치가 남서쪽 경계에서 약 800 떨어져 있어 일부 각도의 생성이 거부될 수 있다(0.25초 뒤 재시도). 웨이브는 시간으로 끝난다. 실제 웨이브별 생성 수를 기록한다.
- **미술 범위:** 파티가 북쪽으로 이동하거나 그쪽에 적이 생기면 미술 구역 밖(블록아웃 외형)이 보인다.
- **소품:** 충돌이 없어 적·투사체가 관목·석재를 시각적으로 통과한다.
- **터치:** 멀티터치는 `pointerId`를 구분하지 않는다. 실기기 터치는 사용자 담당이다.

## 구현 중 발견과 변경 (2026-11-02)

- **비전투 화면 가장자리에 맵이 보임:**
  - 첫 Play 검증 캡처에서 로비·정비·결과 화면의 오른쪽과 아래 가장자리에 3D 맵이 보였다.
  - 원인: 비전투 페이지는 1600×900 고정 크기 배경(`DSUI` `Box(..., W, H)`, 위쪽 가운데 기준)이라 화면비나 안전 영역이 다르면 캔버스 일부가 덮이지 않는다. 2D 본편은 이때 카메라 배경을 같은 색(`#0d1317`, `DSWorld.cs:147`)으로 지워 보이지 않았다.
  - 변경: `DSUI.Init`에서 캔버스 전체를 덮는 `PageBackdrop`(같은 색, 레이캐스트 없음)을 안전 영역 루트 뒤에 두고, 페이지를 만들 때 전투가 아닌 상태에서만 켠다.
  - 2D 화면은 같은 색이라 시각 변화가 없다. 전투 화면은 꺼져 있다.
- **규모 판단:** 브리핑의 "런타임 코드 변경이 필요해지면 L2"는 보수적으로 적은 조건이었다. 이번 변경은 UI 배치만 바꾸고 상태 소유권·데이터 스키마·도메인 경계를 바꾸지 않으므로 [개발 절차](../workflows/development.md) 기준 L1로 유지한다. 이 판단도 구현 후 독립 검토 대상에 포함한다. 런타임 변경이 생겼으므로 2D 본편의 `run.py all --screens` 회귀가 필수다.
- **검증기 보강:** 비전투 캡처의 바깥 2px 테두리가 `#0d1317`인지 자동 검사한다(`edge_check`). 수정 전 캡처 12장에서 모두 FAIL을 확인했다.
- **편집기 입력 범위:** 무인 CLI 실행에서는 편집기 포커스가 없어 Play가 멈추고(프레임 1) 터치 장치가 비활성화되거나 이벤트가 버려졌다. Play 동안 `editor.playmode set_run_in_background`를 켰다가 끄고, 터치 단계 동안 InputSettings 복제본(`AllDeviceInputAlwaysGoesToGameView`, `IgnoreFocus`)을 썼다가 원래 객체로 되돌린다. 편집기 전용 검증 조건이며 게임·빌드 설정은 바꾸지 않는다. InputSettings 에셋은 없다.
- **명령 출처:** 맵 명령 큐가 허용하는 시험 출처 `TEST`를 쓴다(허용 목록: UI, KEYBOARD, DEVICE_SMOKE, TEST).
