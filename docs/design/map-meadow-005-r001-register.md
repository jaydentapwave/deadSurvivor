# MAP-MEADOW-005 / r001 — 등록부 읽기와 시험 기준

2026-10-30 KST. 검토중 / 게임 적용 미구현. [작업 묶음](map-meadow-005-r001-package.md).

## 이번 등록 범위

주요 시각 군집 64개, 외곽 조사 영역 4개, 원형 잔해 상위 묶음 1개를 등록했다. CSV의 69행을 장애물69개로 세지 않는다. 64개에도 경계에 부착된 군집이 포함되므로 독립된 내부 섬64개라는 뜻이 아니다. 객체 등록 단위는 원본의 공식 객체 수가 아니라 이번 분석에서 사용한 시각 군집 단위다.

통로 후보 17개와 P 시작 후보를 연결했다. 통로는 지도에서 보이는 길과 우리가 시험하려는 빈 공간을 함께 포함한다. 실측 충돌이나 도달 가능성을 확인한 결과가 아니다. 군집이 보이지 않는 어두운 외곽·작은 잔돌·꽃·식생 세부는 전수 등록 대상에서 제외했다. 큰 군집의 육안 위치 등록 단계로, G1의 전체 정밀 대응 완료는 아니다.

## 좌표 해석

- REF-VM-001 원본 전체 1195×1110, 자르기 없음. x/y는 왼쪽 위 기준 픽셀, 오른쪽/아래로 증가.
- u=x/1195, v=y/1110. 소수 다섯 자리 표기는 재연결 편의를 위한 것으로 측정 정밀도를 뜻하지 않는다.
- 객체 bbox는 육안으로 잡은 근사 검색 영역이다. 정확한 실루엣·바닥 차지 면적·안전 반경·충돌 도형이 아니다. 주변 풀/그림자가 일부 포함될 수 있다. 중간 확신도, 외곽 조사 영역은 낮음으로 기록했다.
- RT 경유점은 육안 경로 후보다. 점끼리 직선 연결 시 실제 돌을 통과할 수 있으며 그런 경우 후보를 수정해야 한다. 특히 T4와 T5는 정밀 윤곽 확인 전 안전을 주장하지 않는다.
- 월드 변환·파티 반경·도착 영역 크기는 미정. 지도상의 bbox만으로 진형 통과나 최단 경로를 계산하지 않는다.

## 고정 ID와 분류

OB-001~064는 개별 군집, OB-B01~04는 상/우/하/좌 외곽 조사 영역, OB-G01은 원형 잔해의 부모다. OB-060~063 네 조각만 실제 개별 군집으로 센다. 부모를 원판 충돌로 채우지 않는다. 조사 영역은 모서리에서 겹칠 수 있고 밀도 계산에 넣지 않는다.

RF-01~10은 기존 특징 ID를 재사용한다. RT의 역할은 시험 후보이며 ‘모든 파티가 반드시 통과하는 경로’로 아직 확정하지 않았다. 04의 T 별칭은 지역이고 새 RT가 실제 후보 경로를 구분한다.

## 시작 후보와 입력 프로토콜

P01 참조 위치는 원본 픽셀 (565,580), 정규화 약 (0.47280,0.52252)다. 중앙 연결로 왼쪽 근처의 후보이며 도착/출발 영역 반경은 미정이다. 네 명을 실제로 놓아 확인하기 전 확정 시작점이 아니다.

| 프로토콜 | 계획 입력 순서 | 성공 조건 | 현재 차단 |
|---|---|---|---|
| START-01 | P01에 N명·F진형 초기화→입력0으로 관찰 | 슬롯 전부 유효 지면, 겹침/이탈0, 정지 수렴 | D01~04·D06 |

경계 RT-012~015의 끝점은 바깥 방향 입력을 정하기 위한 목표다. 끝점에 캐릭터를 초기화하거나 그곳 도달을 성공 기준으로 삼지 않는다. 경유점 전환·정지 시간·스텝 수·입력 벡터는 월드 변환 후 별도 고정한다. 자동 경로 탐색이 아니라 명시된 입력 시퀀스를 사용하는 시험이므로, 경유점이 실제로 안전한지 먼저 확인한다.

WALK-01의 reverse 조합은 순서 역전 시험이다. 한 실행 도중 정지 후 즉시 반전하는 기존 MC-MOVE-04 상세 시나리오와는 다르므로, 그 상세 왕복/반전 사례는 별도 추가가 필요하다. 이번 계획372개만으로 MC-MOVE-04 전체 범위가 채워지지 않는다.

## 계획 사례 조합

- 이동 후보 13개 × 1~4인 × 3진형 × 정/역방향 = 312개.
- 외곽 접근 4개 × 1~4인 × 3진형 = 48개. 경계 바깥 초기화 방지를 위해 단순 역방향 조합을 만들지 않음.
- P01 초기화 × 1~4인 × 3진형 = 12개.
- 합계 **372개는 예상 실행 목록**이며 실행 횟수나 테스트 통과 수가 아니다. 모두 execution_status=NOT_RUN, readiness=BLOCKED.
- F0 균형/F1 쐐기/F2 횡대, 현재 진형 정의 사용. 값의 복제/변경 없이 기존 기획을 따른다.
- 생사·정비·고dt·스폰·재배치·공격·카메라·성능·전체 연결·반복 재현·정상대조/실패주입은 기존 사례 명세에 남아 있고 이번 조합 CSV에 아직 펼치지 않았다. 전체 하네스 사례 수를 372라고 제한하지 않는다.

## 실제 실행 시 측정과 판정

모든 슬롯의 목표/실제 위치·생사·구간 충돌·경계 거리·입력·dt·경유점 진행을 기록한다. bbox가 아닌 확정 충돌 후보로 관통을 검사한다. 정체는 입력이 있고 정해진 관찰창 동안 진행량이 기준보다 작을 때만 평가하며 의도한 정지 구간과 구분한다. 경계 접근에서는 바깥쪽 진행량0이 정상일 수 있으므로 BOUND-01의 복귀 구간에서 도달·정체를 평가한다.

관통/이탈 검출, 도달 제한 초과, 허용 진형 오차 초과는 FAIL. 기준/측정 누락은 BLOCKED. 최초 실패 프레임·앞뒤 궤적·증거 지문을 보존한다. 실제 도형·측정 없이 이 등록부만 검사한 결과는 문서 정합성 PASS로만 부른다.

## 검토 범위와 남은 일

1. 이번 단계: 주요 군집의 근사 위치, 후보 경로·계획 ID의 추적 관계 확인.
2. 다음 설계: RT별 사용 정책과 정확한 윤곽/월드 변환 결정안. 후보가 겹치면 경로/진형 조건을 수정하고 CH로 기록.
3. 이후: 실제 입력 사례 전개, 나머지 사례군 조합 전개, 하네스 구현 설계 검토.

산출물 네 판과 Unity는 이번에 제작하지 않았다. CSV 데이터는 문서용 등록부이며 런타임 콘텐츠나 실행 가능한 테스트 데이터가 아니다.
