# 맵 하네스 사례 명세 v1

2026-10-30. **모두 설계 사례이며 실행 결과는 NOT_RUN**. 좌표·충돌·기준값이 없는 사례는 구현 후 사전 확인 시 BLOCKED로 판정해야 한다. 이 문서를 실행 로그처럼 사용하지 않는다. 공통 실행/판정은 [하네스 설계](맵-워크플로우-하네스-설계.md), 표현은 [산출물 규격](../workflows/map-artifact-contract.md)을 따른다.

## 공통 시험 조건

각 사례에는 작업/맵/사례/기준 개정, 참조 RF/OB/RT, 실제 초기 상태·입력·측정·예상 상태·증거·복구를 채운다. 아래 표는 사례군 정의이며 실제 실행 전에 [사례 양식](../templates/map-test-case.md)으로 파라미터 조합을 펼쳐 예상 ID 목록을 고정한다. 예: `MC-MOVE-04 / 4인 / 횡대 / 왕복 / S0 / 16:9`는 하나의 조합으로 식별한다.

공통 이동 조합은 1~4인 × 세 진형 × 양방향, 고정 dt와 정지/반전 입력을 포함한다. 시간 단계 변형·파티 생사·화면 변형은 별도 사례군에 명시한다. 서로 다른 조합을 1건으로 합산하지 않는다. 모든 조합을 만들 수 없는 이유는 예상 목록에서 누락시키지 말고 BLOCKED로 기록한다.

## 상세 사례 — MC-MOVE-04 사선 통로

- 목적/연결: RF-08, 04의 T4. 사선 잔해 사이의 필수 통로에서 고정 방향 진형이 충돌 없이 왕복하는지 확인.
- 사전 조건: RT 양끝 영역·안전한 중간 정지점·장애물 도형·좌표 변환·r·오차/정체/도달 제한 등록. 미등록이면 BLOCKED. 그림의 T4 핀은 잔해를 가리키므로 출발점으로 쓰지 않는다.
- 초기 상태: 4인 횡대, 같은 슬롯/HP/장비, 적·투사체 없음, 고정 카메라·dt·입력 상태. 다른 파티/진형 조합은 별도 실행.
- 입력: 등록한 시작 영역에서 통로 방향 이동 → 중간점에서 입력0으로 지정 시간 정지 → 같은 방향으로 끝 영역 도달 → 반대 입력으로 시작 영역 복귀. 실제 벡터·스텝 수·도착 허용 영역·정지 길이는 사례 데이터에 명시하며 현재 미정.
- 관찰: 매 시뮬레이션 단계의 Center·목표/실제 슬롯 위치·생사·구간 충돌·경계 거리·통로 진행량·입력·dt. 충돌 계산은 끝점만 검사하지 않음.
- 판정: 검출 관통/경계 이탈 0, 왕복 목표 도달, 오차·정체 제한 이내, 정지 중 수렴. 파티 개별 순간이동·진형 자동 회전·장애물 무시로 통과시키면 FAIL.
- 증거: 초기/정지/종료와 최초 실패 프레임, 경로/충돌층, 시계열, 모든 지문. 궤적이 빠지면 안전을 증명한 PASS 불가.
- 복구: 파티·시간·진형·입력·카메라 원상태, 직접 시작한 실행 종료.

## 상세 사례 — MC-SPAWN-01 후보 소진

- 목적: 화면 밖 생성 조건과 장애물·최소 거리·접근 조건을 모두 만족하는 지면이 없을 때 무한 재시도나 일괄 생성이 없는지 확인.
- 초기 조건: 전체 맵을 바꾸지 않는 격리된 시험 후보 집합에서 모두 거절되도록 구성. 일반/추가 생성은 별도 조합. RNG·남은 예산·타이머를 고정.
- 입력: 등록된 제한 시간 동안 생성 갱신 → 후보 하나를 유효하게 바꾸기 → 다시 갱신. 이 변화를 스텝으로 명시.
- 관찰: 시도/실패/지연/실제 생성 수·생성 위치·예산·프레임 소요·실패 이유. 실패를 성공 생성으로 세지 않는지 확인.
- 판정: 사전 retry/delay/burst 제한 준수, 유효 후보 전까지 실제 생성0, 이후 상한 초과 몰아내기 없음. 상한 미정이면 BLOCKED. 시간제 웨이브 종료 시 남은 예산 정책도 먼저 명세.
- 증거/복구: 후보 거절 로그와 해당 지면·시야·거리 화면, 원래 후보 제공 경로/타이머 복구. 이것만으로 정상 웨이브 전투 압력이 검증됐다고 보지 않음.

## 하네스 자체 실패 탐지 시험

실패 주입은 실제 맵 자산을 손상시키지 않는 격리된 복제/시험 입력으로 수행하는 설계다. **하네스가 예상 반응을 검출하면 하네스 탐지 시험은 PASS지만, 주입된 사례는 정해진 FAIL/BLOCKED 등 원래 판정을 유지한다.** 둘의 결과 칸을 합치지 않는다. 정상 대조군도 반드시 같은 관찰 경로로 실행하여 항상 실패만 내는 검사기를 걸러낸다.

| ID | 주입 | 기대 반응 | 탐지하지 못하면 |
|---|---|---|---|
| FI-01 | 시작 슬롯을 장애물 내부로 배치 | MC-START-01의 정확한 겹침 원인 FAIL | 하네스 FAIL |
| FI-02 | 등록된 필수 통로를 임시로 막음 | MC-CONN-01 불연결 또는 MC-MOVE 정체/미도달 FAIL | 하네스 FAIL |
| FI-03 | 한 스텝에 얇은 벽을 가로질러 끝점만 바깥에 놓음 | 구간 관통 FAIL | 하네스 FAIL |
| FI-04 | 결과 하나 삭제/중복, 빈 사례 집합, 종료 표식 누락 | 완전성 검사 거부, 종합 PASS 금지 | 하네스 FAIL |
| FI-05 | 이전 실행 캡처/결과 또는 다른 맵 지문 혼입 | 증거 불일치 FAIL | 하네스 FAIL |
| FI-06 | 임계값 누락 또는 NaN 측정 | 누락은 BLOCKED, 완료 주장 데이터 불량은 FAIL | 하네스 FAIL |
| FI-07 | 직접 변경한 시험 설정 복구를 고의 실패 | cleanup FAIL, 전체 성공 금지 | 하네스 FAIL |
| FI-08 | 실행 중 취소/시간초과/프로세스 종료 | 중간 결과와 미완료 표시, 복구 시도·다음 사전 확인, PASS 금지 | 하네스 FAIL |
| FI-09 | 같은 개정 표기로 다른 도면/군집 배치 제공 | MC-ART-01 또는 지문 불일치 FAIL | 하네스 FAIL |
| FI-10 | 측정 갱신을 중지하되 게임은 진행 | 관찰 누락 검출, 판정 BLOCKED | 하네스 FAIL |

FI 결과에는 실제 관찰한 오류 종류와 예상 오류가 일치하는지도 기록한다. 다른 예외로 멈췄다는 이유로 탐지 성공 처리하지 않는다. FI-07/08은 실제 사용자 설정이 아닌 시험 격리 환경에서 우선 검증한다.

## 검증 범위 누락 방지

- P/T 샘플 통과만으로 전체 맵 합격 금지. 전체 OB·필수 RT 등록과 MC-CONN-01 필요.
- 네 명만 검사하고 1~3명 재중심·사망 슬롯을 생략하지 않음.
- 일반 생성만 검사하고 추가 생성·재배치를 생략하지 않음.
- 맵 이미지의 길을 실제 도달 가능 경로로 간주하지 않음.
- 게임 규칙 검사·기기 성능·사람의 조작감은 각자의 증거로 판정.
- 미정 좌표·수치·정책은 작업 묶음의 차단 목록에 모으며 사례와 연결. 사례 문구가 상세해도 아직 실행 가능한 사례 데이터가 없다는 사실을 명시.
