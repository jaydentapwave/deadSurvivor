# 050 — 에셋 규격(모바일)·캐릭터 팔레트·정식 제작 경로

- 규모: **L2**. 자산 등록부(카탈로그) 도입, 자산 위치(소유권) 이동, 제작 경로 원본 변경. [개발 절차](../workflows/development.md) L2 조건.
- 사용자 요청(2026-11-03): "규격표 숫자의 경우 모바일에 최적화된 형태로 정리를 해줘, 캐릭터도 우선 팔레트를 해주면 좋을 것 같고 3번은 후자로 해줘 그래서 지금 나온 것 모두 개선을 해줄래". 앞선 점검에서 나온 5건: ① 규격표 ② 캐릭터·몬스터 공용 셰이더 ③ 실제로 쓴 `tripo_045.py` 흐름을 정식 경로로 ④ 정식 위치·채택 목록 ⑤ 텍스처 축소.

## 이번에 쓸 수 있게 될 결과와 완료 조건

1. **규격표**: 자산 종류별 모바일 숫자(삼각형·텍스처·뼈·재질·셰이더·그림자·원점·정면). 숫자 원본은 `docs/art/asset-catalog.json`의 `standards`, 사람용 표는 [에셋 규격](../workflows/asset-standard.md).
2. **빌드 첫 장면(`Map046_Full`)의 모든 고체 렌더러가 `DeadSurvivor/LowPolyPalette`**(물·효과·바닥 원형 그림자·피격 깜빡임은 예외 목록). 영웅 6명·몬스터 5종·바위(OB-001)가 팔레트 색만 쓴다.
3. **정식 경로 1개**: `Tools/Art/assets.py` — `spec` / `list` / `gen`(Tripo, `tripo_045.py` 승격) / `prep`(Blender: 감량·텍스처 팔레트화) / `unity`(Unity 프리팹·재질·가져오기 설정·액터 세트) / `check`(규격 대조) / `capture`(정면·게임 각도 줄 세우기).
4. **빌드 장면이 쓰는 에셋은 모두 `Assets/DeadSurvivor/Art/` 아래**에 있고 카탈로그에 등록된다. `Scenes/Proto*`, `Art/Tests`는 시험 폴더이며 빌드 장면에서 참조하지 않는다.
5. 캐릭터 텍스처가 규격 크기(영웅 256, 몬스터 128)이고 모바일 압축(ASTC)이 걸린다.
- 완료 확인: `assets.py check --all` PASS, 컴파일 오류 0, `Map046_Full` 짧은 Play 1회 PASS + 캡처, 성능 한 줄(049와 같은 측정), 사용자 화면 확인.

## 근거 숫자 (2026-11-03 실측, `Map046_Full`)

- 카메라: 직교 크기 6, 55° 기울기 → 영웅(0.8) 화면 높이 **1280×720에서 약 28px, 1080p 폰에서 약 41px**, 몬스터(0.52) 약 18px / 27px.
- 현재: 영웅 삼각형 1,558·뼈 67·텍스처 2048(가져오기 512)·URP Lit. 몬스터 750~890·텍스처 2048(일반형 1024)·URP Lit. 바위 OB-001 **9,492삼각형**·2048 색+노멀·URP Lit(1개). 나무 1,368, 큰 바위 576, 맵 생성 메시 4,326(팔레트).
- 텍스처 크기: 1080p에서 41px인 영웅은 몸 UV가 텍스처 높이의 절반만 써도 256이면 화면보다 약 3배 촘촘하다. 몬스터 27px는 128이면 충분하다.
