# 040 — Codex→Claude 인수인계와 공통 작업 선호

- 상태: 구현 기준
- 규모: L1. 문서 변경이지만 공통 규칙 원본(AGENTS)에 작업 방식과 독립 검토 라우팅(교차 모델 우선)을 추가하므로 [개발 절차](../workflows/development.md)의 "역할 계약 변경" 조건에 해당한다.
- 산출물·완료 조건: Codex와 Claude가 같은 파일에서 사용자 작업 선호와 도구 연결 정보를 읽을 수 있다. 에이전트별 메모리에 따로 두지 않는다.
- 요구(사용자, 2026-11-02): "한곳에서 계속 바라보게끔". 서브에이전트 모델·effort는 메인에 위임("알아서"). Claude Unity 플러그인 갱신은 메인에 위임.
- 제외 범위: hook·gate·baseline·필수 검사 ID 변경 없음. 전역 Codex/Claude 설정 변경 없음(플러그인 갱신 시도는 Claude Code 자동 모드 보호로 차단, 사용자 직접 실행으로 남김). 게임 코드·데이터 변경 없음.
- 근거 자료: Codex 사용자 설정(`~/.codex/config.toml`, 읽기 전용·비밀값 가림), Codex 세션 141개 중 사용자 메시지 342개와 도구 호출 기록(2026-10-27~11-01 UTC), 이 컴퓨터에서의 실행 확인(Tripo CLI 버전, Unity 상태, `codex exec` 시험 호출). 원자료 요약은 세션 로컬 임시 폴더에만 두었고 저장소에 복사하지 않았다.
- 변경 파일과 전 → 후:
  - `AGENTS.md`: 작업 선호 절 추가. 이전에는 Codex 대화에만 있던 선호(진행 공유, 솔직한 평가, 전체 느낌 우선, 워크플로우 제거 신중, 병렬 에이전트 충돌 방지, 서브에이전트 모델 위임, 교차 모델 검토 우선)를 공통 원본으로 옮긴다.
  - `docs/개발환경.md`: 에이전트 도구 연결 표 추가(Tripo CLI 경로·환경변수, Unity CLI 새 명령 이름과 Claude 플러그인 구버전 차이, Codex 이미지 출력 위치, Stop hook 신뢰 상태, `~/Documents` 접근 제한, 금지 연결).
  - `docs/workflows/development.md`: Claude 역할 정의 인식을 "확인 대상"에서 확인 결과로 갱신.
- 재사용: 기존 AGENTS 저장 경계·검사 원칙, 개발환경 문서를 갱신한다. 새 규칙 파일을 만들지 않는다.
- 실패·경계: 교차 모델 검토를 쓸 수 없으면 같은 계열의 독립 서브에이전트로 검토하고 그 사실을 기록한다. 기존 "독립 검토 도구가 없으면 BLOCKED" 규칙은 유지한다.
- 최소 필수 검증: 문서 링크·앵커(gate docs), 기존 규칙과의 충돌 여부, 사실 기재가 확인 근거와 일치하는지 → 독립 검토(Codex, validator-client 계약).
- 초기 실제 연결: 문서 작업이라 해당 없음.
- 미정: Desktop 경로에서 Codex 프로젝트 Stop hook 자동 발동 여부(사용자가 Codex `/hooks`에서 재신뢰해야 확인 가능).
