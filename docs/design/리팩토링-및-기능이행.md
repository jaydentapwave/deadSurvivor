# 기존 동작 보존 리팩토링과 기능 이행

상태: 설계 검토 PASS 후 프로토타입 구현. L2: 코드 책임 분리 및 이후 JSON 스키마 변경.

## 단계 계약

1. 현재 C#/데이터를 스냅샷 보존하고 Unity 실제 실행 회귀 기준 확보.
2. 하네스에 대상 에디터 확인, 컴파일, 실제 프레임 증가, 규칙 및 입력 검사, 실행별 새 로그/캡처, 세션 정리를 연결.
3. DSGame의 인벤토리·능력치·런 흐름을 partial 파일로 분리한다. DSGame 객체가 상태를 계속 단독 소유한다. 기존 public API와 직렬화 필드, Unity 스크립트 파일/메타를 유지한다. 다른 프로젝트의 DI 구조를 도입하지 않는다. 전투도 적 행동/투사체와 시뮬레이션 책임에 맞춰 후속 분리한다.
4. 기존 회귀 결과를 통과한 뒤에만 최신 할일 기능을 구현한다. 기존 검사 스냅샷은 남기고 새 기획으로 바뀐 기대값은 변경 근거를 기록한다.
5. DOCX는 이전 기준/장기 컨셉으로 보존한다. 최신 할일의 고정 4×4, 주무기 직업, 무료 부활, 435초 웨이브 기준이 이전 규칙보다 우선한다. 마을/메타 성장/구출 스토리는 이번 할일 범위에 없는 장기 컨셉이다.

## 소유권과 안전

저작본 UnityMigration/Runtime·Editor·Data와 실행 프로젝트의 대응 C#은 현재 일치한다. 적용 직전마다 비교하여 외부 변경이 있으면 덮어쓰지 않는다. 신규 partial 파일은 실행 폴더에 추가하며 기존 .meta를 유지한다. 기준 스냅샷과 결과는 현재 저장소 output 아래에만 둔다. 에디터는 개인 Deadsurvivor만 지정한다.

## 검증

기존 DSVerification 145회, UI 포인터 드래그/조이스틱, 실제 프레임, 콘솔 오류, 가로 화면 캡처. 실행 세션은 중지 상태에서 시작하고 finally에서 종료한다. 이미 플레이 중이면 BLOCKED. 큐 등록은 성공이 아니며 완료 신호를 기다린다. 시간 초과/명령 실패는 성공으로 바꾸지 않는다.

## 다음 기능의 별도 검토

32종 아이템과 직업/전투 변경은 별도 상세 브리핑을 작성해 스키마·효과 계산·공유 타이머·교체 원자성·UI 미리보기를 검토한 후 구현한다. 이번 리팩토링에서 행동을 바꾸지 않는다.

## 설계 검토 보완 D1/D2

미저장 씬이 있거나 Enter Play Mode의 scene/domain reload가 비활성인 환경은 변경하지 않고 BLOCKED 처리한다. 플레이 시작 요청 전 소유 시도를 기록하고 시작 실패 시 상태를 확인한다. 기존 플레이 세션은 건드리지 않는다. finally 종료 후 stopped를 확인하며 정리 오류는 원래 실패를 지우지 않고 별도 결과로 기록한다.

InteractionCheck.cs 및 하네스 어댑터도 지문에 포함한다. 입력 검사는 실행별 고유 경로를 인자로 받아 준비/실행 실패와 완료 신호를 그 파일에 쓴다. 이 파일은 실행 전 없어야 하며 완료 상태와 실제 프레임 진행을 확인한다. 타임아웃·미생성은 BLOCKED/FAIL로 처리하고 기존 MigrationVerification 텍스트를 새 성공 근거로 사용하지 않는다.
