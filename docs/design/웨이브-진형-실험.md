# 웨이브 시간과 진형 실험 구현

상태: 설계 검토 PASS 후 프로토타입 구현. L2: 웨이브 데이터에 시간/보상 및 측정 필드를 추가.

WaveDef에 duration/drops를 추가한다. 기본 duration 배열은 30,30,35,40,40,45,45,50,55,65(합435초), 2026-10-29 사용자 요청으로 중간 정비 보상은 매번 무작위3~5개(각 개수 동일 확률)로 변경했다. 9회 합계는27~45개, 기대값36개다. 기존33개 고정 기준은 과거 기록이다. 남은 적 조기 전멸로 웨이브를 끝내지 않고 정해진 시간에 종료한다. 10웨이브는 결과로 이동한다. 패배는 더 일찍 종료 가능하다.

테스트 설정의 첫 웨이브 시간은 30초 기본, 다른 웨이브 시간도 duration/30 비율로 함께 조정한다. 보상 override는 0=웨이브 데이터 사용, 1~8=중간 웨이브 동일 개수다. 웨이브 drops=0이면3~5개 무작위, 양수면 해당 개수 고정이다. 기본은 모든 drops=0이며 마지막 웨이브에는 보상을 생성하지 않는다. UI 설명과 검증을 같이 수정한다. 정비 시간은 제한하지 않는다.

측정은 전투 시뮬레이션 시간, 실제 전투 경과, 정비 실제 경과, 일시정지 시간을 분리한다. 배속/건너뛰기 사용 여부를 기록한다. 초기 로비와 결과 체류는 합산하지 않는다. 스킵도 10웨이브이면 결과로 종료한다.

진형은 기본 균형형, 쐐기형, 횡대형. 화면 위쪽 고정이며 이동 방향 자동 회전 없음. 간격은 기존48px, 자리 추종은 기존 보간을 유지한다. 1~3명은 각 배열의 처음 n개를 사용해 중심을 다시 맞춘다. 사망자는 슬롯 유지, 부활 시 같은 슬롯 복귀. 정비 중 선택은 다음 웨이브부터 적용한다. 진형 자체 능력치 보너스는 없다. 이름/주무기 이름을 담은 좌표 미리보기를 정비 중앙에 표시한다.

검증: 총 시간435/매회 보상3~5·총27~45, 조기 종료 방지, 시간/스킵 종료, 정비 중 전투 동작 정지, 기록 합계, 1~4인 진형 좌표 중복 없음, 선택 후 다음 웨이브 적용과 사망/부활 슬롯 보존. 실사용자의 진형 선호 및 체감 재미·난이도 평가는 별도 미완료로 남긴다.

## W1/W2 보완

전멸을 시간 종료보다 먼저 처리한다. 같은 프레임에 전멸과 시간이 겹치면 중간/최종 웨이브 모두 패배이며 전리품을 지급하지 않는다. 시뮬레이션 dt는 남은 웨이브 시간으로 제한한다.

실제 시간은 활성 전투, 정비/전환, 일시정지를 배타적으로 기록한다. 유효 플레이=활성 전투+정비/전환, 전체 런=유효 플레이+일시정지. 웨이브 시작에 전투 구간 시작, 정비 진입에 해당 웨이브 전투 기록 확정, 다음 시작에 정비 기록 확정. 최종 웨이브는 정비 0이다. 현재 전환은 동기식이며 별도 대기 연출이 없어 별도 전환 항목은 0, 해당 프레임 경과를 전투/정비 구간에 한 번만 산입한다.

자동 검사는 verificationRun으로 명시한다. 기본 설정 대비 시간/보상/배속/적 수 또는 JSON 변경, 건너뛰기를 testControlsUsed로 기록한다. 로비와 결과 체류는 런 합계와 분리해 기록한다. 앱 초기 로딩 시간은 -1(미측정)로 명시하며 이번 완료 항목에 포함하지 않는다.

원래 상세 요구는 [구현 전 할일 원문](../sources/할일-구현전-20261029.md)에 보존하며 현재 상태는 [할일](../../할일.md)을 따른다.

## 무작위 보상 개수 변경 (L1)

기존 보상용 LootRng로 묶음 개수를 한 번 뽑은 뒤 기존 가중치로 종류를 뽑는다. 개수 난수는 전투 RNG를 소비하지 않는다. 기본 JSON·설정 안내·검사를 함께 변경하며 고정 개수 테스트 설정은 유지한다. 범위/3·4·5 도달/동일 시드 재현/중복 지급 방지/최종 보상 없음/설정 우선순위를 실제 FinishWave 경로로 검사한다. 기존 자동 장비 비교 결과는 이전 보상 정책의 기록으로 보존한다.

## 몬스터 수 감소

2026-10-29 요청에 따라 기본 countScale=0.7. 일반 생성 예산은 웨이브별140,189,238,287,336,385,434,483,532,581이며 기존 대비30% 감소다. 버닝 추가 생성도 같은 배수를 사용하되 간격/정수 반올림 때문에 실제 개체 수에는 오차가 있다. 시간·보상은 유지하며 테스트 설정의 배수 override는 가능하다. 이전 자동 비교는 감소 전 밸런스 기록이다.

후속 요청으로 현재 기본 countScale은0.49다(0.7 대비30% 추가 감소). 현재 일반 생성 예산은98,132,167,201,235,270,304,338,372,407. 위0.7 수치는 이전 단계 기록이다.
