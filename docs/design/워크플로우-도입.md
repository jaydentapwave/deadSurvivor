# 개인 개발 워크플로우 도입

상태: 구현 후 검토 중. 규모: L1. 기존 게임 상태/데이터 구조는 바꾸지 않으며 여러 문서·역할·로컬 검사 경로를 연결한다.

## 요구와 범위

walter_idle의 문서·설계 검토·구현 검토 구조를 개인 프로젝트에 적용한다. 회사 외부 기록 금지. 게임 기능 개발, 원격 저장소, 전역 설정, 자동 배포, 회사 훅 도입은 제외한다.

## 구현 계약

AGENTS가 저장 경계, docs/workflows/development.md가 규모별 절차, 각 역할 MD가 리뷰 기준의 단일 원본이다. Codex 스킬과 Claude 에이전트는 그 원본을 읽는 얇은 진입점이다. Codex는 역할 파일을 자동 등록한다고 가정하지 않고 collaboration으로 독립 검토를 호출한다.

기존에는 계획 문서와 개별 Unity 검사만 있었다. 이번 변경은 설계→독립 검토→구현→검사→문서 갱신의 작업 절차를 제공한다. 기존 DSGame과 JSON 소유권은 유지한다.

## 실패와 복구

리뷰 도구 미사용 가능 시 독립 검토를 BLOCKED로 기록한다. Unity 어댑터가 없는 all 검사는 미실행을 표시하고 실패가 아닌 환경 미완료 종료 코드 2를 반환한다. 원본 소스는 수정하지 않고 결과만 output/verification에 저장한다. 자동 훅을 설치하지 않아 기존 실행 환경에 영향을 주지 않는다.

## 검증

- 정상 로컬 문서와 데이터: local PASS.
- 깨진 문서 링크/저장소 밖 파일 링크: docs FAIL.
- 없는 무기 참조/중복 아이템 ID: data FAIL.
- all 실행: Unity NOT_RUN, 전체 BLOCKED, 종료 코드 2.
- 독립 validator-client 검토: 결과는 docs/reviews/워크플로우-도입-20261029.md에 기록.
- 설치된 도구에서 스킬 자동 검색과 Claude 역할 자동 등록은 미확인. 파일 경로를 읽는 수동 진입은 제공한다.

이 브리핑은 도입 작업 중 작성한 L1 구현 범위 기록이며 사전 L2 설계 리뷰를 받았다고 주장하지 않는다.
