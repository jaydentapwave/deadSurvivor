# 042 — 3D 캐릭터 1명·몬스터 1종 시험 (100% AI)

- 상태: 구현 기준
- 규모: L1. 게임 코드·데이터·상태 소유권은 바꾸지 않는다. 새 자산과 격리 시험 장면을 추가한다. 캐릭터 리깅·애니메이션은 [AI 3D 자산 워크플로우](../workflows/ai-3d-assets.md)에서 "별도 설계 전까지 범위 밖"이므로 이 문서를 그 별도 설계로 삼는다. 정식 자산 등록(A5)과 게임 연결은 하지 않는다.
- 사용자 요구(2026-11-02): [041 r002 `day.png`](../reviews/keyart-041-review.md)를 스타일 기준으로 채택. 다음 단계로 캐릭터와 몬스터를 **1종씩만** 만든다.
- 산출물·완료 조건: 3D 영웅 1명(리깅 + idle·run)과 3D 일반 몬스터 1종을 격리 장면에서 게임 카메라와 실제 크기로 렌더한다. 같은 화면에 현재 2D 스프라이트를 나란히 놓고 키 아트와 비교한 캡처를 만든다. **시험 후보**이며 정식 채택이 아니다.
- 제외 범위: `DSWorld` 그리기 층 교체(L2, 별도), 게임 장면·기존 장면 수정, 전투 연결, 추가 종족, 무기·장비 모델, 밤 조명 시스템.
- 대상 선택(에이전트 제안):
  - 영웅은 bruno(전사, 주색 `#d79b68`). 기준 키 아트에서 가장 잘 읽히는 색이라 파이프라인 시험의 기본 사례로 삼는다. 위험 사례인 한스는 후속이다.
  - 몬스터는 melee(가장 흔한 일반형, `#819363`).

## 생성 경로

1. **콘셉트 이미지:** Codex 이미지 생성으로 Tripo 입력용 단일 개체 이미지 2장을 만든다(정면, 전신, 단색 배경, 그림자 없음, 영웅은 A포즈). 입력은 `day.png`(스타일)와 스프라이트 시트(정체성)다. 외부 레퍼런스는 넣지 않는다.
2. **Tripo:** 프로젝트 로컬 CLI 0.8.1, `tripo make <이미지> --model tripo-v3.1 --seed <고정> --candidates 1`. 같은 인자로 먼저 dry-run해 유효성과 예상 비용을 기록한 뒤 제출한다.
3. **영웅 리깅:** `anim check` → `anim rig --spec unity --out-format fbx` → `anim retarget --animation preset:idle preset:run --animate-in-place`. 프리셋 이름은 Tripo 내장 예제(`tripo docs --topic examples/animation`)에 나온 것만 쓴다.
4. **몬스터:** 리깅하지 않는다. 다리 없는 덩어리형이라 통통 튀기·찌그러짐 같은 절차적 동작을 Unity 코드로 준다(에이전트 제안. 크레딧 절약, 코드로 관리 가능).
5. **Unity:** 별도 시험 장면에 정사영 55도 카메라와 게임 표시 높이 0.72(영웅·일반 몬스터 동일)를 맞춘다. 3D 영웅 1·몬스터 여러 마리·기존 2D 스프라이트 1세트를 배치하고, 1280×720으로 낮 조명을 캡처한다.

## r006 — 가까운 카메라 + 테두리 빛(rim) 시험 (사용자 승인 2026-11-02)

- 목적: [042 검증](../reviews/char-monster-042-review.md)에서 게임 카메라(정사영 6, 55도)의 약 32px 3D 영웅이 2D보다 안 읽혔다. 같은 모델로 (a) 카메라를 당겨 화면 속 크기를 키우고 (b) 043 세션의 rim 셰이더를 입혔을 때 3D 캐릭터가 성립하는지 판정한다. 크레딧은 쓰지 않는다.
- 범위: 기존 Test042 장면을 열고 2D 그룹과 화면 크기 맞춤 3D 그룹을 각각 중앙에 두어 정사영 6 / 4.5 / 4로 캡처한다. rim은 043 셰이더를 쓰는 새 머티리얼을 042 폴더에만 만들고, 043 에셋은 수정하지 않는다. 장면은 저장하지 않고 원래 구성을 복구한다. Play 모드는 쓰지 않는다.
- 판정 기준(정성): 각 크기에서 얼굴·가슴판·발 등 정체성 요소가 1280×720에서 보이는가. 2D 대비 어느 쪽이 읽히는가. 카메라를 당겼을 때 보이는 범위 감소(정사영 4.5는 화면 면적의 약 56%, 4는 약 44%)를 함께 적는다. 화면 범위 변경은 게임 플레이 결정이므로 사용자 결정으로 남긴다.
- 의존성: 043 셰이더 준비와 Unity 사용 순서는 043 세션과 조율한다. 셰이더가 준비되지 않으면 기본 URP Lit으로 카메라 크기만 먼저 시험하고 rim은 NOT_RUN으로 남긴다.
