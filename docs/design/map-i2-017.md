# MAP-I2-017 이동 해결기와 실제 프레임 시험

2026-10-31 · L2 · 상태: 이동 핵심·fixture 구현/검증 완료. [016 기록 계층](map-i1-016.md) 다음의 I2 첫 구현 묶음이다. [009 이동 계약 §5](map-harness-implementation.md)을 구현한다. 사용자 요구는 구현 계속이며 최종 맵 치수/미술 채택은 아니다.

## 범위와 소유권

메인이 DSMapGeometry/DSMapMotion과 DSGame 실제 이동 연결, 별도 Editor 시험/실행기를 구현한다. design-reviewer·algorithm-tester·validator-client는 읽기 전용 독립 검토다. 기존 개인 Unity와 로컬 Runtime/Editor 24개 및 콘텐츠 바이트를 먼저 비교하고 baseline을 보존했다. 기존 플레이는 LegacyNoMap 동작을 유지한다.

이번은 `MOVEMENT_FIXTURE_ONLY` 시험 범위다. 009의 전체 MapRequired/full map v1/명령 큐·상태 전환·난수 추적·전체 FI/G2 완료를 구현한 것으로 표시하지 않는다. I1 `PROTOCOL_FIXTURE_ONLY` 결과도 실제 관측으로 재표시하지 않는다. 두 포맷을 섞지 않고 이번 실제 관측은 별도 `output/map-i2-017/<run-id>/`에 기록한다. 전체 map v1 어댑터와 부활/진형 전환 원자성은 후속 작업으로 남긴다.

## 변경과 알고리즘

- `Runtime/DSMapGeometry.cs`: 불변 단순 다각형 경계/장애물. 좌표 |값|≤1024, circle만 지원. 유한수·정점/변 길이·자기교차·면적·개수 검사. 입력 배열 복사. double 계산으로 선분 교차/최소거리와 초기 포함을 검사하며 오목을 hull로 바꾸지 않는다. boundary 밖/obstacle 안 또는 sweep 거리≤r+2ε면 안전하지 않다. 009의 G>=2ε보다 보수적인 G>2ε로 이번 구현의 등호를 고정하며 r+2ε 정확 접촉은 거부하는 분석 시험을 둔다. ε 필수(시험 .001), Center 반경도 별도 필수값8, 각 r=8은 시험 단위이며 최종 몸체 수치가 아니다.
- `Runtime/DSMapMotion.cs`: Center·생존자 실제 위치·전체 예약 슬롯(사망자 포함)의 초기 안전성 검사. j/256을 256부터0까지 전부 탐색 가능; center'=center+input×140×dt×alpha, 실제 생존자'=Lerp(old,center'+slot,min(1,12dt)); 예약'=center'+slot. 모든 실제/예약/center 선분 안전한 첫 후보를 반환한다. 0에도 추종이 생기므로 따로 검사한다. 후보 없으면 모든 실제 좌표 보존, 초기 무효는 예외/명시 FAIL이며 자유 지면으로 fallback하지 않는다. 죽은 실제 위치는 sweep 제외하고 슬롯은 예약한다. proposal은 상태를 직접 바꾸지 않는다.
- `Runtime/DSGame.MapMotion.cs` 및 Combat: 기존 center/추종을 공통 이동 적용 함수로 이동. Editor 전용 fixture binding은 새 격리 게임에서 초기화 후 최초 Update 전에만 가능하고 해제 후 일반 플레이로 재사용하지 않는다. 시험에서는 같은 Simulate 이동 함수를 사용하되 Spawn/Burning/Recycle/장비/적/투사체 경로 진입 전에 명시적으로 분기한다. 일반 플레이 분기는 기존 순서와 수치 유지.
- `Runtime/DSGame.cs`: 기존 키보드/조이스틱 입력 수집을 공유 함수로 추출. fixture의 FIXED_REPLAY는 한 실제 Update당 한 스텝, supplied dt는 .05 clamp×speed 후 잔여 시간 clip. DEVICE_SMOKE는 소유 가상 Keyboard를 기존 수집 함수로 읽고 실제 dt 사용. 실제 dt와 공급 dt·requested/applied·frame/call count·before/after/예약·몸체/도형·instance ID를 보존한다. 직접 Simulate 호출은 fixture의 프레임 허가 없으면 거부한다.
- 시험 binding 중 StartRun/NextWave/FinishWave/Revive/SelectFormation/ReturnLobby/Result 등 외부 상태 명령은 거부·중단 사유를 기록한다. UI 상호작용은 시험 동안 차단하고 기존 키보드 상태 단축키도 실행하지 않는다. 예상 HP/인원/진형/상태·직전 after를 다음 before와 대조해 오염을 성공으로 삼지 않는다. 전체 명령 큐 구현을 뜻하지 않는다.

## 격리와 복구

`Editor/DSMapMotionVerification.cs`가 자료의 초기화·고정 입력/실제 프레임 driver·단위 사례를 제공한다. `Tools/Verify/map_motion_run.py`는 개인 경로/소스일치/컴파일·Play 정지/저장된 clean 씬/표준 reload를 확인한 뒤 원래 scene setup·selection·background 값을 저장한다. 기존 씬을 저장하거나 변경하지 않고 빈 임시 씬에서 Play를 시작한다. Play 안에서 소유 카메라·DSGame 한 개만 생성하고 reference/run-id/nonce를 고정한다. 생성/초기화 중 game.enabled=false, driver 준비 뒤 활성화. 씬·PlayerSettings/Font·패키지는 저장하지 않는다. 영구 게임 자산 생성/Tripo 비용은 없다. 캡처 png/meta는 고유 Assets 경로에 임시 생성하며 호출 전 intent·사전 부재를 기록한다. 확인된 소유 해시를 검사한 뒤 삭제하고, 미확인/변조 생성물은 보존하여 BLOCKED와 pending을 남긴다. pending은 모든 대상/소스 지문 검사 뒤 제거한다.

대상 Editor/프로젝트 단위 OS 원자 lock을 전체 실행/정리 동안 유지하고, 영속 pending marker와 SessionState의 run/nonce/phase 및 Editor PID를 결합한다. 다른 실행의 lock/pending이 있으면 변경 전 BLOCKED다. Play 진입과 정리 직전 소유권·유일한 실행 표식·PID를 재확인한다. 표식은 run/nonce 이름을 가진 일반 root GameObject로 reload에 포함하며 단일 unsaved scene·유일 표식·Transform만·자식0·기본 Transform·활성 상태를 확인한다. Unity는 unsaved scene 이름을 reload에서 비우므로 씬 이름을 소유권 근거로 사용하지 않는다. 사례 객체 정리에서 표식은 제외한다. 소유 임시 씬은 표식만 있는 상태와 RenderSettings 직렬값을 확인하고 복원한다. 원래 씬의 clean 검사는 유지한다. reload를 넘는 Editor callback이 예상 phase 이외의 Play 중지/재진입을 감지하면 소유권을 무효화한다. 불일치는 추가 Play정지/씬복원 없이 BLOCKED와 복구자료를 남긴다. lock 충돌·다른 owner 정리 거부·표식 유실/복제/자식 추가/설정 변경을 시험한다.

부모 Python의 finally에서 소유 Play 정지와 원래 씬/selection/background 복원을 확인하고 소유 가상 장치를 제거한다. 임시 씬은 저장하지 않는다. 사용자 개입/상태 충돌/연결 실패는 BLOCKED 또는 FAIL 및 원자료 보존이며 이전 씬을 강제로 덮지 않는다. 일반 외부 worker 강제 종료/reload watchdog은 아직 이 시험기의 완료 범위가 아니므로 전체 FI08/CLEAN으로 보고하지 않는다. Ctrl-C·timeout·실패에 대한 이번 부모 finally 정리 결과는 별도 남긴다.

## 시험과 인수

1. 독립 사전 설계와 계산 반례 검토 후 구현. 기존 oracle의 분석 정답 시험도 유지한다.
2. Unity 단위: 무장애/벽/얇은 벽/오목/띠·경계, 1~4인×3진형, 0입력 추종·반전·사망 슬롯 예약·무효 초기/입력/다각형·복사 불변. 판정기 성공 flag에 기대지 않는다.
3. 실제 Update: 정상/얇은 벽/오목/경계/0입력 추종/반전·비단조·alpha0 추종/완전 보류/사망 예약 fixture, 같은 고정 입력2회와 소유 keyboard DEVICE_SMOKE. 사전 고정된 사례 집합과 입력열·도형을 원자료에 결합한다. 생산 FormationOffset에서 얻은 catalog를 실행 전 동결하며 초기 실제/예약 위치를 관측에서 역산해 정답으로 삼지 않는다. 매스텝 공통 중심 변위·격자 계수·관측 목표에 대한 추종·보류 시 전체 좌표 불변을 확인한다. 정상은 안전성 외 진행·예상 정지 구간도 확인하고 반전은 전진 중간 도달과 최종 귀환을 각각 검사한다.
4. 별도 Python oracle가 저장된 도형/Center(명시 반경8)·실제 및 예약 선분을 모두 판정한다. 양쪽 슬롯은 장애물을 비켜가지만 Center만 관통하는 반례도 별도 고정한다. 관통주입(FI03 부분)은 소유 fixture의 한 스텝에서만 이동 차단을 우회하고 `SWEPT_PENETRATION` 검출을 확인한다. 무효 초기 점(FI01 부분)도 별도 정상 대조군과 비교한다. 전체 FI01~10이나 G2 통과로 승격하지 않는다.
5. 선행 코드 독립 검토/수정→현재 실제 프레임/입력·캡처·정리→기존 all --screens→독립 실행 근거 확인→문서/local/gate. 런타임/검사기 지문이 변하면 영향 검사를 다시 수행한다.

미정인 실제 맵 C/몸체/스케일/카메라/성능 수치는 이번 fixture 수치로 채택하지 않는다. 후속 I3~I5와 전체 G2 필수 목록을 축소하지 않는다.

## 실행 명령과 표현 경계

```sh
python3 Tools/Verify/map_motion_run.py
python3 Tools/Verify/map_motion_run.py --cleanup-probe prepare
python3 Tools/Verify/map_motion_run.py --cleanup-probe start
```

기존 local/all은 이 별도 실제 이동 시험을 자동 실행하지 않는다. 기록과 원자료·독립 판정·캡처는 실행별 고유 output에 보존한다. 시험 벽의 윤곽은 기존 논리→표시 변환으로 표시하며 최종 3D 숲 배경이나 PhysX Collider 채택을 뜻하지 않는다. geometry C# 질의가 이동 차단을 담당한다. 고유 표식이 없는 이전 실패 실행은 이름 상실 전후 원자료와 빈 씬/동일 PID/owner·nonce 증거를 대조한 한정 회복으로 처리했으며, 실패 상태는 소급 PASS로 바꾸지 않는다.
