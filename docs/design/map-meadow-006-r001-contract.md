## 1. 좌표 계약

### 세 좌표계를 섞지 않기

| 좌표 | 단위·축 | 소유 근거 |
|---|---|---|
| 이미지 p=(px,py) | 원본 픽셀, 왼쪽 위 원점, 오른쪽+px/아래+py | REF-VM-001 1195×1110 전체 이미지, 자르기 없음 |
| 게임 q=(qx,qy) | 기존 게임 논리 단위, 오른쪽+qx/아래+qy로 대응시키는 안 | 기존 진형 오프셋의 부호 유지, 실제 렌더 어댑터는 구현 전 확인 |
| 월드 w=(X,Y,Z) | 3D 표시 단위, 오른쪽+X/위쪽+Z, 바닥Y=0 | 새 표시 변환 제안, 실제 카메라 축과 별개 |

원본의 ‘위’는 실제 북쪽을 뜻하지 않는다. 카메라를 기울여도 맵 좌표·스폰 판정이 회전하지 않도록 표시 변환을 분리한다. 현재 화면과 향후 카메라가 픽셀 단위로 같은 모습이라는 주장은 아니다.

P01=(565,580)을 이미지 기준점 p0로 잡는다. **기준점은 좌표 계산용이며 파티가 안전하게 시작할 수 있다는 뜻은 아니다.** 안전한 시작 지점이 바뀌어도 모든 좌표를 재정의하기보다 q_start를 별도로 기록한다. 원점 자체를 바꾸는 경우에는 모든 OB/RT·입력·캡처 변환을 새 개정으로 바꾼다.

스케일 s>0는 ‘게임 논리 단위/원본 픽셀’, k>0는 ‘월드 단위/게임 논리 단위’다. 실제 값은 미정이다.

```text
qx = s * (px - 565)
qy = s * (py - 580)
X = k * qx
Y = 0
Z = -k * qy

px = 565 + X / (k*s)
py = 580 - Z / (k*s)

px = 1195*u
py = 1110*v
```

u/v 정규화 표는 정밀 원본이 아니다. 원본 픽셀 값을 우선 사용하고, 정규화 왕복은 다섯 자리 반올림 오차를 고려한다. 픽셀/정규화가 오차 허용 범위를 넘어 불일치하면 자료 오류다. 1195와1110의 서로 다른 길이를 무시하고 u와v에 같은 길이를 곱해 정사각형으로 만드는 변환은 금지한다.

맵 크기 비교에서는 s만 바꾸고 기존 캐릭터 논리 크기·48 간격·140 이동 속도 등은 보존한다. k를 바꾸면 맵과 캐릭터·이동 속도의 **월드 표시값 전체**를 함께 바꾸어 상대 비율을 유지한다. 현재 논리 계산에 s 또는 k를 중복 곱하지 않는다. 벡터에는 원점 이동을 적용하지 않으며, 논리 벡터 (dx,dy)는 월드 (k*dx,0,-k*dy)가 된다.

직교 회전·추가 오프셋·지형 높이는 이번 기본식에 넣지 않는다. 나중에 필요하면 변환 개정을 만들고 기존 식과 혼용하지 않는다. 화면 투영/원근 보정은 별도 계층이다.

### 확인할 불변식

- P01의 월드 위치가 (0,0,0).
- 원본에서 오른쪽 이동→+X, 아래 이동→-Z. 거리 d픽셀은 게임에서 s*d, 월드에서 k*s*d.
- 임의 두 점의 거리비·각도·인접 관계 유지. s/k가 0·음수·NaN·무한대면 사전 거부.
- s와k 각각뿐 아니라 곱 k*s도 양수·유한이어야 한다. underflow로0 또는 overflow로무한대가 되면 거부한다. 입력 좌표와 중간·최종 계산값도 유한성을 확인한다. 숫자 표현 범위 밖이면 좌표를 성공적으로 변환했다고 보고하지 않는다.
- 정변환→역변환으로 원래 픽셀 복원. 소수 반올림 오차와 게임 geometry_epsilon은 별도다.
- 이미지 위/아래 반전으로 다각형 부호 면적의 부호가 바뀔 수 있다. 월드 XZ 다각형의 회전 방향은 변환 후 검사하고 필요하면 정점 순서를 뒤집는다. 두 번 반전하거나 외곽/구멍을 혼동하지 않는다.

[검산 벡터](map-meadow-006-r001-transform-vectors.csv)는 s=2, k=0.01이라는 **임의 계산 예제**로만 검사한다. 채택 수치·실제 맵 치수·런타임 테스트가 아니다.

## 2. 충돌 후보 작성 계약

005의 bbox는 검색 범위이고 충돌로 변환하지 않는다. 이번 [작성표](map-meadow-006-r001-contour-policy.csv)는 각 객체에 어떤 작성 방법을 적용할지 배정한다. 실제 도형 점은 아직 없다.

### 분리해서 기록할 세 요소

1. **시각 윤곽 V:** 이미지에 보이는 돌·기둥·식생·그림자 범위를 구분한다. 원본에서 확인되는 부분만 관찰로 기록.
2. **기본 도형 충돌 후보 C:** 우리 게임에서 막을 바닥 영역의 제안. 높이/수관 때문에 바닥이 가려지면 불확실 영역 U를 별도로 기록하고 보류.
3. **파티 여유 영역:** C에 캐릭터/진형을 고려한 이동 가능성 검사. 몸체 여유를 C 자체에 두 번 더하지 않는다.

### 통과 판정은 슬롯 하나가 아닌 전체 파티

각 슬롯의 목표 오프셋 oi, 이동 몸체 반경 ri, 추종 여유 m은 같은 게임 논리 단위를 사용한다. r과m은 음수가 될 수 없다. 통로의 논리좌표 차이 d=(dx,dy)에 대해 n=(-dy,dx)/|d|로 단위 법선을 잡는다. 길이가0인 구간은 거부한다. 이미지 법선과 월드 법선의 부호/단위를 섞지 않는다. 직선 구간의 필요 폭은 다음처럼 **검토용으로** 계산한다.

사전 조건: 슬롯 집합은 비어 있지 않고 oi/ri/m/d의 모든 성분이 유한해야 한다. 각 슬롯에 반경이 하나씩 있어야 하며 ri>=0, m>=0이다. 법선은 유한한 단위 벡터여야 하고 영벡터나 길이가1이 아닌 벡터를 그대로 대입하지 않는다. 위반 시 수치 계산 결과로 PASS를 만들지 않고 잘못된 시험 입력으로 거부한다. 실제 어댑터의 거부 동작은 아직 미구현이다.

```text
required_width = max_i(dot(n,oi) + ri)
               - min_i(dot(n,oi) - ri) + 2*m
```

이는 직선 구간의 필요 여유 비교이며 충분조건이 아니다. 굽은 길·교차로·모서리에서는 실제 이동 궤적과 연속 충돌 검사가 추가로 필요하다. 캐릭터 반경이 동일할 때만 2r로 묶을 수 있다. 예정 진형/죽은 슬롯을 제외해 폭을 줄이지 않는다. 1~3명은 기존 재중심 오프셋을 사용한다.

필수 통로가 맞지 않으면 원인을 순서대로 분리한다: V/C 해석 오류 → 입력 경로 오류 → 스케일 s 비교 → 지역 간격 조정 제안. 결과를 통과시키려고 r/m/임계값을 임의 축소하거나 실패 객체를 삭제하지 않는다. 변경 시 RF와 CH를 함께 검토한다.

### 경로 연결성의 별도 조건

원형의 RT-006 끝점과 RT-008 끝점은 같은 점이 아니다. 두 개별 경로가 통과해도 원형 내부에서 서로 연결된다는 증거가 아니다. 내부 연결 RT-018을 추가 제안한다. 외부 출발 지역들의 전체 연결은 MC-CONN-01에서 별도 확인해야 한다.

RT-018 후보: 원본 (285,900)→(305,925)→(330,950). 연결 OB-G01/060~063, RF-09, MC-CONN-01·MC-MOVE-05. 필수 후보지만 실제 도형/반경 검증 전이다. 새 RT의 양방향 기본조합24개는 별도 정책표에 예상 수로 기록하고 005의372개에 이미 들어 있다고 주장하지 않는다. 실제 사례 행 전개는 다음 개정 작업이다.

## 4. 미정 항목의 해소 상태

| 키 | 이번 진전 | 여전히 막는 조건 |
|---|---|---|
| D01 | 좌표축·기준점·변환식 제안 및 산술 검산 | 실제 s/k 채택, 렌더/입력 대응·카메라 확인 |
| D02 | 69개 등록행의 작성 유형·보존 조건·영향 통로 배정 | 실제 V/C/U 점과 접합·구멍·자기교차 확인 |
