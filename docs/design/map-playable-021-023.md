# 맵 실플레이 연결 021–023

- 상태: 검토 중
- 규모: L2. 실제 DSGame의 이동·파티 전환·전투와 3D 표시 소유권을 연결한다.
- 사용자 요구: 1) 크기·카메라·장애물 비율 2) 실제 파티·정비·부활·다음 웨이브 3) 적 접근·공격·장애물 연결. 단계별 검증과 별도 커밋.
- 관련 원본: [018](map-blockout-018.md), [개발 절차](../workflows/development.md), [규격](../workflows/map-artifact-contract.md). 007/r001 지도·018 데이터·원본 장면은 변경하지 않는다. 신규 Tripo 생성은 없다.
- 범위: 별도 개발용 장면의 기능 프로토타입. 원본 64개 후보 폴리곤의 실측 정확성 및 전체 G2/G3/G4 인수를 주장하지 않는다. 기존 DeadSurvivor 장면은 기존 2D 동작을 유지한다.

## 단계와 소유권

1. 021: s=4/6/8와 카메라 45/55도를 같은 위치에서 비교. 018 원본 프리팹을 새 장면에 복제해 s=4·55도·추적 카메라를 잠정 기본값으로 검증한다. 가림은 별도 가시성 컴포넌트가 카메라–파티 사이 장애물 렌더러만 반투명화한다. 원본 공유 재질을 수정하지 않고 실행 중 복제 재질만 소유·복구한다. 충돌 형상과 장애물 높이는 유지한다. 실제 캡처와 수치가 기본값의 근거다.
2. 022: DSGame이 파티·생사·웨이브의 유일한 소유자다. 선택적 DSMapSession이 immutable DSMapGeometry와 시작점·표시 설정을 소유한다. DSGame.MapMotion의 기존 fixture를 우선 유지하고 map session일 때 DSMapMotion을 사용한다. 시작, 진형 선택, 다음 웨이브, 부활은 모든 관련 actual/reserved 슬롯의 sweep을 변경 전에 확인한다. 실패 시 HP·아이템·RNG·웨이브·pendingFormation을 변경하지 않는다. 정비 중 타이머는 기존대로 정지한다. DSWorld의 선택적 3D 분기는 기존 스프라이트를 카메라 방향 빌보드로 표시한다. UI는 기존 DSUI를 사용한다. 새 개발 장면은 이 단계에서 전투를 끄고 실제 정비 흐름을 시험한다.
3. 023: 같은 opt-in 장면에서 전투를 켠다. 적 반경별 안전한 생성/재배치, 장애물 경로 우회, 이동 구간 sweep을 적용한다. 경로를 찾지 못하면 정지하며 순간이동으로 장애물을 통과하지 않는다. 직선 경로가 막히면 제한된 격자 탐색을 사용하고 각 연결을 SafeSweep으로 인증한다. 근접·연쇄·피해 펄스·폭발은 시야가 통할 때만 피해, 회복은 벽 통과 허용. 투사체는 피해 판정보다 먼저 벽 구간 검사, 충돌 시 소멸하며 벽 너머 폭발을 만들지 않는다. 돌진은 실제 이동 구간만 접촉 피해를 준다. 레거시 장면의 계산은 변경하지 않는다.

## 변경 대상과 재사용

Assets/DeadSurvivor/Runtime/DSMap*.cs, DSGame*.cs, DSWorld*.cs, Editor의 별도 021–023 도구, 신규 Scenes/Map021 개발 장면, Tools/Verify의 통합 실행 도구. DSMapGeometry·DSMapMotion·018 메시·검증 소유 세션은 재사용한다. 기존 데이터 스키마와 r001 검증은 유지한다. 새 프로필은 별도 JSON으로 작성한다. 자료와 검증 기록은 현재 저장소 안에만 둔다.

## 실패와 복구

편집 전 깨끗한 장면·정지 상태 확인, 실제 Editor와 프로젝트를 CLI로 고정한다. 소유한 새 오브젝트/자산만 생성·정리하며 기존 장면 설정과 선택을 복원한다. 공유 폰트와 사용자 파일을 자동 저장하지 않는다. 검사 세션을 소유하지 못하면 중단하고 BLOCKED로 기록한다. 생성 실패 시 원본 장면·데이터·프리팹은 영향받지 않는다. 각 단계의 커밋으로 코드와 새 장면을 되돌릴 수 있다.

## 미정과 검토

맵의 장식 재질·장애물 최종 높이·전체 맵 인수는 후속 범위다. 이번 기본 프로필은 실험용이며 지도 확정으로 승격하지 않는다. 독립 검토 결과는 구현 전에 아래에 기록한다.

### 사전 검토 보완

- D1: 여섯 비교는 OB-001 북쪽 동일 상대 간격(각 scale에서 전면70 logical), 4인 균형형, 동일 native 화면 크기와 ortho6을 고정한다. 각 캡처에 실제 발/머리 screen 좌표·몸체 높이 px·카메라 행렬·장애물 높이/폭을 저장한다. 후보 합격은 몸체 높이40px 이상(native 화면), 파티 안전 점유, 화면 내 네 발·머리, 오류0이다. 가림은 발 위0.36world 지점으로 향한 선분과 장애물 Renderer bounds 교차 시 alpha.22, 교차 해제 시1; 지면과 경계는 제외. 축정렬 bounds의 과대 페이드는 허용하는 개발용 시각 휴리스틱이다.
- D2: DSGame의 serialized MapSession을 Awake 시작에서 초기화한 뒤 World/UI를 만든다. session은 한 Game만 bind하며 다른 Game 재바인딩을 거부한다. 맵 분기에서만 BattleWorld·UI·신설 EventSystem을 Game 하위에 소유시킨다. UI용 폰트는 map scene에서만 비공유 runtime font로 생성하고 material/atlas까지 해제한다. 원본 프리팹 geometry는 빌린 자산이며 복제 material만 해제한다. 소유 원본과 설정의 지문을 실행 전후 비교한다.
- D3: 신규 생성은 안전한 정지점과 최소 한 생존자까지의 경로 도달성을 모두 확인한다. 실패는 해당 프레임의 시도 횟수 제한으로 종료하고 Spawned는 증가시키지 않는다. 최대4회 시도/프레임, 이후 시간 유예를 두고 재시도한다. 경로 탐색 예산 초과는 도달 성공으로 취급하지 않는다. 재배치 실패는 기존 위치/ID/HP를 보존하고 나중에 재시도한다. 경로의 node/edge 캐시는 immutable geometry와 radius 단위로만 공유한다.
- D4 / 범위 결정 CH-021: 사용자의 1–3 구현 지시에 따라 I5를 완료 인수하는 대신 별도 opt-in 개발 실험을 수행한다. production 기본 장면·G4 상태·G3 필수 목록은 그대로다. 개발 장면 이름과 사용법에 EXPERIMENTAL을 표시한다. 전투 효과 원은 잠재 사거리 표시이며 차폐된 대상에게 피해를 보장하지 않는다. 맵 분기에서 원형 효과는 벽 검사를 대신하는 피해 표식으로 사용하지 않고, 명중 숫자는 실제 Hit에서만 생성한다.
