# 첫 3D 맵 구현 착수 명세

> 2026-10-31 자산 설계 연결: [A0~A5 워크플로우](../workflows/ai-3d-assets.md)와 [자산 하네스](ai-3d-asset-harness.md)를 G5 표현 적용의 선행 자산 인수로 둔다. 아래 I0~I5와 G2/G3 기본 도형 작업은 외부 생성 없이 진행 가능하다. 자산 채택은 맵 구조·충돌·카메라/성능 인수를 대신하지 않는다.

2026-10-31 KST · 개정 r001 · 작업 ID MAP-PREP-008

현재 상태: 제작 전 준비 1~4의 통합 명세. 이 문서가 정한 것은 **첫 구현에서 시험할 기준과 실행 순서**다. 실제 구현 착수·맵 동작·최종 수치 채택은 별도 상태로 관리한다. 원본 분석과 배치는 MAP-MEADOW-007/r001을 사용한다.

## 작업 브리핑

- 요구: 제작 기준을 통합하고, 첫 시험 정책·충돌 후보의 불확실성·하네스 구현 인수 조건을 구체화한다. 사용자 요구인 내부 돌/벽, 원본 구조 대응, 일관된 도면을 보존한다.
- 규모: L1 문서 통합. 기존 MP01~10의 동작 제안을 선택해 첫 시험 기준으로 묶는다. 이번에는 코드·상태 소유권·실행 데이터 스키마를 변경하지 않는다. 실제 이동/전환 구현은 L2 사전 설계 검토 대상이다.
- 산출물: 본 명세, 객체별 불확실성 대장, 최신 문서 입구/할일 정리, 입력 지문과 검증 기록.
- 규칙 소유: DSGame이 게임 상태를 소유하고, 007 layout이 준비 좌표를 소유한다. 본 문서는 아래 원본 규칙을 복사해 새로운 판정기를 만들지 않는다.
- 검증: 링크·데이터 검사, 객체/통로/정책 대조, 이전 자료 지문 보존 확인, 독립 validator-client 검토, 최종 gate. 실제 Unity·하네스는 NOT_RUN.
- 복구: 문서 연결을 이전 입구로 되돌릴 수 있다. 원본 PNG·007 layout·기존 사례 CSV·과거 검증 기록은 보존한다.

## 2. 첫 시험의 동작 결정표

아래 요약과 상세 MP 계약이 불일치하면 구현을 멈추고 문서 불일치를 먼저 수정한다. 원작 행동의 재현을 주장하지 않는다.

| 항목 | 첫 시험 선택 | 실패하면 할 일 | 근거/검사 |
|---|---|---|---|
| 풀밭·길 | 둘 다 이동 가능, 같은 속도. 바닥 무늬로 복도 강제하지 않음 | 바닥 표현과 충돌층 연결 오류 확인 | MP01/E01·05·12, MOVE03 |
| 돌·벽·식생 | C 후보와 경계가 이동을 제한. 식생/그림자는 별도 근거 없이 충돌 추가 금지 | 아래 대장에 해당 OB와 접지 불확실성 기록 | MP02/E01·15, START/BOUND |
| 파티 막힘 | 고정 슬롯·방향 유지, 생존자와 예약 슬롯의 안전한 공통 이동까지만 허용 | 관통은 FAIL, 떨림/정체/불편한 우회는 정책 재검토. 자동 축소·회전으로 숨기지 않음 | MP03~04/E04~06·09, MOVE01~05/TIME |
| 사망 | 선택 인원 수의 슬롯 유지. 시체 과거 위치와 현재 예약 슬롯 구분 | 죽은 슬롯 제거로 통로가 열리면 FAIL | MP05/E06~07, LIFE |
| 부활 | 현 진형 예약 위치 검증 후 HP·좌표·장비 상태 함께 반영 | 무효면 어떤 상태도 바꾸지 않고 이유 기록 | MP06/E07, LIFE/PREP |
| 정비 선택 | 새 진형의 목표와 전환 구간이 안전할 때 Pending만 변경 | 무효 선택은 거절하고 이전 유효 선택 보존. 취소는 현 진형을 선택하는 동작으로 구현 연결 | MP07/E04~06, PREP |
| 출발 | 상태 변경 전에 전체 재검사. 성공 후 기존 추종 경로로 새 진형에 수렴 | 실패 시 웨이브/시간/적/장비/HP/보관함/RNG 보존. 현 유효 진형 출발은 명시적 선택 | MP08/E06, PREP |
| 시간 | 정비/일시정지 전투 시간·이동 정지. 관찰기의 실제 경과시간은 기록 | 입력/검사기가 정지를 우회하면 FAIL | MP09/E05~06·16, TIME |
| 공격 | G2/G3 이동 시험에서는 적/공격을 제어된 시험 설정으로 비활성화 | 비활성 상태를 증명하지 못하면 이동 전용 실행 BLOCKED | MP10/E01·12, G4 ATTACK 전 결정 |

공통 안전 비율 α와 0입력 추종의 정확한 계약은 MP04를 따른다. 이분탐색 단조성 가정이나 캐릭터별 위치 잘라내기로 대체하지 않는다. 시작부터 겹친 상태는 자동 워프하지 않고 실패 원인으로 기록한다.

현재 코드의 `SelectFormation`은 Pending을 바로 바꾸고, `Revive`는 HP/위치를 즉시 바꾸며, `NextWave`는 보관함 삭제·Wave 증가·난수 소비 등을 먼저 수행한다. 따라서 위 조건은 **새 구현이 필요한 시험 기준**이다. NextWave는 현재 캐릭터 위치를 순간 재배치하지 않고 이후 Simulate 추종으로 전환한다. 구현 시 이 경로의 구간 안전성을 검증해야 한다.

공격의 통과/차단은 이번에 추정 확정하지 않는다. G4 작업자는 근접·부채꼴·투사체·폭발·연쇄·회복 각각에 대해 발사자/대상 위치, 벽 앞/뒤, 효과 영역/연쇄 경로, 시각 표시와 피해/회복 이벤트를 결정표로 연결해야 한다. 미결정 효과가 있으면 G4 완료는 BLOCKED다.

## 3. 충돌 후보와 불확실성 처리

[객체별 착수 대장](map-first-implementation-uncertainty.csv)은 007의 69개 등록행과 PERIM-01을 빠짐없이 연결한다. 좌표는 복사하지 않고 layout ID와 지문을 참조한다. RT 칸은 기존 관련 통로의 참조이며 완전한 영향 목록이 아니다. LC01~11과 전체 자유 지면 연결은 항상 별도 검사한다. RT가 없는 군집도 삭제/생략 대상이 아니다.

| 순서/분류 | 대상 | 첫 후보 처리 | 해소에 필요한 증거 |
|---|---|---|---|
| U0 역할 오류 예방 | OB-G01, OB-B01~04 | 부모·조사영역에서 충돌 생성 금지 | 생성 객체 목록에서 부모/조사 collider 0, 자식/경계 ID 일치 |
| U1 외곽 접합 | PERIM-01, OB008/019/030/048/064 | 경계와 군집을 별도 입력으로 유지. 합집합/틈 폐쇄를 자동 적용하지 않음 | 바닥 투영 겹침/틈, 파티 반경을 포함한 네 방향·오목/돌출 접근, 연결 성분. 시각적으로 닫힌 외곽의 새 통과 틈은 CH 판단 필요 |
| U2 곡선·원형 | OB002~004, OB060~063 | 007 띠 후보 유지, 안쪽·조각 사이 빈 공간 보존 | 안/밖 윤곽과 끝단 대조, RT001 및 원형 진입→내부→이탈, 진단 개구부 안전 |
| U3 사선·작은 군집 | OB037~044, OB009~018 | 방향/개수/밀도를 유지하며 각 C를 기본 도형 바닥으로 표현 | 사선 법선 간격·구간 이동, RT002/005와 주변 자유 지면 연결 |
| U4 나머지 군집 | 위에서 지정하지 않은 주요 OB | 기존 외피 C를 첫 비교 후보로 사용 | 각 객체 기본 도형 바닥과 C 일치, 관련 RT 및 전체 연결. 내부 빈 공간을 발견하면 별도 CH |

### 순환 의존을 피하는 채택 절차

1. G2는 치수와 정답이 알려진 독립 도형을 사용한다. 007 C 타당성이나 최종 아트가 없어도 검출기 자체를 검증할 수 있다.
2. G3의 첫 후보는 C에 맞춘 단순 도형을 만든다. **우리 시험용 바닥**으로 명시하고, 원작 접지면 복원이라고 부르지 않는다. V/U와의 차이는 계속 보인다.
3. 모든 객체·경계의 기본 도형 투영과 C를 대조하고, 구멍/접합/빈 공간·파티 통과를 검사한다. 외피 후보가 길을 막으면 스케일/몸체/정책/C 중 원인을 구분한다. 통과시키려고 C를 몰래 줄이지 않는다.
4. 대안 C는 별도 개정과 CH로 비교한다. 대상 OB/RF/RT/LC, 변경 전후, 근거 종류, 시각 차이, 영향 시험 결과를 남긴다. RF 핵심 구조를 바꾸려면 기존 사용자 요구와의 충돌을 먼저 해결한다.
5. 검토와 시험을 거친 새 실행 묶음에서만 C를 우리 기본 도형 기준으로 채택한다. 007의 역사적 BLOCKED를 소급 변경하지 않는다. G5는 최종 모델의 접지·가림을 다시 검증한다.

원작의 숨은 충돌을 끝내 알 수 없어도 우리 후보를 시험할 수 있다. 반대로 우리 기본 도형과 C가 같다는 사실만으로 원본 충실도나 실제 파티 이동을 PASS로 만들 수 없다.

## 4. 구현 순서와 인수 조건

실제 구현은 아래 순서로 별도 작업을 시작한다. I0~I5는 새 단계 통과 규칙이 아니라 G2/G3 구현을 나눈 작업 단위다. 각 단계 전체 필수 MC/FI는 원본 표를 따른다.

| 단위 | 작업과 대상 | 남겨야 하는 자료 | 다음 작업 조건 |
|---|---|---|---|
| I0 대상·계약 고정 | 개인 Unity 프로젝트와 UnityMigration 파일별 차이, Editor/패키지/씬/미저장 상태 확인. 로컬 소스와 대상의 채택 방향 결정 | 양쪽 경로·해시·차이표, 실행 대상 버전, L2 설계 브리핑과 design-reviewer 결과 | 차이를 모른 채 sync 실행 금지. 중복 상태 소유권/호환성/복구 검토 해소 |

### 상태 시나리오를 실제 사례로 펼치는 방법

007 STATE01~08은 시나리오 원본이다. 아래 축을 조합해 별도 실행 사례 ID를 만들고 원본 행 ID를 parent로 보관한다. 좌표가 없는 행을 완료된 실행 사례로 세지 않는다.

- 공통 지형: 먼저 G2 정상/무효 도형, 이후 G3의 RT005 사선·RT006 원형 진입·네 방향 경계(RT012~015). 각 위치는 후보 도형과 실제/예약 슬롯의 유효성을 계산해 등록한다.
- 인원/진형: 기존 시나리오의 4인 × 현 진형0/1/2를 기본으로 전개. 실제 지형의 부활·정비 인수에는 1~3인 경계 사례도 추가하며 기존005의 범위를 대체하지 않는다.
- 전환: 선택을 포함한 행은 예정 진형0/1/2, 같은 진형 재선택, 유효/무효 전환을 포함한다. 죽음/부활은 각 슬롯을 한 번씩 대상으로 하고 전멸은 기존 결과 흐름 회귀로 별도 지정한다.
- 시간: 정상 프레임, .05 전후 원프레임 dt, 지원 배속, 남은 웨이브 시간 잘림, 정지 후 반전. Config.speed 적용 전후를 혼동하지 않는다.
- 식별: `parent/terrain/pose/N/F/P/deadSlot/timing/variant`를 유일 키로 사용한다. 적용 불가 조합은 실행 전 이유를 기록한다. 생성 수·유일 수·제외 수·실행 수를 따로 보고한다.

| parent | 원본 순서 | 특별히 동결할 조건 |
|---|---|---|
| STATE01 | 부활→예정 선택→출발 | 부활은 현 진형, 이후 새 진형 전환 안전 |
| STATE02 | 예정 선택→부활→출발 | 출발 시 재검사, 생존자 상태 변화 이후에도 안전 |
| STATE03 | 예정 선택→취소→출발 | 취소 입력의 실제 UI/게임 연결, 현 진형 보존 |
| STATE04 | 무효 Pending 선택 | 기존 선택 유효 대조군과 무효 선택, 오류 이유 및 출발 가능성 |
| STATE05 | 출발 직전 조건 무효화 | 격리 fixture에서만 실패 주입, 최초 변경 전 거부·RNG까지 불변 |

| STATE08 | 정비 중 입력/선택/부활/취소 | 전투 시간과 위치 고정, 명시적 부활 위치 변경은 별도 사건 |

자연 지형에 ‘현재 유효/예정 무효’ 위치가 없는 조합은 임의의 벽을 실제 맵에 추가해 만들지 않는다. 격리 도형에서 거부 동작을 검증하고 실제 맵에서 해당 조합 적용 불가의 기하 근거를 기록한다. 검사가 실패한 뒤 제외로 바꾸는 것은 금지한다.

HR-ROUTE/CONTINUOUS의 입력 생성·고정 재생은 007 계약을 따른다. 원형은 RT006→RT018→역RT008의 전체 연속열과 그 역방향을 검사하며 중간 초기화하지 않는다. 목표 좌표만으로 입력열이 동결됐다고 보고하지 않는다.

## 6. 이번 준비 작업의 완료 기준

- 최신 입구와 할일이 이 명세를 가리키며 과거 준비 성과와 런타임 미완료가 혼동되지 않는다.
- MP01~10마다 첫 시험 선택/근거/반증을 찾을 수 있다. 미정 공격 정책을 자동 기본값으로 만들지 않는다.
- 69개 등록행+PERIM-01이 대장에 존재하고, 기존 RT 참조가 맞으며, U별 조치·기한·검사가 있다.
- I0~I5의 선후관계·필수 증거·복구·미정 해소 시점이 연결된다. 전체 MC/FI가 축소되지 않는다.
- 독립 검토 지적을 해소하고 현재 파일로 gate PASS를 기록한다. 실제 G1 전체/G2~G5는 별도 인수 전까지 완료로 승격하지 않는다.

다음 실제 구현 요청에서 시작할 작업은 **I0 대상 차이 확인과 L2 브리핑**, 이후 **I1~I2 실행/검출 도구**다. 추가 레퍼런스 탐색·최종 모델·장식 이미지 반복 생성은 착수 선행 조건이 아니다.

구체화 후속(2026-10-31): [MAP-HARNESS-009 구현 설계](map-harness-implementation.md)에 I0~I3의 코드 연결·입력 소유권·기하 판정·데이터·복구를 작성했다. 해당 설계의 검토 상태를 확인하고 구현한다. 본 명세의 I4/I5 보정·전체 인수 조건은 유지한다.
