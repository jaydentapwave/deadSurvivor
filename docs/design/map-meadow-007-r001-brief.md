# MAP-MEADOW-007 r001 — 근거 기반 준비 1~4 설계 브리핑

- 상태: 설계 검토 중. 제작 전 문서·배치 후보 데이터만 작성. Unity/맵 하네스 구현 없음.
- 규모: L2. 공통 배치 원본과 증거 연결 자료를 신설하고, 향후 이동 판정 책임을 설계하기 때문.
- 요구: 이동·장애물 정책, 공통 맵/윤곽 후보, 크기 결정 시험, 하네스 명세 모두 근거 추적 가능하게 구축. 레퍼런스가 입증하지 않는 원작 동작을 사실로 만들지 않음.
- 확정 방향: Verdant Meadows의 내부 군집·곡선·사선·끊어진 원형·불규칙 경계 보존. 제작 보류. 네 판은 같은 원본에서 표현.
- 근거: 로컬 원본 PNG REF-VM-001; 005의 주요 군집 64개/조사 4개/부모 1개와 17통로; 006의 변환식/RT018; DSGame.Formation/Combat/Run/Inventory; Unity 공식 Camera/CCD/Test Framework 문서. wiki 현재 직접 조회 403, 기존 원본은 로컬 직접 확인.
- 변경: 007 근거대장·정책/보정/하네스 문서, 공통 layout JSON과 네 판 SVG, 사례 추가 CSV. 기존 005/006 데이터는 보존하고 최신 진입 링크만 갱신.
- 소유: DSGame의 생사·진형·시간·입력 상태는 기존 단일 소유 유지. 새 layout은 준비용 후보이며 게임 콘텐츠 JSON이나 Unity 자산의 새 원본으로 자동 승격하지 않음. 그림의 V와 우리 게임용 C 제안, 바닥을 모르는 U를 구분.
- 설계 후보: 고정 방향/슬롯 유지, 이동 불가능한 요청은 파티 전체 안전 이동량으로 제한하는 보수적 기준안. 기존 개별 Lerp의 실제 위치 구간까지 검사 필요. 죽은 슬롯 예약 유지. 정비 진형 변경과 부활은 다음 진형까지 유효한 영역에서 원자적 전환하도록 제안. 상세 한계·거부 처리 문서화 예정. 원작에서 배운 동작이라는 주장은 금지.
- 윤곽: 원본을 직접 보고 수작업 다각형 후보 작성. bbox를 자동 충돌화하지 않음. V는 거친 관찰선, C는 그 관찰을 토대로 한 시험 후보, U는 가려진 접지/그림자·식생에 의한 불확실성. 정확한 원작 충돌/측량이라고 표시하지 않음.
- 실패/복구: 입력·초기 위치·관찰 부족 시 성공 금지. 게임 상태를 시험기가 복제 계산하지 않고 실제 전후 상태 관찰. 격리 시험 상태만 복구하며 사용자 씬/파일 강제 복구 금지. 중단·실패 별도 상태.
- 검증: 로컬 문서 검사, 원본 대비 네 판 시각 확인, JSON/CSV ID·좌표·도형 위상·경로 연속성·지문 검사. 독립 설계 및 최종 검토. 계산식은 독립 로직 검토. Unity 실행 NOT_RUN.
- 미정: 실제 신체 반경·카메라 높이·맵 스케일·오차/시간 기준은 보정 실험으로 결정. 원작 수치 출처 없음. 근거가 있는 실험 방법을 설계하며 최종 판정을 BLOCKED로 유지.
- 재사용: 기존 규격·사례군/FI-01~10·변환식을 사용, 새 런타임 API/패키지 강제 도입 없음.
- 호환/복구: 기존 파일 삭제/동기화 없음. 007 준비 파일은 별도 개정. 사례는 005 372건을 덮어쓰지 않고 추가 계획으로 연결.
- DR-01 반영: 정비에서 유효하지 않은 예정 진형 선택을 거부하고 기존 유효 선택/현 진형을 유지한다. NextWave의 Wave 증가·시간 초기화·적 제거 전에 전환 전체를 사전 검사한다. 출발 시 재검사 실패에는 현 유효 진형으로 출발하는 명시적 대안을 제공하며 자동 워프/진형 변경은 하지 않는다.
- DR-02 반영: 부활은 현 Formation의 예약 슬롯, 변경은 PendingFormation으로 구분. 실제 위치→현/예정 목표의 추종 구간을 검사하며 부활→변경, 변경→부활, 취소 순서별 사례를 등록한다. 현 진형까지 무효한 오염 상태는 정상 조작 교착과 구분해 진단 중단한다.
- DR-03 반영: 각 객체에 C 제안 이유·U 범위·판정 상태를 기록한다. 보이는 외피를 시험용 보수적 C 후보로 쓰는 경우에도 원작 접지 윤곽과 구분하며 통로 폭/충돌 타당성은 BLOCKED 유지. 네 판 일관성 통과와 지형 해석 통과는 별개다. 후보 좌표 작성 완료를 G1/G3 전체 통과로 보고하지 않는다.
- 설계 검토: 1차 CHANGE_REQUIRED(DR-01~03) → 보완 재검토 PASS. 실제 산출물 최종 검토는 별도.
