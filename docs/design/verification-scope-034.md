# VERIFICATION-SCOPE-034 — 변경 범위에 따른 gate

2026-11-01 · L2 · 독립 사전 설계 PASS 후 구현. 사용자 요청: 기존 필수 검사를 재검토해 중복/무관한 실행을 줄이고 workflow와 gate를 실제로 개선한다.

## 산출물·범위

같은 gate 명령에서 검사별 RUN/REUSE와 이유·의존 지문·원자료를 확인할 수 있게 한다. 문서만 바뀌면 문서 검사만 새로 실행하고 데이터/H1/007 준비는 같은 입력으로 통과한 근거를 확인한다. gate가 Unity를 자동 조작하지 않는 계약, Stop의 조용한 기록, pre-commit 인덱스 일치, 원본·소스 안정성·경로 검사는 유지한다. 설치 baseline은 변경하지 않는다.

게임 코드/씬/기하·자산 제출·빌드·전체 N1 하네스는 변경하지 않는다. 메인이 구현하며 독립 사전 설계/최종 구현 검토를 받는다. 새 자동화 서버·일반 의존성 프레임워크는 만들지 않는다.

## 검사 재분류

| 검사 | 실행/인수 조건 |
|---|---|
| 입력·경로·실행 전후 안정성 | 매번. pre-commit은 현재 전체 입력과 인덱스 일치도 확인 |
| 문서 링크 | Markdown 내용/파일 집합 또는 참조 대상 존재 상태, 문서 검사기/선택기 변경 시 실행 |
| 콘텐츠 ID/참조 | PrototypeData 또는 해당 검사기/선택기 변경 시 실행 |
| H1 8개 기초 | fixture·map_check/map_io/map_oracle·경로 정책/선택기 변경 시 실행 |
| MAP007 준비 151+내보내기 확인 | 활성 맵 정책/입력/도면·PNG·출력기·검사기 변경 시 실행 |
| Unity 기본 회귀 | 실제 Unity 대상·검증 템플릿 또는 실제 Unity 수집기 변경 시 현재 의존 지문 증거 필요 |
| 다중 해상도 화면 | UI/씬/자산/설정/알 수 없는 Unity 변경 또는 유효한 같은 시각 의존성의 이전 전체 화면 근거 없음 |
| 전수 topology·전체 Python·전체 부하 | 변경과 관련된 경우 workflow가 선택. gate가 매번 자동 추가하지 않음. 전체 단계 인수 요건은 유지 |

첫 실행/근거 누락/손상/검사기 변경 시 해당 정적 검사는 새로 실행한다. 출력에 상태 PASS만 쓰지 않고 action RUN/REUSE, 실행된 검사/재사용된 검사, 원자료 경로/해시를 구분한다.

## 정적 근거 재사용 계약

- 새 gate 형식에서 성공한 실행만 사용한다. 검사별 전체 의존 맵(파일 추가/삭제/바이트/실행 모드, Python 버전, 선택기/판정기 지문)을 비교한다.
- 문서 검사는 ignored output 링크 대상의 존재 변화도 포함한다. 입력이 아닌 원자료 내용의 변화는 해당 증거의 별도 해시 검증이 담당한다.
- cache는 설치 baseline 재설정이 아니라 실제 실행 결과다. 기존 legacy gate는 정적 캐시로 자동 승인하지 않는다. 첫 회는 필요한 정적 검사를 실행한다.
- 검사 결과를 고유 파일로 보존하고 재사용 때 원자료 SHA/상태/의존 맵을 확인한다. 재사용된 결과도 원래 실행 파일을 직접 가리키며 무한 receipt 연결을 만들지 않는다.
- 실패·빈 결과·최종 소스 변경은 성공 cache를 만들지 않는다. 동일 의존성의 더 최근 실패를 과거 PASS로 덮지 않는다. 근거가 없으면 실행하며 건너뛴 것을 새 시험 PASS로 표시하지 않는다.

## Unity 증거·화면 범위

현재 모든 Tools/Verify Python 파일을 동등하게 비교하는 대신 실제 수집 경로 run.py·unity_check.py·gate_support.py·Tools/project_paths.py를 비교한다. gate/판정기 수정은 보존된 원자료를 새 판정기로 다시 검증하며 그 이유만으로 Unity 실행을 요구하지 않는다. 런타임/템플릿은 전체 지문으로 여전히 일치해야 한다.

기존 보고서의 수집 시점 전체 verifiers 목록에서 위 키를 비교하므로 과거 JSON을 다시 쓰지 않는다. 누락되거나 알 수 없는 context는 거부한다. before/after 자체 일치, 실제 프로젝트, compile·rules·실제 frame 증가·입력·기본 캡처·console·cleanup·모든 원자료 해시는 항상 확인한다.

화면 범위 감소는 좁은 허용 목록의 계산 파일(.cs)만 변한 경우로 한정한다. 초기 목록은 DSGame.Combat, DSGame.EquipmentCombat, DSGame.Stats, EquipmentRules, DSMapGeometry, DSMapMotion, DSMapNavigation이며 실제 파일 존재를 확인한다. 데이터/메타·UI/World·일반 Game 초기화/흐름·Editor/자산/설정/추가 파일 등 미분류 변경은 전체 화면을 요구한다.

기본 회귀만 인수하려면 유효한 과거 전체 화면 실행을 새 판정기로 검증하고, 현재와 과거 runtime 차이가 위 계산 파일 안에만 있는지 확인한다. 현재 기본 회귀 자체는 모든 현재 runtime 지문과 일치해야 한다. 전체 화면 근거 없으면 전체 화면을 요구한다. 최신 현재 입력의 실패를 오래된 PASS로 숨기지 않는다. 기존 전체 화면 보고서는 기본보다 강한 증거로 인수할 수 있다. 현재 전체/실기기/맵 인수를 새로 완료했다고 주장하지 않는다.

## 구현과 검증

변경 파일: gate.py, 새 gate_scope.py/gate_evidence.py, 관련 test_gate/test_gate_scope, workflow/검증절차/034 리뷰. run.py·unity_check.py·gate_support.py와 gate-policy baseline은 보존한다. 기존 gate_support의 수집 함수와 legacy 판정 함수는 원문 그대로 유지하며 gate는 분리된 gate_evidence의 현재 판정을 사용한다. 활성 맵 산출물은 변경하지 않는다.

최소 시험: 문서만/데이터/기하/PNG·layout/삭제·미분류 변경의 선택, 캐시 손상·더 최근 실패·새 checker 변경, 런타임 누락/변조·현재 지문·기본/전체 화면 조건, 기존 Stop/pre-commit·중간 소스/인덱스 변경 회귀. 실제 프로젝트에서 첫 gate와 문서 변경 후 gate를 실행해 무관한 검사 재실행 0 및 기존 Unity 증거의 현재 판정 확인. 관련 unit은 한 묶음으로 실행하고 지적/실패 영향만 재실행한다. 이 선택기는 게임 기하 계산을 바꾸지 않으므로 별도 algorithm-tester는 해당 없음.

실패 시 현재 결과를 보존하고 해당 검사/근거를 수정한다. 새 선택기 때문에 필요한 증거가 부족하면 BLOCKED이며 기준/설치 baseline으로 회피하지 않는다. 기존 미커밋 작업은 시작 지문/원문을 보존하고 이번 diff만 수정한다. 실제 효과는 검사별 실행 수와 action으로 보고하며 토큰/전체 작업 시간 절감률은 추정하지 않는다.

구현 결과와 최종 근거는 [034 검토 기록](../reviews/verification-scope-034-review.md)에 남긴다. 같은 시각 입력의 최신 전체 화면 실패도 이전 화면 PASS 재사용을 막는다.
