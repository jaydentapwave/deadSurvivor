저장소 루트에서 실행한다.

```sh
python3 Tools/Verify/run.py local
python3 Tools/Verify/run.py all
python3 Tools/Verify/map_check.py oracle-selftest
python3 UnityMigration/sync.py
```

local은 문서 링크/데이터 ID·참조/독립 기하 분석 검사다. `oracle-selftest`는 분석별 원자료와 현재 입력·모듈 지문을 별도 고유 폴더에 남기며 출력의 `unity_status`는 NOT_RUN이다. 전체 `run.py map --mode prepare|run|judge`는 아직 지원하지 않는다. all은 개인 Unity 프로젝트의 컴파일, 실제 프레임, 규칙, 드래그/회전/상세/탭, 시간 구간, 콘솔, 캡처까지 수행한다. Unity 에디터에서 지정된 씬이 열려 있고 중지 상태이며 미저장 씬이 없어야 한다. scene/domain reload 비활성 환경은 중단한다. Unity CLI 연결 문제는 별도 오류로 보고하며 다른 프로젝트를 사용하지 않는다.

동기화는 기본 읽기 전용 비교다. 적용하려면 `python3 UnityMigration/sync.py --apply --baseline <이전 실행의 summary.json>`을 사용한다. 대상 파일이 기준 지문과 다르면 모든 복사를 시작하기 전에 중단한다. 새 C# 파일은 추가하지만 삭제 전파와 .meta 덮어쓰기는 하지 않는다. 코드/JSON 외 자산은 자동 동기화 범위 밖이다.

결과는 output/verification/실행ID에 저장된다. 실행 전 소스 지문과 실행 후 동일성을 확인한다. Unity 원본과 저작본의 C# 파일 집합 및 내용, JSON도 비교한다. 종료코드0은 필수 자동 검사 통과,1은 실패,2는 환경/미실행 문제다. 직접 시작한 플레이만 종료하고 종료 오류와 설정 복구 오류를 따로 보존한다.

기본 stdout은 짧은 상태 요약이며 전체 보고서 구조·검사·종료 코드는 유지한다. `run.py local --verbose`처럼 기존 명령에 `--verbose`를 붙이면 상세 결과를 출력한다. 저장 보고서는 `python3 Tools/Verify/report.py <보고서 경로>`로 요약, `--check unity.cleanup`처럼 필요한 항목만 조회한다. 이 조회는 새 검증을 실행하거나 과거 증거를 현재 PASS로 승인하지 않는다. 실패/미실행 항목이 많으면 생략 개수를 표시하고 전체 보고서에 모두 남긴다.

검증 순서는 [개발 워크플로우](workflows/development.md)의 작은 시험 → 독립 코드 검토/수정 → 통합·최종 Unity → 독립 증거 확인 → 문서/local/gate를 따른다. 이후 영향 변경이 있으면 필요한 검사를 다시 실행한다.

화면 캡처는 자동 생성 후 사람이거나 에이전트가 직접 확인해야 한다. 캡처 파일 존재만으로 시각 품질을 PASS로 판정하지 않는다. 실제 모바일 성능·물리 터치·밸런스·재미는 별도다. CLI 인자는 설치된 Pipeline 명령에서 확인한 형식이며 버전 변경 시 재확인한다.

## 후속 검사 옵션

- `python3 Tools/Verify/run.py all --screens`: 3개 실제 GameView 크기, 해상도별 입력, 24화면(안전 영역 모의·전투 아이템·최대 장착 포함), 원래 설정 복구 확인.
- `python3 Tools/Verify/run.py all --experiments`: 고정 정책/시드/뷰포트의3진형18회 재현 검사.
- `python3 Tools/Verify/run.py all --experiments --loadouts`: 추가로32종×3시드96쌍192회 초기 장비 비교. 실행 시간이 더 길다. 각 쌍을 동일조건 두 번 반복한 검사와 구분한다.
- `python3 Tools/Verify/balance_audit.py --loadouts output/verification/<실행ID>/unity/loadouts.json`: 데이터 지문이 같은 원자료만 분석한다.

화면 검사는 실제RT·Canvas·UI크기와 후속 프레임을 확인한다. CLI 평가 문맥의 native Screen값만으로 해상도를 판정하지 않는다. 원래 GameView 선택·크기 목록·Simulator상태를 복구하며 실패는 전체 FAIL이다. 다중 Simulator는 정확한 복구를 보장할 수 없어 변경 전에 차단한다. 물리기기의 안전 영역/터치/성능을 증명하지 않는다.
