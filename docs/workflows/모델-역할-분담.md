# 모델 역할 분담

2026-11-23 사용자 결정: "6.2로 변경을해주고 너가판단했을떄 cluade opus 5.5가 더 잘할것 같은 부분은 그쪽에게 맡기도록하고 문서로 남겨줘".

이 문서가 누가 무엇을 맡는지의 원본이다. `CLAUDE.md` "모델·추론 강도와 리뷰 담당"과 `AGENTS.md`는 이 문서를 가리킨다.

## 1. 모델

| 쪽 | 모델 | 추론 | 어디에 적혀 있나 |
|---|---|---|---|
| 디렉터(사람과 대화하는 세션) | 사용자가 켠 모델 그대로 | 사용자 설정 | — |
| Codex(구현·생산, 중계 리뷰, 판독) | `gpt-6.2-astra` (2026-11-23부터. 그 전 `gpt-6.1-sol`) | medium | `Tools/codex_review.py`의 `MODEL`, `Tools/hd2d_judge.py`의 `CODEX`, 실행기 `codex-step.py --model gpt-6.2-astra --effort medium`, 대기열 `--executor codex --model gpt-6.2-astra --effort medium` |

- 사용자는 "6.2"라고만 했다. 이 컴퓨터의 Codex에서 확인된 6.2 모델은 `gpt-6.2-astra` 하나였고(`~/.codex/config.toml`의 기본 모델과 같음) 짧은 호출이 정상 응답했다. 다른 6.2 모델을 뜻했다면 위 표의 자리만 바꾸면 된다.
- `~/.codex/config.toml`(다른 프로젝트와 같이 쓰는 설정)은 바꾸지 않는다.

## 3. 어떻게 걸려 있나

- 리뷰 에이전트 3종(`.claude/agents/spec-reviewer.md`, `validator-client.md`, `design-reviewer.md`)은 0번 단계에서 `DIRECTOR_MADE_BY`를 본다. `codex`이면 Opus 5.5가 `.ai/reviewers/<역할>.md` 지침대로 직접 리뷰하고 판정 줄 끝에 `(리뷰: Claude Opus 5.5 — 구현이 Codex)`를 붙인다. 그 밖에는 예전처럼 `Tools/codex_review.py`로 Codex에 중계한다. Codex 실행기(`codex-step.py`)가 리뷰 세션에 `DIRECTOR_MADE_BY=codex`를 넣는다.
- `algorithm-tester`는 늘 Codex 중계다.
- 디렉터가 단계를 띄울 때: 위 표에서 Opus 5.5 몫인 단계는 `Tools/claude_medium.sh -p …`로, 나머지 구현 단계는 `codex-step.py --model gpt-6.2-astra --effort medium`으로 띄운다. 지시문과 실행 기록에 맡는 쪽과 표의 어느 행인지 한 줄 적는다.
- studio-kit을 다시 깔거나 올리면 `.claude/agents/`가 덮어써질 수 있다. 그때 이 문서대로 되돌린다.

## 4. 확인한 것과 못 한 것 (2026-11-23)

- 확인: `gpt-6.2-astra` 짧은 호출 응답, `Tools/codex_review.py selftest` 통과.
- 미확인: 바뀐 리뷰 에이전트가 실제 Codex 단계 마감에서 직접 리뷰로 도는지(다음 Codex 단계에서 판정 줄 끝 표시로 확인한다). 11-23 밤 실행의 마지막 단계는 바꾸기 전 설정(작업 트리 사본, `gpt-6.1-sol`)으로 돌았다.
