# 맵 산출물 일관성 규격 v1.1

2026-10-31. v1 도면 규격을 유지하고 v1.1에서 G5 자산 연결 계약을 보충했다. [개발 절차](development.md)와 [레퍼런스 절차](reference-design.md)를 유지한다. 007 준비 자료 검사와 H1 기초 기하 분석은 구현돼 있다. 규격 전체의 의미/시각 자동 판정과 실제 Unity 맵 하네스는 미구현이다. 이 규격은 동일한 결과물을 반복 생성한다는 보장이 아니라 **동일한 기준으로 작성·비교·검증하기 위한 계약**이다.

## 작업 묶음의 고정 구성

매 작업은 [작업 묶음 양식](../templates/map-work-package.md)을 사용한다. 작성 순서는 요구/범위 → 입력/지문 → 유지/변경 → 도면/객체 → 사례/기준 → 결과/차이 → 다음 단계다. 없는 항목을 삭제하지 말고 미정·미실행 사유를 남긴다.

| 구성 | 반드시 있는 내용 | 없을 때 |
|---|---|---|
| 작업 표지 | 작업 ID, 버전, 상태, 범위, 이전 버전, 변경 이유 | 형식 FAIL |
| 입력 목록 | 실제 참조 파일·출처·해상도·지문, 제안/관찰 구분 | 출처 확인 불가 범위 BLOCKED |
| 대응표 | 특징 ID→원본 위치→설계 요소→사례→증거 | 핵심 특징 누락 FAIL |
| 도면 | 고정 배치·범례·방향·축척 상태·버전 | 판독/버전 불명 FAIL |
| 변경표 | 변경 ID, 대상 ID, 전후, 이유, 영향 사례 | 승인된 조건과 달라졌으나 기록 없음 FAIL |
| 검증 계획/결과 | 예상 사례, 기준 버전, 상태, 원자료 | 미실행을 합격으로 표현하면 FAIL |

## 파일·ID·상태

- 새 작업은 `MAP-<주제>-<번호>`, 산출물은 `r001`처럼 증가하는 개정 번호를 사용한다. 예: MAP-MEADOW-005. 실제 생성 시 사용하며 예시 ID를 실행 증거로 취급하지 않는다.
- 문서·도면·객체표·프롬프트는 같은 작업 ID와 개정을 표지에 기록한다. 파일 예시: `map-meadow-005-r001-plan.png`. 같은 최종 파일을 조용히 덮어쓰지 않고 r002로 남긴다. 제작 중 초안 수정은 변경 이력으로 관리한다.
- 자료 ID REF, 특징 ID RF, 객체 ID OB, 통로 ID RT, 사례 ID MC, 실패주입 ID FI, 변경 ID CH를 구분한다. T1~T6은 04의 검증 지역 별칭이며 통로·객체 ID를 대신하지 않는다.
- 객체 삭제·분할·통합 시 옛 ID를 재사용하지 않는다. 새 ID와 이전 ID 관계, 이유를 기록한다. 객체 개수 비교에는 분할 관계를 고려한다.
- 작업 상태는 초안/검토중/검토완료/대체됨, 게임 적용 상태는 미구현/시험중/검증완료를 분리한다. 문서 검토완료가 게임 검증완료를 뜻하지 않는다.
- 01~04는 기존 이름을 유지하고 과거 자산으로 보존한다. v1 규격에 소급 적합 판정하지 않는다. 다음 실물 도면부터 적용하고 그 전에는 부족한 항목을 대응표에 명시한다.

## 도면 표현

| 항목 | 기본 규격 |
|---|---|
| 시트 | 가로 4:3, 기본 출력 2400×1800 px. 정밀 지도 영역의 원래 종횡비는 유지하고 남는 공간은 여백으로 사용 |
| 배치 | 왼쪽 75% 지도 영역, 오른쪽 25% 제목·범례·변경 요약, 바깥 48px 여백. 지도 바닥에 본문을 길게 덮지 않음 |
| 시점 | 전체 도면은 수직 정사영. 3D 화면은 별도 판으로 카메라 정보를 표시 |
| 방향 | 원본 위쪽을 도면 위쪽으로 유지. 실제 방위 미확인 시 N 화살표 금지 |
| 글자 | 제목 48px, 영역명 28px, 주석 최소 24px(기본 출력 기준). 같은 글꼴 계열, 한국어 판독 확인 |
| 색 | 종이 #F5F1E7, 선 #203248, 지면 #C9D5B4, 길 #A9BCC4, 장애물 #777B78, 시험 #D89524 |
| 선·기호 | 지형 실선 3px, 후보 점선 2px, 변경 테두리 4px. 색만으로 구분하지 않고 실선/점선/ID·해칭 병행 |
| 표식 | P 시작 후보, T 지역, OB 객체, RT 통로. 지점이 정확하지 않으면 원 또는 영역으로 표시하고 ‘후보’ 명시 |
| 축척 | 미정이면 ‘비례 개념도 · 축척 미정’. 실측 도면에는 단위·변환·정밀도 표시. 임의 미터/100U 재도입 금지 |
| 표제란 | 작업ID/개정/도면종류/상태/날짜/입력 개정/원본 출처/충돌 검증 여부 |

수치는 작업물 표현의 기본 제안값으로 v1에서 고정한다. 다른 화면/출력 요구가 생기면 규격 개정을 남긴다. 지도 구조를 레이아웃에 맞춰 늘이거나 장애물을 삭제하지 않는다. 같은 범위를 비교하는 판은 지도 크기·방향·여백·카메라를 고정하고 달라진 조건을 표시한다.

### 같은 지도에서 분리할 네 판

1. 구조판: 실제 시각 형태·지형 ID·길. 충돌을 암시하지 않는다.
2. 충돌 후보판: 구조를 흐리게 유지하고 이동 차단 후보와 여유 공간 표시. 후보/확정 구분.
3. 시험판: 같은 배치에 P/T/RT와 실제 입력 경로·도착 영역 표시. 아직 없는 좌표를 지어내지 않는다.
4. 변경판: 이전과 현재를 같은 변환으로 비교하고 CH 표식만 추가. 정렬 변환과 제외 영역을 기록한다.

모든 판은 동일한 배치 원본을 사용한다. 각각을 이미지 생성으로 새로 만들어 객체가 바뀌게 하지 않는다. 이미지 생성은 외형 시안/스타일 탐색용으로 유지하되, 정확한 좌표·문자·치수·시험 경로를 요구하는 판은 후속 제작에서 공통 배치 데이터로 그리도록 설계한다. 생성 이미지의 문구·크기·객체 위치가 규격과 다르면 수정 또는 비규격 시안 표시 없이 최종 판으로 통과시키지 않는다. 007 준비 개정에서는 [공통 후보 배치와 네 판](../design/map-meadow-007-r001-spatial.md)을 작성했다. 이 출력은 준비 도면용이며 실제 게임 자산/충돌/실행 하네스는 미구현이다.

## 좌표와 측정의 일관성

등록부의 첫 적용 예는 [MAP-MEADOW-005 r001](../design/map-meadow-005-r001-package.md)이다. 객체 검색 박스·정확한 실루엣·충돌 윤곽을 구분하고, 통로 경유점은 후보로 기록한다. 외곽 조사 영역과 상위 묶음은 개별 장애물 수에서 제외한다. 사례 목록은 실행 상태(NOT_RUN)와 실행 준비(BLOCKED)를 별도 칸으로 관리한다. 이 등록 작업만으로 산출물 네 판이나 실행 하네스가 만들어졌다고 보고하지 않는다.

원본의 참조 좌표는 전체 이미지 왼쪽 위 (0,0), 오른쪽 아래 (1,1)인 정규화 좌표로 통일한다. 원본 픽셀 해상도·자르기 범위를 함께 기록한다. 이는 참조 위치이며 월드 좌표가 아니다. 월드 변환은 스케일·원점·축 방향·회전·단위를 별도 승인된 설계에 기록한 뒤 적용한다. 도면을 새로 자르면 변환 개정과 지문도 바꾼다.

밀도는 ‘많아 보인다’만으로 끝내지 않는다. 개별 객체 등록 후 동일 영역별 군집 수·시각 점유율·주요 방향·열린 공간 연결을 비교하도록 설계한다. 식생 면적과 충돌 면적은 따로 센다. 허용 차이는 기준값으로 정하며 현재 미정이다. 단일 이미지 유사도 점수로 구조 합격을 대체하지 않는다.

## 변경 통제와 인수

### G5 외부 3D 자산 연결

[자산 워크플로우](ai-3d-assets.md)의 A5 채택본을 사용한다. 자료 형식 원본은 [자산 하네스 계약](../design/ai-3d-asset-harness.md)이며 map request v1와 별도의 map-bindings sidecar를 계획한다. 현재 연결 검사기는 미구현이다.

- OB마다 asset ID/개정/acceptance·프리팹·의존 파일 지문, 실제 배치 변환, map/layout/C/변환 개정, RF/RT/영향 MC를 연결한다. 같은 자산을 여러 군집에 쓸 때도 OB별 배치를 기록한다.
- 시각 모델 V가 C·U·통로를 재정의하지 않는다. 장식은 비충돌 이유/부모를 명시한다. 생성 MeshCollider를 승인된 C로 간주하지 않는다.
- A4의 자산 비교와 G5의 실제 맵 MC-CAMERA-01/MC-PERF-01을 구분한다. G5에서는 기존 필수 동작 검사와 자산 연결 AC-10도 필요하다.
- 구조/충돌이 달라지면 맵 CH/개정/사례를 갱신한다. 텍스처만 바뀌어도 관련 시각/성능/의존 지문을 다시 확인한다. 기준이 없는 형식적 asset 승인이나 과거 바위 전송 기록으로 채택을 대신하지 않는다.

### 변경 영향과 인수 증거

구조·충돌·표현·시험 중 무엇을 바꾸는지 CH마다 표시하고 영향을 받는 RF/OB/RT/MC를 연결한다. 작은 선화 수정은 게임 시험 전체를 재실행할 이유가 없지만, 군집 이동·충돌 변경은 관련 통로·생성·공격을 다시 검사한다. 영향을 판정할 자료가 없으면 범위를 넓혀 검토하고 누락된 것으로 보류한다.

완료 인수에는 형식 확인, 원본과 시각 비교, 변경표, 해당 단계 필수 검사 결과가 필요하다. 독립 리뷰는 development.md의 규모에 따라 수행한다. 핵심 구조 변경이 사용자 요구와 충돌하면 기존 승인 유무를 확인하고 방향 변경으로 설명한다. 단순 규격 준수 작업마다 사용자 확인을 추가하지 않는다.
