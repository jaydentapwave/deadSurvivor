# 장면 빌더 공통 규칙

장면·자산을 코드로 다시 만드는 빌더(`Tools/Map/build_*.cs`, `Tools/Proto/build_*.cs`)에 공통으로 적용한다. [핵심 규칙](core-rules.md)이 우선한다. 근거는 [046 놓친 것](../design/map-full-046.md#놓친-것)과 [047 기록](../reviews/combat-fx-047-log.md#에러문제-상황)이며, 2026-11-03 [048 하네스 갱신](../reviews/harness-update-048.md)에서 모았다.

## 1. 장면 소유와 순서 (047 H3, 047-E3, 046-12)

- 한 장면은 **소유 빌더** 하나가 만든다. 다른 빌더가 같은 장면에 붙이는 것(액터 세트, 효과, 밤 화면 등)은 소유 빌더가 다시 붙인다. 지금 `Map046_Full`은 `build_map_046.cs`가 소유하고 `build_monsters_046.cs`(액터 세트)·`build_fx_047.cs`(효과·밤)의 결과를 다시 붙인다.
- 다시 만드는 순서는 그 장면의 기록 문서에 한 줄로 적는다. 예: [047 "다시 만들기 순서"](../reviews/combat-fx-047-log.md#만든-것).
- 새 빌더가 소유 장면을 고치면 소유 빌더의 다시 붙이기 목록에도 넣는다. 넣지 않으면 다음 전체 빌드에서 조용히 사라진다.

## 2. 저장 뒤 다시 열어 확인 (046-12)

- 빌더는 장면을 저장한 뒤 **다시 열어** 핵심 참조(액터 세트, 효과 재질, 조명 등)가 실제로 저장됐는지 확인하고, 아니면 예외로 멈춘다. 예: `ACTORS_NOT_SAVED`, `FX_NOT_SAVED`, `DAYNIGHT_NOT_SAVED`.
- 메시·재질 처리 뒤에는 저장된 프리팹을 다시 읽어 잰다([자산 워크플로우](ai-3d-assets.md#파일-보존가져오기복구)와 같다).

## 3. GUID 유지 (047 H13, 047-E11)

- 다시 만드는 빌더는 장면 파일을 지우고 새로 복사하지 않는다. 같은 경로에 **내용만 덮어써** GUID를 유지하고, GUID가 바뀌면 멈춘다(`build_map_046.cs`의 `SCENE_GUID_CHANGED`).
- 빌드 설정의 장면 경로·GUID 일치는 gate 정적 검사 `refs`가 본다(`python3 Tools/Verify/run.py refs`).
- 남은 일: `build_monsters_046.cs`·`build_fx_047.cs`는 자기 자산 폴더를 지우고 다시 만들어 재질·프리팹 GUID가 바뀐다. 지금은 그 자산을 가리키는 쪽(장면)을 같은 빌더가 다시 연결하므로 결함은 아니다. 다른 자산이 이 GUID를 가리키게 되면 덮어쓰기로 바꾼다.

## 4. 부작용 파일 되돌리기 (047 H4, 046-2, 047-E9)

- Play·장면 저장·캡처 뒤 동적 글꼴 캐시 `PrototypeFont.asset` 등이 바뀐다. 목록은 `Tools/Harness/tier-policy.json`의 `side_effect_files`다.
- 빌더·캡처 명령은 `/usr/bin/python3 Tools/Harness/protect.py run -- unity command script run ...`으로 감싼다. 실행 전 깨끗했던 파일만 `git checkout`으로 되돌리고, 실행 전에 이미 바뀌어 있던 파일(사용자 작업일 수 있음)은 건드리지 않고 알린다.
- `Tools/Harness/play_probe.py`와 짧은·전체 Play 실행기(`keyart_045.py`)는 이 정리를 스스로 한다(결과는 보고서 `side_effect_files`). 덮어쓴 내용은 `output/hook-state/protect-backup/<시각>/`에 사본이 남는다. 지금 상태는 `protect.py check`로 확인한다.
- 근본 해결 후보(사용자 결정 전, 게임 자산 변경): 빌드에 쓰는 글꼴을 정적 아틀라스로 고정.

## 5. 만드는 내용 (046 게임 결함에서)

| 규칙 | 근거 |
|---|---|
| 겹치는 평면(지면·흙·길·물)은 높이 순서를 표로 정하고 빌더 상수로 둔다 | 046-4 |
| 팔레트 칸·재질 속성은 먼저 출력해 보고 고른다. 번호나 이름만 보고 고르지 않는다 | 046-5 |
| 기존 생성 코드를 옮길 때 메시 후처리(법선·색·분할 방식)까지 같이 옮긴다 | 046-6, 046-7 |
| 배치 생성기는 레퍼런스 개수·밀도를 숫자로 먼저 비교한다 | 046-8 |
| 자산 예산은 "개당 × 배치 수"로 본다. 합친 메시는 화면보다 작은 묶음으로 나눈다 | 046-9 |
| 새 모델은 정면 카메라 캡처로 앞 방향을 확인한다(`build_monsters_046.cs`의 `lineup_front`) | 046-15 |
| 빌더를 다시 돌리거나 크게 바꾼 뒤에는 성능 한 줄을 잰다(`play_probe.py --wave 7 --hp-lock --settle 0 --captures 0 --perf 20`) | 047 H12 |
