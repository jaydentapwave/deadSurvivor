# 성능 예산과 최적화 절차

맵·캐릭터·효과를 더하거나 성능을 줄이는 작업에 적용한다. [핵심 규칙](core-rules.md)이 우선한다. 근거는 [049 성능 작업](../reviews/perf-049.md)이며, 2026-11-03 사용자 요청("이것도 워크플로우에 녹여줄수있도록해줘")으로 만들었다.

## 1. 예산

목표 기기는 모바일(Android·iPhone)이다. 아래 편집기 지표는 실기기 성능을 대신 보는 **대리 지표**이며, 최종 판정은 실기기 프레임 시간이다(사용자 측정, 목표 기기는 미정).

| 상황 | 그리기 호출 | 삼각형 | 그림자 그리는 물체 | set-pass | 근거 |
|---|---|---|---|---|---|
| 시작 화면(적 없음) | 250 이하 | 15만 이하 | — | — | 045 예산 |
| 7웨이브(적 약 90) | **250 이하** | **20만 이하** | **50 이하** | 60 이하 | 049. 현재 147 · 7.1만 · 19 · 47 → PASS |
| 최대 부하(적 약 300) | 400 이하 | 40만 이하 | 50 이하 | 60 이하 | 049. 현재 추정 375 · 14.9만 · 15 · **약 75(FAIL)** |
| 적 1마리당(두 측정의 차이로 계산) | 약 1 이하 | 1,000 이하 | 0 | — | 049 |
| 렌더 시간(편집기 `renderTime`) | 부하에서 기준보다 늘지 않을 것. **그리기 호출 수보다 우선한다** | | | | 049 |
| 실기기 프레임 시간 | 16.6ms(60fps), 느린 5%도 20ms 이하. 최소 33ms(30fps) | | | | 049, 기기 미정 |

- 예산 수치는 2026-11-03 제안값을 사용자가 진행하라고 해서 정했다. 업계에서 흔히 쓰는 모바일 기준(그리기 호출 수백, 삼각형 수십만)에 맞춘 값이며 우리 기기에서 잰 값이 아니다. 실기기 측정 뒤 다시 정한다.
- 자산 하나의 예산은 "개당 × 배치 수"로 본다([빌더 규칙](scene-builders.md) 5절). 종류별 개당 숫자(삼각형·텍스처·뼈·그림자)는 [에셋 규격](asset-standard.md) 1절이다(050).

## 2. 측정 기준

모든 성능 수치는 같은 조건에서 잰다. 조건이 다른 수치는 나란히 비교하지 않는다(048-2).

| 항목 | 기준 |
|---|---|
| 렌더 설정 | `Mobile_RPAsset`(`play_probe.py --mobile`). PC 설정은 그림자 단계가 4개(모바일 1개)라 그리기 호출이 크게 부풀려진다(049: 같은 7웨이브가 PC 401, 모바일 167) |
| 값 | `play_probe`가 20초 동안 1초마다 읽은 **중앙값**(최대값도 기록). 한 프레임 값은 피격 깜빡임 수 등으로 크게 흔들린다(049-2) |
| 화면 | 편집기 Game 창 하나, 1280×720. 게임을 그리는 창이 둘이면 두 번 잡힌다(046-13) |
| 편집기 | `runInBackground` 켬(`play_probe`가 켜고 되돌림, 046-3) |
| 7웨이브 | `/usr/bin/python3 Tools/Harness/play_probe.py --mobile --wave 7 --hp-lock --settle 0 --captures 0 --perf 20` |
| 부하 | `... --mobile --count-scale 3 --wave 7 --hp-lock --settle 0 --captures 0 --perf 20`(적 약 550~570까지 늘어남. 300마리 값은 7웨이브와 부하 사이를 적 수로 나눠 추정) |
| 적 1마리당 | 1웨이브(`--wave 1 --settle 2 --perf 10`)와 7웨이브 값의 차이 ÷ 적 수 차이 |

## 3. 줄이는 절차

1. **자산 구성을 먼저 본다.** `play_probe.py --assets`로 렌더러·메시 조각·재질·삼각형·그림자·인스턴싱을 출력한다. 추측으로 최적화 항목을 제안하지 않는다(049-1: 몬스터가 이미 메시·재질 1개인데 "합치기"를 제안했다).
2. **같은 기준으로 잰다.** 7웨이브, 최대 부하, 적 1마리당 값을 표로 남긴다.
3. **효과가 큰 것부터 하나씩 바꾸고, 바꿀 때마다 잰다.** 어떤 변경이 얼마나 줄였는지 나눠 기록한다.
4. **사용자에게 화면을 보여 준다.** 그림자·모델 감량은 보이는 것이 바뀐다([핵심 규칙](core-rules.md) 6절).

| 원인 | 방법 | 도구 |
|---|---|---|
| 물체마다 그림자를 그림(그림자 단계 수만큼 다시 그림) | 그림자 끄고 바닥 원형 그림자 | Unity: 액터 세트 `MonsterBlobShadow`, 빌더 |
| 같은 모델을 하나씩 그림 | GPU 인스턴싱(재질 인스턴싱 켬 + 렌더러 속성 블록). **049에서 손해로 측정돼 꺼 둠**: URP의 SRP Batcher를 끄고 바꾸는 방식이라 그리기 호출은 줄지만(부하 628 → 239) 렌더 시간이 늘었다(9.2 → 12.1ms). SRP Batcher가 켜진 URP에서는 그리기 호출 수만 보고 판단하지 않는다 | Unity: 액터 세트 `MonsterInstanced` |
| 메시 조각·재질이 여럿 | 조각·재질 합치기 | Unity 빌더(같은 재질이면 메시 합치기), 텍스처가 여럿이면 Blender에서 아틀라스 |
| 모델 삼각형이 많음 | 감량(decimate)·LOD | **Blender**: `Tools/Assets/process_blender.py`([자산 워크플로우](ai-3d-assets.md) A2) |
| 맵 묶음 메시가 화면보다 큼 | 묶음 크기 줄이기 | 맵 빌더(046-9) |

Blender는 모델 자체를 가볍게 만들어야 할 때만 쓴다. 그림자·인스턴싱·묶음은 Unity에서 끝난다.

## 4. 기록

- 단계 기록에 "성능 한 줄"(그리기 호출·삼각형·그림자·set-pass·fps, 측정 명령)을 남긴다([핵심 규칙](core-rules.md) 1절).
- 예산을 넘으면 기록에 FAIL로 적고, 줄일지 예산을 바꿀지는 사용자가 정한다.
