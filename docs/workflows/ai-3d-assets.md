# 외부 AI 3D 자산 제작 워크플로우

ASSET-PIPELINE-011/r001 · 2026-10-31 · 전체 단계 설계 · 012 최소 전송 부분 구현

[채택 근거 AD01~07](../design/ai-3d-reference-adoption.md)와 [CLI 선택](../decisions/3d-cli-workflow.md)을 적용한다. 자산 제작 단계/책임의 원본은 본 문서, 자료/검사/실패 사례의 원본은 [자산 하네스 설계](../design/ai-3d-asset-harness.md)다. 기존 [개발 절차](development.md), [맵 단계](../design/맵-워크플로우-하네스-설계.md), [검증 gate](verification-gates.md)는 유지한다.

## 적용 범위와 도구

첫 대상은 정적 배경 소품인 바위·돌벽이다. 맵 전체 자동 생성, 캐릭터/리깅/애니메이션은 별도 설계 전까지 범위 밖이다. 같은 자산의 개정과 같은 모델을 배치한 여러 OB 인스턴스를 구분한다.

기본 흐름은 **Tripo CLI/API → 로컬 원본 → Blender 후처리 → 기존 Unity CLI 가져오기 → 독립 검사 → 채택 등록 → 맵 표현 적용**이다. Blender 조작 수단은 구현 때 로컬 버전과 사용 가능 기능을 확인한다. MCP for Blender/Unity MCP의 설계는 참고하지만 현재 MCP 설치나 기존 CLI 교체를 요구하지 않는다.

- 공급자 어댑터는 생성·조회·다운로드만 담당하고 모델 채택을 결정하지 않는다.
- Blender 처리기는 원본의 복사본에 명시된 처리만 수행하고 처리 전후 측정을 출력한다.
- Unity 가져오기 어댑터는 지정된 개인 프로젝트에 후보 프리팹을 만들고 실제 가져온 값을 측정한다.
- 판정기는 등록 기준과 관측을 비교한다. 등록부 작성자는 판정/복구 증거를 확인한 뒤 채택 기록을 남긴다.
- DSGame과 맵 C는 기존 소유권을 유지한다. 자산 어댑터는 맵 좌표, 통로, 이동·스폰 규칙을 바꾸지 않는다.

## A0~A5 작업 단계

아래 A는 자산 단계이며 G0~G5 맵 단계나 H1~H5 구현 단계를 대신하지 않는다. 이전 단계 증거를 같은 의존 지문으로 확인해야 다음 단계 완료를 주장할 수 있다.

| 단계 | 입력과 작업 | 필수 산출물 | 다음 단계 조건 |
|---|---|---|---|
| A0 계약 고정 | 자산 ID/개정·정적 소품 역할·RF/OB·허용 자료·형태/팔레트·수치/단위·출처·비용/공개 범위 작성 | asset-spec, 예상 검사 ID, 미정 목록 | 필요한 수치/허용 범위와 기능 확인. 유료 제출은 요청별 허용 근거 추가 필수 |
| A1 원본 확보 | 허용된 생성 요청 또는 기존 원본 재사용. 수락 작업 ID 저장, 조회/다운로드 | journal, raw 파일/해시, provenance | 생성 완료와 파일 검증은 별개. 파일·부속 텍스처·출처가 모두 확인돼야 A2 |
| A2 후처리 | 원본 보존, 크기/방향/원점 정규화, 필요시 메시 경량화/재질 정리 | 처리 절차/버전/설정/해시, processed 모델, 전후 수치/화면 | 구조·외형 유지와 해당 예산 검사. 자동 UV/재질 복구도 변경 기록 필수 |
| A3 Unity 후보 | 대상·버전·렌더 파이프라인·포맷 지원 확인, 격리된 새 개정 가져오기 | 후보 프리팹/GUID/.meta/의존 해시, 실제 측정/콘솔 | 컴파일/임포트/재질/텍스처·변환·복구 검사. 파일 존재만으로 완료 금지 |
| A4 비교·인수 | 처리 전후, Blender/Unity, 실제 게임 카메라 비교. 성능 측정 | 비교 원본 화면, 관찰값, 항목별 판정, review/cleanup | 모든 필수 축 PASS. 미정/미실행/누락이 있으면 채택하지 않음 |
| A5 채택·연결 | 검증된 정확한 개정 등록. 이후 별도 맵 작업에서 OB에 배치 | 채택 레코드와 자산 의존 지문; 배치 시 map-binding sidecar | 자산 채택과 G5 맵 인수를 분리. 배치/전체 부담/맵 회귀 증거가 추가로 필요 |

준비용 fixture는 `scope=FIXTURE`로 별도 계약·기준을 갖는다. 비용 없이 처리기와 검사기를 개발할 수 있지만 실제 소품의 A4/A5나 G5 증거로 전용하지 않는다. 기존 Studio 바위는 [012 TRANSFER_TEST](../design/asset-pipeline-minimum.md)에서 처리·Unity 전송을 시험했다. 011의 PRODUCTION A2~A5 통과 기록이 아니다.

## 입력 계약과 일관성

[자산 작업 양식](../templates/ai-3d-asset-package.md)을 사용한다. 자산별 `asset_id/revision`과 계약 지문을 고정하고 다음을 먼저 정한다.

다음 Tripo 정적 소품 요청부터 [TRIPO-STATIC-PROP/r001 생성 기준](tripo-generation-standard.md)을 A0 필수 작성 규칙으로 적용한다. 대상/개수·실루엣·색/재질·크기/예산·텍스처/조명·정확한 생성 버전과 시드 정책을 작성하고 **프롬프트 요구 / 실제 지원되는 공급자 옵션 / Unity 인수 기준**을 구분해 동결한다. 값과 근거가 미정이면 준비 상태로 남긴다. 과거 바위 시험 수치를 모든 소품에 자동 적용하지 않는다. 이 문서 규칙은 생성 제출 어댑터나 자동 자산 gate 구현을 뜻하지 않는다.

- 형태: 어떤 RF를 표현하는지, 실루엣/모서리/표면 거칠기/색 범위, 허용·금지 변형. 공급자 프롬프트만 스타일 기준으로 사용하지 않는다.
- 실제 크기: 축·단위·정면·지면 접점·원점·각 축 치수 허용치. 맵에서 적용할 회전/스케일과 논리↔Unity 변환은 맵 binding이 소유한다. 자동 최대축 1m 정규화를 모든 물체에 적용하지 않는다.
- 자원: 삼각형/재질/텍스처 크기·메모리 예산과 사용 인스턴스 수, 측정 환경·성능 조건. 외부 예제 수치나 이번 약50만 삼각형 바위를 합격 기준으로 삼지 않는다.
- 비교: 카메라 투영·위치·방향·범위·출력 해상도·조명·색 관리·렌더 파이프라인과 검토 항목. 항목 누락은 전체 평균 점수로 덮지 않는다.
- 변경: 프롬프트·공급자 모델·옵션·원본·처리기·수치·카메라를 바꾸면 관련 개정과 증거를 새로 만든다. 동일 프롬프트/시드는 동일 메시 재생성 보장이 아니다. 재현은 보존된 원본 해시와 처리 절차를 기준으로 삼는다.

기준 수치는 A0에서 근거·단위·개정을 등록한다. 현재 실제 소품 기준은 미정이며 통과 여부는 BLOCKED다. 비용/공개 범위가 확정되지 않은 준비 작업에서 임의 유료 생성을 하지 않는다. 필요한 단계에만 필요한 기준을 요구하며, A2의 로컬 fixture 개발에 API 잔액을 요구하지 않는다.

## 유료 작업·중단·재개

AD01을 구체화한 우리 정책이다. `PLANNED → SUBMITTING → ACCEPTED → POLLING → DOWNLOADED`는 공급자 작업 상태이며 PASS/FAIL 같은 품질 판정과 구분한다.

1. 로컬 잠금 아래 공급자/서버/비밀이 아닌 계정 구분자/요청 지문/승인 범위/비용 한도를 확인한다. 같은 요청을 수행 중이면 두 번째 유료 제출을 거부한다. credential나 인증 헤더를 기록하지 않는다.
2. 제출 전에 고유 attempt ID와 `SUBMITTING`을 내구 기록한다. 수락된 task ID를 받으면 조회 전에 원자적으로 저장하고 `ACCEPTED`로 이동한다. CLI/SDK 내부 POST 자동 재시도를 확인할 수 없으면 유료 어댑터는 BLOCKED다.
3. 수락 ID가 있으면 재시작 후 조회/다운로드부터 이어간다. provider 실패·취소·만료도 새 생성 허가가 아니다. 재생성이 필요하면 새 attempt에 이유/추가 비용/기존 승인 잔여 범위 또는 새 승인 근거를 남긴다.
4. 제출 응답 유실/수락 ID 저장 전 종료는 `SUBMISSION_UNKNOWN`과 BLOCKED로 보존한다. 공급자 조회로 특정 작업을 확인하거나 사용자가 판단할 때까지 새 POST를 보내지 않는다. 로컬 잠금만으로 정확히 한 번 과금을 보장하지 않는다.
5. 상태 조회와 다운로드는 사전 정한 최대 횟수/간격/전체 시간 제한 안에서만 재시도한다. 서명 다운로드 URL은 필요할 때 다시 조회하고 URL·토큰을 보고서에 보존하지 않는다. 임시 파일 다운로드→파일 확인→해시→원자적 확정 순서다.
6. 사용자 취소는 먼저 로컬 실행을 중단한다. 원격 취소 가능 여부/결과를 별도로 기록하며 로컬 중단을 공급자 취소·환불로 표현하지 않는다. 이미 승인된 task가 계속 실행될 수 있으면 상태를 남긴다.

Studio 잔액과 API 잔액은 별개다. [과거 잔액 기록](../decisions/3d-cli-workflow.md)을 현재 사용 가능 잔액으로 재사용하지 않는다. 공개 예외는 기존 일반 바위 한 건뿐이다. 다운로드/후처리는 추가 공개를 뜻하지 않으며 외부 재텍스처·리메시도 새 유료/업로드 작업이면 같은 제출 규칙을 적용한다.

## 파일 보존·가져오기·복구

자료 설계 경로는 프로젝트 안 `output/asset-pipeline/<asset-id>/<revision>/<run-id>/`다. 이 경로는 전체 등록 설계다. 012 최소 도구는 `output/asset-pipeline/<asset-id>/<run-id>/`를 사용하고 개정은 동결된 spec/job 지문으로 보존한다. 원본, 처리본, 캡처, journal, 결과를 구분한다. 승인 자산의 영구 보존 경로는 `docs/art/assets/<asset-id>/<revision>/`로 계획하되 A5 구현 전에는 자동 복사하지 않는다. 해당 보존본에는 모델/외부 텍스처·계약·처리 절차·최종 증거를 포함하며 output 캐시만으로 재현 가능하다고 주장하지 않는다.

실제 Unity 자산은 AGENTS의 개인 Unity 대상 안 후보 경로에만 만든다. 대상 밖 자동 탐색/동기화를 하지 않는다. GLB/FBX 선택은 현재 importer와 렌더 파이프라인에서 확인하고, 누락 패키지는 BLOCKED로 보고한다. 외부 예제 버전 설치를 암묵적으로 수행하지 않는다.

- 복사/가져오기 전에 대상 경로·파일/.meta·씬/선택/설정의 상태와 소유권을 기록한다. 새 개정 경로 충돌은 차단한다.
- 메시·재질 처리 후 **저장된 최종 프리팹을 다시 로드해** 크기·원점·텍스처 연결·의존 해시를 측정한다. Blender 수치를 Unity 실측으로 대신하지 않는다.
- 첫 정적 소품은 임의 스크립트·Rigidbody·Animator·생성 MeshCollider를 붙이지 않는다. 필요한 컴포넌트는 명시된 허용 목록만 사용한다. 충돌은 채택된 맵 C가 담당한다.
- 실패/취소 시 소유 임시 씬/오브젝트/설정만 복구한다. 새로 생성한 파일은 해시가 소유 기록과 같을 때만 제거/격리하며, 사용자 변경이 있으면 보존하고 충돌을 기록한다. 이전 채택본/원본을 덮어 복원하지 않는다.
- 자산 등록은 최종 증거와 복구 확인 이후 단일 작성자가 수행한다. 완료 직전 파일이 달라지면 등록을 거부한다. 실패한 후보는 실패 증거를 남기고 맵에서 선택되지 않게 한다.

## 맵 적용과 검사 책임

A5 자산은 G5 표현 적용의 입력이다. G3/G4 기본 도형 시험에는 AI 소품이 없어도 된다. 공급자의 생성 크기/바닥 모양/자동 collider는 맵 C·경계·RT의 근거가 될 수 없다.

맵 배치마다 OB→asset 개정/프리팹/변환/C 개정→RF/RT/MC를 연결한다. 동일 프리팹을 여러 OB에 쓸 수 있지만 각각의 회전/스케일·시각 점유·통로 가림은 따로 확인한다. 장식용이면 비충돌 이유와 부모 OB를 명시하며 C 필드를 빈 값으로 숨기지 않는다.

G5 인수에는 기존 G4 필수 사례에 더해 자산 A4/A5 증거, MC-CAMERA-01과 MC-PERF-01, 바뀐 배치·충돌·스폰·공격 영향 사례가 필요하다. 자산 단독 성능이 전체 맵 성능을 대신하지 않는다. C를 바꿔야 하면 별도의 맵 CH/개정/인수로 돌아간다.

## 실행량·토큰·다음 구현

반복 조회/측정/해시/비교 목록 수집은 로컬 실행기가 수행하고 에이전트에는 run ID, 상태, 필수 사례 수, 첫 실패, 미정/누락 목록과 필요한 화면만 전달한다. 전체 원자료는 로컬에 남긴다. 화면 검토·실패 주입·복구를 생략해서 실행량을 줄이지 않는다.

구현은 계약/가짜 공급자 복구 시험 → 로컬 후처리 → 격리 Unity 인수 → 자산 gate/등록 연결 → 허용된 API 1건 검증 순서다. [012 사용법](../../Tools/Assets/README.md)에 최소 실행 명령을 확정했다. 기존 바위 계약/로컬 작업 재개·Blender·Unity 전송을 검증하며 유료 제출/원격 다운로드·전체 인수/등록·자산 gate는 미구현이다. 기존 local/all/gate PASS는 자산 시험을 대신하지 않는다.
