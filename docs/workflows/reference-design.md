# 레퍼런스 기반 시각 설계

2026-10-30. 사용자 요청에 따른 프로젝트 로컬 규칙. 개발 규모 분류와 독립 검토는 [개발 워크플로우](development.md)를 따른다. 새 승인 절차나 외부 연동을 추가하지 않는다.

## 반드시 구분할 근거

설계 문서에 사용자 요구, 원본에서 관찰한 사실, 에이전트 제안, 미정을 구분한다. 에이전트 제안은 문서에 기록되거나 검사에 통과해도 사용자 확정으로 승격하지 않는다. 원본의 외형만으로 충돌·높이·축척·스폰·통과 가능성을 확정하지 않는다.

## 작업 순서

1. 원본 이미지 직접 확인: 출처 URL, 파일명, 해상도, 확인 날짜와 로컬 입력 파일을 기록한다. 확보 불가 시 BLOCKED인 범위를 명시하고 추정 이미지로 대체했다고 숨기지 않는다.
2. 외곽·장애물 분포와 크기·방향·열린 공간·연결 경로를 분석한다. 관찰과 해석을 분리한다.
3. 유지할 특징과 변경할 특징을 명시한다. 표현 스타일 변경 요청을 맵 구조 단순화로 해석하지 않는다. 구현 편의로 사용자 핵심 요구를 바꾸려면 방향 변경임을 설명하고 기존 승인이 없는 경우 확인한다. 통상적인 제작·비교에는 별도 승인을 요구하지 않는다.
4. 생성 입력에 실제 원본 이미지를 전달하고 입력 경로·사용 도구·최종 프롬프트를 보관한다. 이전 생성 시안을 원본 대신 넘긴 채 원본 직접 참조라고 보고하지 않는다.
5. 원본과 결과를 동일 항목으로 시각 비교한다. 외곽, 지역별 밀도, 크기·형태 다양성, 길 연결, 열린 공간, 표시 정확성을 각각 기록한다. 정확한 개수·면적·축척을 측정하지 않았다면 수치 일치라고 주장하지 않는다.
6. 핵심 특징이 누락되면 FAIL로 기록하고 원본부터 수정한다. 글자·범례가 정확하거나 문서 링크 검사가 PASS여도 요구 충족 PASS를 대신하지 못한다. 결과물 검토와 런타임 검증은 구분한다.
7. 피드백이 기본 전제를 부정하면 전제와 최신 문서 연결부터 수정한다. 실패 시안은 과거 비교용으로 보존하고 현재 기준으로 계속 사용하지 않는다.

## 완료 기록

맵 산출물의 고정 형식·버전·표현 규칙은 [맵 산출물 규격](map-artifact-contract.md)을 따른다. 실제 맵 검사와 증거 판정은 [워크플로우·하네스 설계](../design/맵-워크플로우-하네스-설계.md), 사례는 [사례 명세](../design/맵-하네스-사례명세.md)를 사용한다. 현재는 문서 설계이며 맵 하네스가 구현됐다는 뜻이 아니다.

입력 원본·프롬프트·결과 파일·항목별 비교·잔여 차이·실행 시각·SHA-256·검사 결과를 프로젝트 안에 기록한다. 이미지 생성 결과는 별도 정밀 좌표 검증 없이 구현 도면이나 충돌 데이터가 되지 않는다. 외부 공유·회사 서비스 기록은 금지하며 AGENTS 저장 경계를 유지한다.
