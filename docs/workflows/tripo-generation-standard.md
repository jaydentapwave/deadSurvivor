# Tripo 정적 소품 생성 기준

TRIPO-STATIC-PROP/r001 · 2026-10-31. 다음 바위·돌벽 등 정적 배경 소품 요청부터 A0에서 적용한다. [자산 작업 양식](../templates/ai-3d-asset-package.md)에 이 기준의 ID/개정을 기입하고 자산별 값을 동결한다. 변경하면 요청 개정과 영향을 기록한다.

## 적용 순서

1. 대상 소품과 원본 참고 자료를 정하고 아래 요청표를 작성한다. 사용자 요구·레퍼런스 관찰·에이전트 제안을 구분한다.
2. 생성 모델/서버/실제 계정·Studio/API 경로에서 지원하는 옵션과 조합을 확인한다. 미지원 옵션은 전송하지 않고 요구 충족 방법을 정한다. 필요한 제어를 할 수 없으면 해당 요청은 BLOCKED다.
3. 프롬프트, 실제 공급자 옵션, Unity 인수 기준을 각각 동결한다. 공급자에게 숫자를 전달하는 필드가 없으면 프롬프트만으로 강제됐다고 보지 않는다.
4. 요청별 비용 한도·공개/업로드 허용 근거를 확인한 뒤 실행한다. 재시도/새 생성도 기존 승인 범위와 작업 기록을 따른다.
5. 원본/task ID/유효 옵션/도구 버전/파일 지문을 보존하고 Unity CLI로 실제 결과를 검사한다. 필요한 후처리와 검증된 처리본 재사용은 기존 [단계별 절차](ai-3d-assets.md)를 따른다.

이 기준은 A0 요청 작성 규칙이다. 현재 012/013 도구는 기존 원본의 Blender 처리와 Unity 전송을 구현한다. **Tripo→Unity 직행, 생성 제출 어댑터, 이 표의 자동 검사·자산 gate는 미구현**이다. 현재 실행 경로를 변경하려면 별도 구현/독립 검증이 필요하다.

## 자산별 필수 요청표

| 구분 | 반드시 작성할 내용 | 기록/검증 방법 |
|---|---|---|
| 대상·용도 | 소품 종류, 개수, 전투 장애물/장식 역할, 포함/제외할 주변 요소 | 프롬프트와 참고 이미지. 충돌은 맵 C가 별도 소유 |
| 실루엣·구조 | 폭/높이/깊이 비율, 큰 면/모서리/굴곡, 부속물, 유지할 특징과 금지 변형 | 레퍼런스 이미지 ID/파일 지문과 관찰. 전후 직접 화면 비교 |
| 색·재질 | 주색/보조색, 돌/금속/목재, 무광/광택, 표면 디테일 밀도 | 프롬프트·팔레트/색 표본. 숫자만으로 시각 합격 처리 금지 |
| 기하 예산 | Unity 삼각형 상한·메시/재질 수와 근거, 인스턴스 수 | 지원되는 `face_limit`/`quad`에 반영 후 Unity 실측 |
| 치수·배치 | 각 축 목표 범위·단위·정면·바닥 접점·원점 허용 오차 | 프롬프트로 비율 요청, 실제 Renderer bounds/원점 검사 |
| 텍스처 | 필요한 슬롯, 최종 최대 해상도, 품질, UV 필요 여부 | 지원되는 texture/PBR/품질 설정과 다운로드 후 슬롯/해상도 검사 |
| 조명 | 텍스처에 남기지 않을 강한 그림자·하이라이트, 확인용 조명/카메라 | 프롬프트 및 지원되는 delight, Unity 고정 화면에서 직접 확인 |
| 구조·애니메이션 | 정적 소품, 분할 필요 여부, 불필요한 리깅/애니메이션 작업 제외 | 생성/후처리 요청과 실제 프리팹 컴포넌트 검사 |
| 재현·비용 | 공급자 모델/텍스처 버전, 입력/프롬프트/옵션 지문, 시드 정책, 비용/공개/계정 | 요청/응답·task ID·원본 파일과 허용 근거 보존 |

필수 항목은 자산별 값 또는 해당 없음의 이유를 기록한다. 수치/단위/근거가 미정이면 A0 준비 상태로 남기고 생성/인수를 진행하지 않는다. `face_limit`을 지정해도 실루엣·UV·재질·정확한 최종 삼각형 수는 별도로 검사한다. 사각형 면 수를 Unity 삼각형 예산과 혼용하지 않는다.

## 기본 요청 정책과 예외

다음은 정적 소품의 **기본 정책**이다. 현재 공급자 모델과 계정 기능을 확인하여 실제 전송 옵션을 확정하고, 예외는 이유와 영향 범위를 요청표에 기록한다. 빈 값이나 미지원 값을 API 필드로 그대로 보내지 않는다.

| 항목 | 기본 정책 | 예외/주의 |
|---|---|---|
| 프롬프트 구조 | `대상/개수 → 실루엣/비율 → 미술/색/재질 → 표면/조명 → 제외 요소` 순서 | 자산별 구체 표현과 참고 이미지가 필요. 모델의 글자 수 제한 준수 |
| face_limit | 자산별 승인된 삼각형 예산을 숫자로 기입 | 공통 고정 숫자 없음. 과거 바위≤10,000은 전송 시험 기준 |
| quad | `false`로 삼각형 기준 사용 | 편집 목적의 사각형 출력은 별도 이유와 변환 후 삼각형 예산 필요 |
| geometry_quality | 지원 시 `standard` | 세부 형상이 필요한 경우 비용/예산 확인 후 변경. 모델별 지원 조건 확인 |
| texture / pbr | 텍스처를 쓰는 소품은 각각 `true` | PBR은 해당 지원 API에서 texture를 true로 강제할 수 있음. 무텍스처 소품은 별도 유효 조합 확인 |
| texture_quality | 지원 시 `standard` | 품질 설정을 정확한 2048px 지정으로 해석하지 않는다. 최종 해상도는 자산 계약으로 검사 |
| UV | 최종 textured 자산은 UV 존재/연결을 검사 | `export_uv`는 선택한 endpoint가 지원할 때만 지정. 지원 확인 없이 공통 전송 필드로 추가하지 않음 |
| auto_size | 지원 시 `false`, 자산 계약의 단위/크기로 정규화·실측 | `true`는 실제 크기 추정 옵션이며 정확한 목표 치수나 바닥 원점을 보장하지 않음 |
| generate_parts | 지원 시 `false` | 분할이 필요하면 별도 요청. false가 메시1/재질1 보장은 아님 |
| smart_low_poly | 명시적으로 사용 여부 결정, 자동 활성화하지 않음 | 저폴리 형상 요구·지원 범위·추가 비용 확인 후 사용. 이 옵션이 원하는 미술 스타일을 보장하지 않음 |
| delight | 지원되는 텍스처 버전에서 활성화 검토 | 현재 공식 문서상 `v3.5-20260815`가 읽으며 구버전은 무시. 미지원은 효과 없음으로 기록하고 화면 검사로 보완 |
| 모델/시드 | 정확한 geometry/texture 모델 버전과 각 seed 정책 기록 | 'latest'를 고정 버전으로 취급하지 않는다. 자동 seed는 실제 반환값 또는 UNKNOWN으로 기록. 미확인을 0으로 대체하지 않음 |
| 출력 포맷 | 지원이 확인된 현재 importer와 맞는 GLB/FBX 선택 | 현재 시험 도구는 FBX만 지원. 다른 포맷은 별도 전송 지원 확인. quad 활성화에 따른 FBX 강제 조건도 확인 |

프롬프트는 요청한 형태/재질/비율을 설명한다. 수치 제한은 지원되는 실제 옵션에 넣는다. 원점, 메시/재질 수, 텍스처 해상도, Unity 컴포넌트는 최종 자산을 실측해 판정한다. 생성 옵션과 인수 기준을 서로 대체하지 않는다.

## 요청에 보존할 최소 기록

- 기준 ID/개정, asset ID/개정, scope, 레퍼런스와 사용 허용 근거.
- 프롬프트/negative prompt 원문, 입력 이미지와 해시, 미술 기준·제외 요소.
- 공급자/서버·Studio/API/CLI 경로, 실제 모델 버전과 지원 기능 확인일/공식 근거. CLI를 쓰면 실제 설치 버전과 해당 명령의 인자 확인 근거.
- 실제 전송 필드/값, 명시적으로 생략한 옵션과 이유, UI라면 확인한 설정의 로컬 증거. 선택한 값과 실제 적용/반환 확인을 구분한다.
- geometry/image/texture seed의 고정/자동 정책과 확인된 값, 계정 구분자(비밀 제외), 비용 한도·공개/업로드 범위·승인 근거.
- task ID/attempt, 생성·다운로드 결과와 파일 지문, Unity 인수 기준·결과, 후처리 사유·도구 지문·전후 비교. 인증키/서명 URL을 기록하지 않는다.

시드/프롬프트 기록만으로 동일 메시 재생성을 보장하지 않는다. 재현과 재사용의 기준은 보존된 원본 파일과 의존 지문이다. 요약에는 요청 개정·상태·첫 미정/실패·기록 경로만 전달하고 원자료는 프로젝트 안에 보존한다.

## 공식 근거와 적용 범위

확인일 2026-10-31. 다음은 기능 근거이며, 우리 자산별 수치나 계정의 기능/비용 승인을 대신하지 않는다. 새 생성 시 선택 모델·계정·endpoint의 현재 문서와 실제 CLI/UI 지원을 재확인한다.

- [Tripo H Series 생성 API](https://developers.tripo3d.ai/en/docs/generation-text-to-model/standard): prompt, model/texture_version, seed, face_limit, texture/PBR/quality, delight, auto_size, quad, smart_low_poly, generate_parts 및 조합 제한.
- [H3 기존 API 문서](https://docs.tripo3d.ai/model-generation/text-to-model-v3-0-v3-1.html): export_uv 등 버전별 필드, smart_low_poly·quad 및 품질 옵션의 추가 비용. 현재 계정/신규 API의 비용표로 전용하지 않는다.
- [Tripo Studio 안내](https://www.tripo3d.ai/blog/tripo-studio-tutorial-english): 생성의 topology/Smart Low Poly와 생성 후 Retopology의 Polygon Count. API 필드명이 Studio UI의 동일 기능/접근성을 보장하지 않는다.

기존 [바위 시험 계약](../design/asset-rock-test-contract.json)의 10,000삼각형·메시/재질1·2K·가로 최대2단위는 TRANSFER_TEST 전용이다. 이 문서는 해당 JSON에 새 필드를 주입하거나 최종 게임 미술/성능/맵 기준으로 승격하지 않는다.
