## 판단 메모

- 첫 판 개수(C1 10, C2 32)는 "최소 3~5"보다 크다. 사용자 스펙이 프로토타입 범위를 "10웨이브 · 아이템 32종"으로 정했고, 예전 값이 있어 데이터로 채운다. 아이템마다 코드가 필요한 것은 발동 방식 7가지(근접 부채꼴 2, 투사체, 폭발 투사체, 연쇄 번개, 단일 회복, 범위 회복)뿐이다.
- F1이 크다(Core 기반 + 2D 렌더 + 화면 네 개). 뼈대가 판정 경로를 먼저 세워야 뒤 기능이 경로에 이어 붙일 수 있어 나누지 않았다. 기능 기획서 단계에서 너무 크면 할 일을 나눈다.
- 승리 경로(G7)는 실제 규칙으로 10웨이브를 버텨야 한다. 예전 판은 자동 이동으로 "10웨이브 자연 완주"를 통과한 적이 있다(045 기록). 봇이 못 이기면 수치가 아니라 봇을 먼저 의심하고, 그래도 안 되면 M6을 다시 정한다(사람에게 알린다).
- 아트 쪽은 [아트 기준서](../art/아트-기준서.md)와 그림체 시범이 맡는다. 기능은 임시 도형으로 먼저 끝내고 그림은 따로 넣는다(director-game 4절).
