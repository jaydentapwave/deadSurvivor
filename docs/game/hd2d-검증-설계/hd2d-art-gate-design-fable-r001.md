## 1. 검사 목록

### 1.0 검사가 기대는 입력 (캡처 도구가 같이 내야 하는 것)

1회차에는 아래가 없어서 색·영역 검사를 손으로 잡은 상자로 돌렸다. 관문을 자동으로 돌리려면 캡처 도구(`LookdevCaptureUtils`)가 판마다 이것을 같이 쓴다.

| 입력 | 내용 | 왜 | 묶음 |
|---|---|---|---|
| `manifest.json` | 판마다: 역할(`candidate`·`baseline`), 요구한 값과 실제 값(카메라 방식·각·정사영 크기·인물 키, 품질 단계, Render Scale, SRP Batcher, 안티에일리어싱, 해 방향), 캡처 파일 목록, 프레임 번호, 소스 해시(지금 `source-fingerprint.json`), 콘솔 에러 수 | 설정·무결성 검사가 캡처 도구의 말이 아니라 기록을 본다(P7) | 최소 |
| 화면 영역 상자 `regions` | 대원·몬스터·소품·빈 바닥 견본점(가운데·위 띠·아래 띠·네 모서리)을 `WorldToScreenPoint`로 화면 상자로 적음. 종류(`hero`·`monster`·`prop3d`·`propBoard`·`ground`·`road`·`water`) 포함 | 색·결·반복·흐림 검사의 영역. 손으로 잡지 않는다 | 최소 |
| 효과 끈 쌍둥이 `<판>-nofx.png` | 같은 프레임에서 볼륨·흐림 기능만 끄고 한 장 | 흐림 띠·가장자리 어둡게·빛 번짐을 내용과 섞이지 않게 잰다. 대원 도트가 효과 때문에 흐트러지는지도 여기서 가른다 | 최소 |
| 종류 마스크 `<판>-class.png` | 종류별 단색으로 다시 그린 한 장(지금 `*-height-mask.png`를 넓힌 것) | 외곽선·가림·가운데 비움을 픽셀로 잰다 | 나중 |

## 2. 자동으로 못 보는 것

"HD-2D스러운가", "같은 결로 보이나"는 숫자(D3~D5, H1~H5)가 필요조건만 본다. 숫자를 다 맞추고도 어색할 수 있어 모델 판독 두 개를 관문 마지막에 둔다. **숫자 검사가 모두 통과한 판만** 판독에 올린다(판독은 느리고 비싸다).

| | V1 채점표 | V2 눈가림 골라내기 |
|---|---|---|
| 질문 | 근접 캡처와 전체 캡처를 보고 항목마다 "그림에서 본 것"을 먼저 적고 예·아니오 | 같은 크기 조각 넷(캐릭터 도트 둘, 지금 2D 게임 장식 하나, 판의 배경 소품·바닥 하나)을 섞어 놓고 "그림체가 다른 것이 있으면 번호와 이유. 없으면 없음" |
| 항목 | ① 배경 도트 한 칸이 캐릭터 도트 한 칸과 같은 크기인가 ② 소품 명암이 띠 2~3단인가(부드러운 번짐 없음) ③ 소품에 갈색 외곽선이 있는가 ④ 소품이 바닥과 한눈에 갈리는가 ⑤ 캐릭터가 배경 위에 붙어 보이는가(그림자가 발에 닿고 방향이 하나) ⑥ 위·아래가 가운데보다 흐린가 ⑦ 레퍼런스(`docs/art/reference/hd2d-study-20261117/`) 조각과 나란히 놓았을 때 빛·깊이감이 같은 종류인가 | 자리와 순서를 바꿔 3번 |
| 누가 | 두 모델 계열: Codex(`gpt-6.1-sol`, `Tools/codex_review.py`와 같은 호출)와 Claude(medium). 서로의 답을 보지 않는다. 판 이름·방식·기대 답을 주지 않는다 | 같음 |
| 통과 | 두 모델 모두 ①~⑥ 예, ⑦은 한쪽 이상 예. 두 모델이 갈린 항목은 FAIL로 센다 | 3번 중 배경 조각을 고른 횟수가 두 모델 합쳐 6번 중 1번 이하 |
| 닻(판독이 믿을 만한지) | 판독을 관문에 넣기 전에 한 번: **1회차 B·F는 떨어져야 하고**(사용자가 실제로 아쉽다고 한 그림), 지금 2D 게임 캡처의 장식은 ①~④에서 붙어야 한다. 닻이 틀리면 그 항목은 관문에서 빼고 정보로만 싣는다 | 조각 넷이 모두 캐릭터 도트일 때 "없음"이 나와야 한다 |

- 판독 결과는 요약 한 장에 "모델이 본 것" 원문 한 줄씩과 같이 싣는다. 사용자는 판독이 맞았는지 바로 볼 수 있고, 틀렸으면 그 판이 다음 닻 표본이 된다.
- 판독으로 바꾸지 않는 것: 방향·취향(어느 방식이 더 좋은가, 분위기). 이것은 사용자가 고른다(핵심 규칙 6절 "사용자가 아트 디렉터"). 관문은 "보여 줄 만한가"만 가른다.
- 움직임(입자, 걷기, 카메라 이동의 느낌)은 정지 캡처로 못 본다. M1 숫자와 연속 8장 줄을 싣고, 요약에 "움직임은 직접 Play로 볼 것"이라고 적는다.

| 통과하지만 나쁨: 숫자만 맞고 어색함 | 외곽선이 지저분, 띠가 얼룩 | V1·V2. 그래도 남는 것은 사용자가 본다 — 요약에 "자동으로 못 본 것" 칸 |
| 통과하지만 나쁨: 설정을 거짓으로 적음 | manifest에 요구 값을 그대로 복사 | 실제 값은 실행 중 API에서 읽게 하고(`QualitySettings.GetQualityLevel` 등 — 지금 `measure*.json`이 그렇게 해서 P7이 드러났다), 관문은 요구 칸과 실제 칸이 **따로** 있는지 확인 |
| 통과하지만 나쁨: 판 역할 바꾸기 | 떨어진 판을 baseline으로 | 역할은 지시문에서 오고 지시문 해시를 manifest에 적음. 요약에 baseline 수를 표시 |
| 좋은데 떨어짐: 일부러 다른 판 | 카메라 비교(F 10%)는 D1에서 떨어진다 | 지시문에 "이 판은 D1을 비교하려는 것"을 미리 선언한 면제. 면제는 검사 id 단위, 요약과 미리보기에 딱지 |
| 좋은데 떨어짐: 문턱이 표본 7장에서 나옴 | D2 0.85, R1 0.35, H4 0.03 등 | 문턱은 설정 파일에 두고 출처 칸에 "닻"이라고 적음. 사용자가 통과한 판을 받아들이거나 버릴 때마다 닻 표본에 더하고 `gate.py calibrate`(= `measure.py calibrate`와 같은 생각)로 과거 판정과 맞는 비율을 본다 |
| 좋은데 떨어짐: 원근 판 | 화면 위아래 도트 크기가 달라 D3 빗이 흩어짐 | 원근 판은 가운데 띠에서만 D3을 재고 위·아래 크기 비는 `view.py` 값과 대조 |
| 좋은데 떨어짐: 그림자·효과가 영역에 들어옴 | H4에 나무 어두운 면이 섞임(이번 측정) | 종류 마스크가 생기면 바닥만. 그 전에는 빛 끈 쌍과의 차로 그늘 픽셀을 고름 |
| 관문이 일을 늘림 | 검사가 33개 | 실패는 한 번에 전부 모아 낸다(첫 실패에서 멈추지 않음). 3회 연속 한 번도 결함을 못 잡은 검사는 빼기 후보로 요약에 표시(핵심 규칙 5절) |
| 검사 결함 | 검사가 틀려서 떨어짐 | `gate.py selftest`: 닻 표본(1회차 판 = 반드시 FAIL, 2D 게임 캡처 = 결 검사 PASS)을 넣어 둔다. 실패 보고에 "게임 결함 / 검사 결함" 판단 칸(핵심 규칙 0절) |

## 4. 관문 흐름

### 4.1 순서 (빠른 것 먼저, 실패는 모아서)

| 단 | 검사 | 시간 | 실패하면 |
|---|---|---|---|
| 0 묶음 | G1~G6, S1~S3 | 5초 | 다시 찍는다(그림을 고칠 일이 아니다). 뒤 단은 돌리되 "묶음 실패" 표시 |
| 1 숫자 | L1, D1, M1, P1·P2 (JSON만) | 1초 | 카메라·측정 문제 |
| 2 그림 | D2~D6, C1~C4, R1, L2~L4, H1~H5 | 30초 | 그림·장면을 고친다 |
| 3 판독 | V1, V2 — 0~2단을 모두 통과한 판만 | 2~3분 | 그림을 고친다 |
| 4 기록 | `gate-result.json`(판별·검사별 값, 문턱, 캡처 해시, 설정 해시), `gate-summary.md` | 1초 | — |

### 4.2 실패 뒤 고치기

- 에이전트가 `gate-result.json`의 실패 목록을 **한꺼번에** 받아 고치고 다시 찍어 다시 돌린다. 사람에게 묻지 않는다(AGENTS.md "판정에 못 미치면 다시 돈다").
- 같은 검사가 같은 방법으로 2번 떨어지면 방법을 바꾼다(같은 규칙). 방법을 바꿨다는 것을 결과에 적는다.
- 상한: 한 회차에 다시 돌리기 4번 또는 60분. 넘으면 그림을 보여 주지 않고 **관문 보고만** 디렉터에게 올린다(무엇이 몇 번 떨어졌는지, 게임 결함인지 검사 결함인지). 디렉터가 방법을 바꿔 다시 시킬지, 검사 결함으로 보고 사용자에게 물을지 정한다. 문턱을 에이전트가 스스로 낮추지 않는다.
- 다시 돌릴 때 0·1단은 늘 돌리고, 2·3단은 캡처 해시가 바뀐 판만 돌린다.

### 4.3 탐색 모드

"카메라 방식 고르기"처럼 그림이 덜 된 채로 골라야 하는 회차가 있다(1회차가 그랬다). 사용자가 "모두 통과하지 못하면 보여줄 필요 없다"고 했으므로 기본은 전부 통과다. 탐색 회차는 **지시문에서 미리** `gate.profile: explore`와 "이번에 고르는 것"(예: 카메라 각)을 선언한다.

| | 기본(show) | 탐색(explore) |
|---|---|---|
| 0·1단 | 전부 통과 | 전부 통과 |
| 2·3단 | 전부 통과 | 고르는 것과 닿는 검사만 통과(카메라면 D1·D2·M1·L1~L4). 나머지는 돌려서 값만 싣는다 |
| 미리보기 | 통과 딱지 | 맨 위에 "탐색용 — 그림체·효과는 아직 관문 전" 띠와 떨어진 검사 표 |
| 누가 정하나 | — | 디렉터가 지시문에 적고, 사용자에게 한 줄로 알린다. 캡처 뒤에는 못 바꾼다 |

탐색을 쓸지는 사용자가 정할 일이다(6절 열린 질문).

### 4.4 요약 한 장 (`gate-summary.md`, 미리보기 맨 위에도 같은 표)

```
관문: PASS (show) · 2026-11-18 03:12 · 캡처 5판 55장 · 다시 돌린 횟수 2
판    결(D)  색(C)  반복  구성(L)  HD-2D(H)  떨림  판독
F2a   6/6    4/4    통과   4/4     5/5       0.04  V1 7/7 · V2 0/6
...
묶음: 설정 Mobile·1.0·SRP 켬 일치 · 콘솔 에러 0 · 성능 그리기 212 / 렌더 2.4ms(앞 2.57)
고친 것: 1차 C2(나무 ΔE 9 → 31), R1(0.98 → 0.21) · 2차 H3(0.90배 → 1.3배)
면제: F-int D1(지시문에서 선언)
자동으로 못 본 것: 움직임 느낌, 방식 셋 중 취향 → 직접 봐 주세요
직접 연 캡처: (경로와 본 것)
```

"직접 연 캡처" 줄은 관문이 채우지 않는다. 디렉터가 연 뒤 적는다(핵심 규칙 6절은 관문이 있어도 그대로다 — 관문 통과는 "열어 볼 자격"이지 "봤다"가 아니다).

### 4.5 미리보기 도구 잠금

`sheet.py`가 `measure.py` 기록(`<sha256>.compare.json`)이 PASS이고 최신일 때만 그림을 싣는 것과 같은 방식이다.

| 장치 | 내용 |
|---|---|
| 기록 | `gate.py run`이 `gate-result.json`에 캡처마다 sha256, 판정, 설정 파일 해시, 기준서 승인 해시를 적는다 |
| 페이지 만들기 | `gate.py page <out.html>`만 페이지를 만든다. 싣는 그림마다 지금 sha256이 기록과 같고 판정이 PASS(또는 baseline·면제)인지 확인. 아니면 `NO_PAGE`와 이유, 종료 코드 1 |
| 손으로 만든 페이지 | 페이지에 `gate-result` 해시를 메타 태그로 넣는다. 디렉터 규칙: 이 태그가 없거나 기록과 다른 페이지는 사용자에게 열지 않는다 |
| 일부러 보여 주기 | `--unverified "<이유>"`: 페이지 맨 위와 해당 그림에 빨간 띠(`sheet.py`와 같음). 이유 없이는 못 쓴다. 실패 설명용이지 통과 대신이 아니다 |
| 낡음 | 그림·설정·문턱·기준서 중 하나라도 바뀌면 기록이 낡은 것으로 본다 |

## 6. 우선순위

### 6.1 시안 2회차에 바로 넣을 최소 묶음 (반나절)

2회차 지시의 통과 기준 다섯 줄과 1회차에서 실제로 걸린 것만 고른다. 14개.

| 순 | 검사 | 이유 | 필요한 것 |
|---|---|---|---|
| 1 | G1·G2·G3·G4 | 묶음이 온전한가 | manifest(파일 목록·해시) — 지금 `source-fingerprint.json`을 넓힘 |
| 2 | S1 | P7 재발 방지. 2회차 통과 기준 "Mobile 품질 숫자" | `measure2-*.json`의 `quality` |
| 3 | G5·M1·D1 | 2회차 통과 기준 "떨림이 1.73보다 작다" | `motion-analysis` 형식 그대로 |
| 4 | D3·D4 | 2회차 통과 기준 "배경 도트 = 캐릭터 도트", P8 | 영역 상자 또는 `closeup-*.png` |
| 5 | C2 | 2회차 통과 기준 "나무·소품이 풀과 갈린다" | 영역 상자 |
| 6 | R1 | 2회차 통과 기준 "네모 칸 반복 없음" | 바닥 견본점 |
| 7 | D2 | 1회차에서 새로 드러남(N1). 효과를 세게 하는 2회차에서 더 위험 | `*-height-mask.png`(이미 있음) |
| 8 | H3 | 2회차 지시 "그림자가 키의 1~1.5배" — 숫자 하나 | manifest의 해 방향 |
| 9 | `gate.py page` 잠금 + 요약 한 장 | 사용자 요청의 본체 | — |

- 구현 추정: `gate.py`(검사 14개 + 기록 + 페이지 잠금) 3~4시간 — 이번 실험 스크립트 세 개가 2단 검사의 초안이다. 캡처 도구에 manifest·영역 상자 더하기 1시간 [추정].
- 영역 상자를 2회차에 못 넣으면: D3·D4는 근접 캡처에서, C2·R1은 지시문에 고정 좌표를 적어 돌린다(이번에 쓴 방식). 그때는 결과에 "손 영역"이라고 적는다.
- 2회차 캡처가 이미 끝났으면 다시 찍지 않고 있는 파일로 돌린다(해 방향은 코드에서 읽는다).
