VERDICT: DESIGN

## 1. 검사 목록

**설계 원칙:** 시안 묶음을 한 번 수집해 자동 검사와 구조화된 모델 판독을 수행하고, **해당 단계의 필수 검사가 모두 PASS일 때만 사용자 미리보기를 만든다.** 실패한 그림은 에이전트 수정용으로만 사용한다.

근거 원본은 [1회차 지시](.director/runs/20261118-hd2d-lookdev/steps/1-Deadsurvivor.md), [2회차 지시](.director/runs/20261118-hd2d-lookdev/steps/2-Deadsurvivor.md), [아트 기준서 r5](docs/art/아트-기준서.md), [r6 초안](docs/art/아트-기준서-r6-초안.md)이다. **2회차 지시의 명시적 시안 조건은 적용하되, r6 초안 전체를 승인된 기준으로 취급하지 않는다.** 예를 들어 F의 10%, F-int의 약 8.9%는 시안 조건이며 본 게임 C1의 영구 변경이 아니다.

표의 `[계산]`은 이번 파일에서 산출한 값, `[추정]`은 제안 기준·시간이다. `BLOCKED`는 필수 증거 부족, `NOT_RUN`은 미실행으로 둘 다 공개를 막는다. A는 효과 없는 **대조군**이므로 HD-2D 효과 검사는 사전 정의된 `N/A`다. 실패한 후보를 사후에 대조군으로 바꾸지는 못한다.

- 기존 이동 지표는 ROI `[915,495,1000,625]`의 정수 이동 보상 후 RGB 절대차 평균이며, 표는 프레임 1~7의 **최댓값**이다. F=1.73은 묶음 평균이 아니다. 인물 전용 지표와 ROI 지표의 큰 차이는 배경 혼입 가능성을 보여 준다.
- 기존 정사영 수집기는 이미 카메라 이동을 화면 픽셀 격자로 반올림한다. 따라서 기존 F를 “snap하지 않은 기준”으로 소개하면 안 된다.
- 풀 표본은 모든 main 이미지의 `(20,990)~(1900,1060)`이다. RGB 채널 중앙값을 Lab D65로 바꿔 K7 풀 6색과 비교했다. **이 한 영역의 통과가 화면 전체·흙길·나무색 통과는 아니다.**

## 2. 자동으로 못 보는 것과 모델 판독

**“HD-2D스럽다”, “우리 도트와 같은 결이다”는 숫자 하나로 확정할 수 없다.** 수치 검사를 통과한 묶음에 구조화된 모델 판독을 붙여 공개 관문에 포함한다. 통과는 **검토 가능한 후보**라는 뜻이며, 방향 채택은 사용자에게 남긴다.

| 판독 축 | 판독 질문 | 3점의 조건 |
|---|---|---|
| 그림체 일관성 | 캐릭터 옆의 나무·바위가 같은 작품의 그림으로 읽히는가? | 매끈한 면·질감 밀도·외곽선 충돌이 눈에 띄지 않음 |
| HD-2D 깊이 | 도트 인물·3D 공간·빛·그림자·흐림이 함께 작동하는가? | 깊이가 읽히며 화면 효과가 전투 가독성을 해치지 않음 |
| 읽기 쉬움 | 인물·몬스터·소품이 바닥과 즉시 구분되는가? | 전체 크기에서 역할·실루엣이 갈림 |
| 바닥 품질 | 네모 반복·흙길 이음·과도한 노이즈가 보이는가? | 전체 화면과 근접 모두 중대 반복 결함 없음 |
| 움직임 | 카메라 이동과 애니메이션이 자연스러운가? | 도트 재표본화·얼굴 변화·소지품 소실 등 중대 결함 없음 |

점수는 0=판독 불가, 1=명백한 위반, 2=수정 필요, 3=공개 가능한 후보, 4=기준에 잘 맞음으로 고정한다. **평균으로 상쇄하지 않고 두 판독자의 모든 필수 축이 각각 3 이상**이어야 한다. 각 답은 이미지 해시·영역 좌표·관찰·심각도·수정안을 포함하며 근거 없는 칭찬은 판정으로 인정하지 않는다.

- 판 이름·제작 방식·생성 모델·이전 점수를 가리고 순서를 섞는다. 컨셉과 현재 도트 그림은 기준 자료로 함께 준다.
- 100% 전체 화면, 최근접 4배 확대, 순서가 보존된 이동 프레임을 준다. 축소 컨택트시트만으로 통과시키지 않는다.
- Codex와 Fable이 독립 판독한 뒤 교차 확인한다. 불일치는 평균내지 않고 문제 영역을 수정·재판독한다. 단순 취향 차이로 남으면 이미지 공개 없이 사람 결정 필요 상태를 보고한다.
- 숫자 측정은 도구가 맡는다. 모델이 눈짐작한 ΔE·배율·프레임 시간을 수치 검사 결과로 쓰지 않는다.

**이번 설계의 판독 상태:** 독립 Codex(`gpt-6.1-sol`, medium) 검토 1회를 받아 기준 충돌·F 떨림 지표·공개 우회 위험을 반영했다. Fable은 현재 연결 도구와 로컬 명령에서 찾지 못해 **NOT_RUN**이다. 두 모델 합의 설계로 보고할 수 없으며, 향후 판독 연결이 없을 때도 조용히 한 모델로 대체하지 않는다. 이 설계 작업에서는 외부 업로드를 하지 않았다.

## 3. 속이기·잘못된 통과 위험

| 위험 | 잘못되는 판정 | 방지 |
|---|---|---|

| 빈 장면·정지 프레임 | 떨림·성능이 매우 좋음 | 객체 수·이동량·카메라 행렬·프레임 번호·비교 마스크 존재 확인 |

| 조명받은 외곽선 색 | 원본이 맞아도 C2 FAIL | 원본 색과 최종 화면 명료성을 별도로 검사 |
| 오래된 PASS 복사·판 누락 | 좋은 판만 공개 | 요구 목록 전체와 내용 해시 결속. 필수 후보 누락 시 묶음 거부 |

| 기존 설정 변경을 이번 작업 탓으로 돌림 | 다른 세션 작업을 복원하며 덮음 | Git HEAD가 아니라 **작업 시작 상태**와 비교 |
| 좋은 시안이 임의 수치로 탈락 | 기준을 만족시키느라 그림이 나빠짐 | `[추정]` 한도는 채택/거절 사례로 보정. 기존 명시 기준과 새 탐지 지표를 구분 |

미보정 수치는 승인된 미술 기준으로 가장하지 않는다. 최소판에서는 기존 명시 기준을 수치로 검사하고, 반복·그림체처럼 아직 보정되지 않은 항목은 **필수 모델 판독**으로 다룬다. 이후 정량 검사를 추가할 때 같은 항목의 중복 판독을 줄일 후보도 함께 기록한다.

## 4. 관문 흐름과 수정 루프

| 순서 | 실행 | 예산 [추정] | 실패 시 |
|---|---|---:|---|
| 0 | 프로필·필수 목록·도구·모델 연결 준비 확인 | 2초 | 캡처 전에 BLOCKED |
| 1 | 묶음·디코딩·지문·설정 검사 | 5~15초 | 누락/설정 원인만 수정 |
| 2 | 같은 묶음에서 축척·색·떨림·가림·효과 분석 | 15~40초 | 실패 영역과 관련 증거만 재수집 |
| 3 | 성능 원표본 검사. 없거나 무효면 지정 조건 재측정 | 1초 / 20~40초 | PC 측정 등 무효 결과 폐기 |
| 4 | 독립 모델 2개가 묶음을 나란히 판독 | 60~120초 | 수정 목록을 모아서 한 번에 전달 |
| 5 | 모든 필수 PASS 확인 → 허가 기록 → 미리보기 생성·최종 열기 | 5~10초 | 생성/표시 오류면 공개 보류 |

**목표는 기존 캡처 분석 1~3분, 재측정 포함 약 4분 이내다.** 모델 지연을 포함해 회당 4분 상한을 두며 시간 초과는 PASS가 아니다. 수정·재생성 시간은 검사 시간과 따로 기록한다.

수정 루프는 `실패 분류 → 수정 → 관련 캡처 갱신 → 같은 기준 재실행`이다. 같은 방식으로 두 번 실패하면 방법을 바꾼다. 재생성 대신 채택 그림 손질, 3D 소품 대신 세운 도트 판, 위치 snap 대신 정수 배율 등으로 전환하되 **기준·필수 판 목록을 낮추지 않는다.**

루프는 횟수만으로 종료하지 않는다. 실행 시작 때 정한 총 시간·비용 상한에 도달하거나, 기준 변경·취향 채택처럼 사람 결정이 필요할 때 중단한다. `[추정]` 시안 묶음 수정 예산은 30분으로 시작하고, 중단 시 그림 없이 회차별 수치·시도 방식·남은 결정을 보고한다.

**공개 도구의 강제 조건**

기존 `sheet.py`는 이미지 해시와 신선한 비교 기록을 확인하지만, `--unverified`, props/candidates 예외와 부분 통과 이미지 출력 경로가 있다. 따라서 장면 공개에는 별도 엄격 진입점 `show.py`를 둔다.

- `show.py`가 현재 입력을 다시 해시하고 전체 필수 PASS를 확인해야 HTML·시트·애니메이션을 생성한다.
- 허가 기록에는 요구 목록·소스·설정·이미지·기준서·검사기·모델 응답의 해시를 포함한다. 하나라도 바뀌면 허가 무효다.
- 장면 공개 진입점에는 `--unverified`와 부분 묶음 공개 옵션을 제공하지 않는다. 실패 진단 그림은 에이전트 작업 폴더에만 둔다.
- 검증된 원본을 그대로 표시하고, 확대는 nearest로 한다. 최종 HTML의 모든 자원 연결·이미지 디코딩도 확인한 뒤 연다.
- 도구 경로와 디렉터 규칙을 함께 적용한다. 임의 HTML 작성까지 막는 운영체제 보안 장치라고 주장하지 않는다.

사용자에게 붙이는 요약 한 장은 다음 필드로 고정한다.

| 구분 | 표시 내용 |
|---|---|
| 범위 | 시험 시안/본 게임, 판 목록, 실행 시각·짧은 지문 |
| 관문 | 필수 N/N PASS, 프로필·기준서 버전, 사전 정의 N/A |
| 핵심 수치 | 인물 높이·도트 비·떨림 두 지표·색 분리·화면비 |
| 성능 | 환경/설정, 300마리, draws·frame 평균/p95/최대. 에디터/기기 구분 |
| 판독 | Codex·Fable 축별 점수와 근거, 알려진 한계 |
| 사용자 결정 | 통과 후보 중 어떤 방향을 채택할지. 자동 PASS와 채택 구분 |

기존 도구를 통째로 화면 검사에 적용하지 않는다. 특히 `frames.jitter`는 애니메이션 부위 변화 검사이며 **카메라 이동 떨림 검사와 다르고**, `layers.py`는 횡스크롤 합성용, `tileprev.py`는 원근 캡처 자체의 반복 탐지기가 아니다. 계산 함수와 증거 구조만 필요한 범위에서 재사용한다.

**Python 의존성:** 확인한 `.ai/2d-art/config.json`에는 Python 경로 항목이 없다. 기본 `python3`는 Python 3.15이며 Pillow·NumPy가 없고, `/usr/bin/python3`가 가리키는 Xcode Python에는 둘 다 있다. 이번 이미지 계산은 `/Applications/Xcode.app/Contents/Developer/usr/bin/python3`로 실행했다. 킷 설치 시 `ART25D_PYTHON`을 명시적으로 선택하고 `PIL`·`numpy` import와 버전을 검사한다. 자동 설치나 기본 Python으로의 묵시적 대체는 하지 않는다.

규칙 문장은 다음으로 제안한다.

> “2.5D 시안·화면은 해당 단계의 필수 자동 검사와 독립 판독이 모두 PASS인 현재 묶음만 사용자에게 보여 준다. 누락·미실행·오래된 증거·설정 불일치는 공개를 허용하지 않는다. 실패하면 수정하고 같은 기준으로 재검사한다. 방향과 채택은 사용자가 결정한다.”

이는 이번 사용자 지시에 따라 기존 art-core 6절의 **공개 순서**를 바꾸는 제안이다. “직접 캡처를 연다”, “숫자는 재서 쓴다”는 요구는 유지한다. 프로젝트 값은 설정·기준서에 두고 킷에는 게임 이름·절대 경로·컨셉 이미지·개인 기록을 넣지 않는다. **이번 작업에서 킷 수정·업로드는 하지 않았다.**

## 6. 우선순위

| 단계 | 넣을 것 | 구현 시간 [추정] | 공개 조건 |
|---|---|---:|---|
| **지금 2회차 최소판** | manifest·PNG 디코딩/해상도·해시 결속·실제 설정·카메라/축척·기존 두 떨림 지표·성능 원표본·필수 모델 판독·엄격 `show` | **약 4시간** | 필수 검사 전부 PASS. 수치화가 미완인 그림체·반복·가림·효과는 모델이 직접 판독. 모델 연결 불가는 BLOCKED |
| 다음 묶음 | 객체 ID/알베도/조명 계수·효과 OFF 진단, 도트 두 축·명암·외곽선·개체별 색·가림 정량화 | 1~2일 | 모델 판독과 대조 보정 후 정량 gate로 승격 |
| 본 게임 4~8단계 | UI 안전영역·전투 상태·가림 이동 경로·방향/애니메이션 회귀·실기기 성능 | 단계별 추가 | 해당 화면·상태 계약과 기기 예산 충족 |
| 킷 승격 | 공용 증거 모듈 추출·설치 검사·스키마·정상/실패 fixture·디렉터 계약 | 최소판 실사용 뒤 | 공개 우회·오래된 PASS·누락·모델 오류 반례 시험 통과 |

최소판의 필수 반례는 **PC 설정 성능, 누락 프레임, 수정된 PNG/기준서, 검은 화면, 멈춘 이동, 부분 후보 공개, 모델 시간 초과**다. 기존 도구 selftest는 설치·도구 변경 때 실행하고 매 시안마다 반복하지 않는다. 검사 추가와 함께 **매번 전체 Play, 변경 없는 성능 재측정, 같은 그림의 중복 리뷰, 수기 카메라 계산**을 제거 후보로 기록한다.

이번 자료에서 가장 중요한 설계 보정은 **설정 설명을 믿지 않기(P7), F=1.73을 인물 떨림으로 단정하지 않기, 색 통과를 그림체 통과로 승격하지 않기**다. 코드·문서는 수정하지 않았다. 시간 집계 명령은 결과 파일 쓰기가 필요해 읽기 전용 환경에서 차단됐으며, 정확한 시간·토큰 집계는 **BLOCKED**다.
