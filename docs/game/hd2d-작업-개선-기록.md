## 5. 킷에 넣을 절차 초안

### 5.1 에디터 단계 나란히 돌리기 — 워크트리 + 에디터 따로 (A22)

**왜**: 에디터가 하나라 에디터가 필요한 단계(배경·UI·빛)를 줄 세웠다. 사용자 지적(11-18 12:0x): 서로 크게 연관 없는 단계는 워크트리를 나눠 나란히 돌릴 수 있다. 처음 적용: 5단계 배경(메인 폴더) ∥ U단계 UI(`.director/worktrees/hd2d-ui`, 브랜치 `claude/hd2d-ui`).

**나란히 돌려도 되는 단계 고르기** — 아래가 모두 참일 때만:
| 확인 | 이번 예 |
|---|---|
| 서로가 만든 결과를 **재는** 일이 없다 | UI ∥ 배경: 예. 빛 ∥ 배경: **아니오** — 빛은 땅·물·턱의 밝기·색을 기준값에 맞추는 일이라 배경이 없으면 다시 해야 한다 → 빛은 배경 뒤 |
| 고치는 코드 폴더가 겹치지 않는다(겹치면 한쪽은 읽기만) | UI: `UI/`·`Features/*/View`(UI_), 배경: `Features/Field/`·배경 패스 |
| 공유 파일(장면·설정)은 **다시 돌려도 같은 결과가 나오는 이행 메뉴로만** 바꾼다 | 둘 다 `Main.unity`를 바꿈 → 이행 메뉴(에디터 스크립트)로만, 손으로 바꾼 장면 값 금지 |
| 성능 측정은 나란히 하지 않는다 | 7단계는 모두 합친 뒤 한 번(에디터 여러 개가 CPU를 나눠 쓰면 숫자가 틀린다) |

**절차** (이번에 실제로 한 순서, 걸린 시간):
1. 나란히 쪽이 읽을 문서·설계를 먼저 커밋한다(워크트리는 커밋된 것만 받는다). 다른 단계가 같은 폴더에서 일하는 중이면 `git commit --only -- <경로>`로 그 경로만 커밋해 남의 스테이징을 끌고 가지 않는다.
2. `git worktree add -b claude/<단계> .director/worktrees/<단계> <커밋>`(`.director/worktrees/`는 git 무시 목록에 있다).
3. **Library 복제**: `cp -c -R Library <워크트리>/Library`(APFS 복제, 4.2GB가 13초). 복제 안 하면 첫 열기에서 전체 가져오기(수십 분). 복제 뒤 `Library/EditorInstance.json`은 지운다.
4. 로컬 패키지 경로 확인: `Packages/manifest.json`의 `file:../…`가 워크트리 안에서도 맞는지(이번: `file:../3dkit/unity` — 3dkit이 추적 파일이라 워크트리에 있음).
