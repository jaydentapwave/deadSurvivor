## 3. 지금 시험하는 방식 (D29·D30, 2026-11-17 19:41부터)

1. **넣기 갈래를 나란히 돌린다.** A 걷기·공격 + 그림자, B 들판 장식, C 아이콘 32종을 각자 worktree에서 Codex가 만든다. 에디터는 쓰지 않는다. D UI는 UI 그림이 정리된 뒤에 시작한다.
2. **갈래 안에서는 코드·데이터·테스트만 만든다.** 컴파일·EditMode 실행·Play·캡처·리뷰는 하지 않는다. 데이터를 바꿨으면 `tools/check_data.py`만 돌린다.
3. **준비가 핵심이다.** 그림 `.meta`를 루트 에디터로 먼저 만들어 커밋했다(f59575e). 그래서 갈래들이 같은 GUID를 쓴다. 버린 후보 그림은 게임 폴더에 넣지 않는다.
4. **합칠 때는 루트에서 하나씩 한다.** 브랜치를 합치고, 에디터가 가져오기·컴파일을 하고, 충돌(아틀라스 등 공유 파일)은 디렉터가 푼다.
5. **마지막 확인은 한 번만 한다.** 컴파일, EditMode 1번, 한 판 판정 1번, 성능 수치 1번, 리뷰 묶음(spec·validator·algorithm) 1번, 디렉터가 Play 캡처를 직접 연다. UI가 바뀌므로 화면비 4개는 이 한 번에만 찍는다. 전투·피드백 경로를 따로 돌리는 것은 뺀다.
6. **판정에 못 미치면** 고치고 같은 판정을 다시 돈다(AGENTS.md). 회차와 시간을 [작업 시간 기록](작업-시간-기록.md) 4절에 적는다.

**위험과 대응**

| 위험 | 대응 |
|---|---|
| 컴파일 오류가 합칠 때 한꺼번에 나온다 | 갈래 지시문에 "쓰기 전에 시그니처를 grep으로 확인하고 다시 읽기"를 넣었다. 오류는 디렉터가 합치면서 고친다 |
| 같은 파일을 두 갈래가 고친다 | 갈래를 나눌 때 파일이 겹치지 않게 묶었다(그림자는 걷기와 같은 갈래). 공유 파일은 줄을 더하기만 한다 |
| 결함을 늦게 발견한다 | 리뷰와 Play를 마지막에 모아서 한 번 보고, 거기서 찾은 것은 한 번에 고친다 |
