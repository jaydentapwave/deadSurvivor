## 3. 확인 방법 — 바뀐 범위만 (사용자 "한개 수정했는데 전체를 검증하는 실수는 없었으면해")

| 바뀐 것 | 그때 하는 확인 | 하지 않는 것 |
|---|---|---|
| 그림 한 장(텍스처·스프라이트) | 그 그림의 판정(measure/paint/형태) + 그 그림이 나오는 화면 짧은 Play 캡처 1장 | 판정 경로 전체, EditMode 전체, 리뷰 |
| 재질·셰이더·빛 값 | 컴파일 + 그 화면 캡처 + 관문의 해당 검사만(`check`는 판 하나) | 다른 화면, 성능 전체 |
| 런타임 코드 한 기능 | 컴파일 + 그 기능의 EditMode 테스트(`-testFilter`) + 그 화면 짧은 Play | 판정 경로 전체 |
| UI 한 화면 | 그 화면 캡처 4화면비 | 다른 화면 |
| 단계 마감(게임 동작 파일이 마지막 전체 PASS 뒤 바뀜) | 판정 경로 전체 1회 + EditMode 전체 1회 | 같은 단계 안 반복 |
| 기능 마감 | 마감 리뷰 묶음 한 번(병렬), FAIL만 수정 확인 | 지적 하나마다 리뷰 |

- **성능은 마지막에 한 번만**(사용자 11-18 "300마리를 검증을 할떄 굳이 캡쳐를 왜하는건지", "최적화개념인데 이거는 지금 단계에서 매번 테스트를 하는게 아니라, 아트 완료된 후에 적용까지 완료된다으메 마지막에 테스트를해서, 검증을 해야하는데 매번 하고 있는것 같아"): 시안 회차·4~6단계·U단계에서는 300마리·버닝 성능을 재지 않는다. 아트 관문의 G19는 `deferred`(킷 2621d7f 다음 커밋)로 N/A. **7단계(아트·UI 적용이 모두 끝난 뒤)에 한 번** 실제 10웨이브 버닝으로 재고(캡처 없이 숫자만: 활성 몬스터 수·렌더러 수·실제 품질·그리기·프레임), 예산을 넘을 때만 줄이는 작업을 한다. 8단계 마감 관문은 deferred를 비운 설정으로 돌린다.
- 고친 뒤에는 **고친 지적의 재현만** 다시 본다. 전체 Play는 단계 마감에 한 번(art-core-rules 1절).
- 관문(gate.py)은 판 단위로 돈다. 그림 하나가 바뀌면 그 그림이 든 판만 다시 찍어 `check`한다.
- 판정에 못 미치면 고쳐 다시(같은 방법 2번 실패면 방법을 바꿈, AGENTS.md). 사용자에게 묻지 않는다.
