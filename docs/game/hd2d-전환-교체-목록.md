# HD-2D 전환 교체 목록 — 게임의 모든 시각 요소

- 작성: 2026-11-18 13:3x, Claude(효과 교체 하위 작업, 디렉터 지시). 사용자 원문(11-18): "지금 현재 hd2d로 변경하는만큼 이펙트나 프로젝트타일등도 모두 교체가 되어야해, 이것도 studio-kit에서 활용할 수 있게금 정리하면서 작업을 진행해줘".
- 목적: 2D 판에서 화면에 나오던 것을 **빠짐없이** 세고, 하나하나가 HD-2D에서 어떤 규칙(기준서 행)으로 바뀌는지, 지금 어디까지 왔는지를 한 표로 본다. 끝에 게임과 무관한 **킷 점검표**.
- 상태 말: **끝**(커밋) / **진행**(단계·워크트리) / **예정**(지시문이 있는 단계) / **빠짐**(어느 단계 지시문에도 없음 — 이번에 찾은 것). 개수는 파일·코드에서 셌다(13:2x, `find`·`grep`). 화면에서 재지 않은 것은 `추정`.
- 단계 이름은 [완성 실행 계획](hd2d-완성-실행계획.md): 4 = 화면 기반 W0~W7, 5 = 배경 B0~B9, 5d = 8방향, U = UI(워크트리 `claude/hd2d-ui`), 6 = 빛 L0~L6, 7 = 성능, FX = 이번 효과 교체, 8 = 마감 관문, 9 = 킷.

## 2. 킷 점검표 — "2D/3D → HD-2D 전환 때 바꿔야 할 시각 요소"

게임과 무관하게 쓴다. 전환을 시작할 때 이 표를 게임 파일에서 하나씩 세어 "2D 판 / HD-2D 규칙 / 맡은 단계"를 채운다. **맡은 단계가 비어 있는 행이 하나라도 있으면 시작하지 않는다**(이번 게임에서는 효과·투사체·예고 표시 13행이 비어 있다가 4단계 뒤에 발견됐다).

### 2.1 세는 법
- 런타임 그림: `grep -rln "SpriteRenderer\|LineRenderer\|ParticleSystem\|TextMeshPro"` (Editor 제외) — 뷰 하나마다 행 하나.
- **코드가 만드는 임시 그림**: `grep -rn "Sprite.Create\|CreateBox\|CreateCircle\|new Texture2D"` — 이번에 빠진 것(예고 선·폭발 범위·적 탄)은 모두 여기 있었다. 그림 폴더만 세면 놓친다.
- 데이터의 그림 키: 효과 대응표(`combat_effects.json` 같은 것)의 값마다 — 한 그림이 다른 용도로 재사용된 곳(이번: 폭발 그림을 파동 고리로)을 찾는다.
- 재질·셰이더: 프리팹·장면이 참조하는 재질 GUID를 모두 풀어 "빛 받음 / 빛 없음 / 발광 / 후처리 뒤"로 나눈다.

### 2.3 모든 행에 같은 네 질문
1. **어느 면에 있나** — 세운 판(카메라 기울기만큼 세움, 돌리는 빌보드 아님) / 눕힌 판(Euler(90,0,0) + 1 mm) / 3D 배경(도트화 패스) / 후처리 뒤 / UI 캔버스.
2. **도트 밀도가 캐릭터와 같은가** — 세운 판 1 텍셀 = 1/PPU m, 눕힌 판 가로 1/PPU m × 깊이 1/(PPU·sinθ) m. 실행 중 소수 배율·임의 각도 회전이 없는가.
3. **빛을 받나, 내나** — 받는 것(몸·화살) / 안 받는 것(효과) / 내는 것(심만 Bloom 문턱 위).
4. **짧은 것은 어떻게 판정하나** — 0.2~0.5초 효과는 정지 캡처 한 장이 아니라 연속 캡처나 상태 숫자(art-core-rules 1절).
