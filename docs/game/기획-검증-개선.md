# 기획·검증 개선 — 사용자가 보기 전에 품질이 자동으로 나오게

- 쓴 날: 2026-11-18. 쓴 쪽: 디렉터(메인 세션). 상태: **이 프로젝트 남은 단계에 바로 적용 + studio-kit 반영 초안**.
- 사용자 원문:
  - "계속내가 피드백을 하는거보니깐 검증 및 기획이 제대로 잡히지않아서 인것 같다는 생각이드는데"
  - "기획쪽도 좀 더 개선이 많이 되어야할것 같아, 그래야 우선 내가 보기전부터 자동화가 되어서 어느정도의 퀄리티는 나외야되서 이것도 문서를 남겨줘"
- 관련 기록: [작업 개선 기록](hd2d-작업-개선-기록.md) P13·P14·P18·P19·P20, 킷 후보 A23~A26. [완성 실행 계획](hd2d-완성-실행계획.md) 1절(C1·C2 고침, C10 새로).

## 0. 목표

사용자가 처음 보는 순간에 "이건 기본이 안 됐다"는 지적이 나오지 않는다. 사용자 피드백은 **취향과 방향**(더 밝게, 이 구성이 더 좋다)에 써야 하고, **빠짐·어긋남·눈에 띄는 결함**은 사용자가 보기 전에 기계와 디렉터가 걸러야 한다.

| 피드백 종류 | 누가 잡아야 하나 | 이번에 실제로 누가 잡았나 |
|---|---|---|
| 빠진 요소(효과 그림 교체 누락) | 기획(전체 목록) | 사용자 — P19 |
| 구성 품질(직선 길·사각 연못·무작위 배치) | 검증(맵 전체 판독) | 사용자 — P18 |
| 검증 시점·방법(매 회차 300마리 측정, 측정 중 캡처) | 기획(검증 설계) | 사용자 — P12·P14 |
| 눈에 띄는 그림 결함(위장 무늬, 흰 공 바위) | 검증(두 모델 판독) | **판독이 잡음** — P13, 5~8회차 |
| 취향(옥토패스 들판형 고르기, 외곽선 넣기) | 사용자 | 사용자 — 정상 |

판독(두 모델)이 들어간 뒤로 그림 결함은 기계가 잡았다. 남은 구멍은 **기획 단계**다: 무엇을 바꿔야 하는지, 무엇이 "됨"인지, 무엇을 볼지가 시작 때 정해지지 않았다.

## 1. 원인 (P20 자체 진단)

1. **전체 목록 없이 단계부터 나눴다.** 캐릭터·배경·빛·UI 단계 표를 먼저 만들어, 어느 단계도 맡지 않은 요소(효과·투사체·예고 표시)가 생겼다.
2. **완성 정의가 "있음"을 셌다.** "재고표 행마다 게임에 있음", "효과가 들어감" — 보이는 품질·구성 기준이 없었다.
3. **검증 범위가 좁았다.** 아트 관문 판이 시작 화면 한 장이라 맵 전체 구성은 아무도 보지 않았다.
4. **결정을 사용자 원문과 대조하지 않았다.** 하위 에이전트 권장값을 일괄 확정했다(D-1 "옛 2D 길 유지"는 원문 "바닥들도 모두"와 어긋남).
5. **"사용자가 처음 보면 뭐라고 할까"를 미리 묻지 않았다.** 사용자가 한 지적 대부분은 레퍼런스와 나란히 놓으면 바로 보이는 것이었다.

## 2. 기획 단계가 반드시 내야 할 것 (만들기 전에)

만들기를 시작하기 전에 아래 6개가 모두 있어야 한다. 하나라도 없으면 구현 단계를 띄우지 않는다(도구로 막을 후보: 6절).

| # | 산출물 | 내용 | 이번 프로젝트 파일 |
|---|---|---|---|
| Q1 | **시각 요소 전체 목록** | 게임의 모든 시각 요소(캐릭터·몬스터·상태·바닥·길·물·소품·그림자·빛·효과·투사체·예고 표시·월드 UI·화면 UI·글꼴) × 전환 전 모습 × 목표 규칙(기준서 행) × **맡은 단계** × 지금 상태. 코드·에셋 폴더를 훑어 만들고(사람 기억 X), 맡은 단계가 빈 행이 0이어야 시작 | [전환 교체 목록](hd2d-전환-교체-목록.md)(작성 중) |
| Q2 | **사용자 원문 대조표** | 사용자 원문 한 줄 → 요구 → 그것을 만족시키는 요소(Q1 행)·검사(Q4 행). 디렉터 결정·하위 에이전트 권장값을 확정할 때마다 이 표와 대조하고, 어긋나면 확정하지 않는다 | 이 문서 5절에서 새로 만든다 |
| Q3 | **보이는 품질 기준** | 요소마다 "있음"이 아니라 "이렇게 보여야 됨": 레퍼런스 관찰에서 온 기준 + **하지 않을 것 목록**(직선 길, 사각 물, 고른 간격 흩뿌림, 같은 무늬 반복, 부드러운 그라데이션, 2D 시절 그림 그대로). 숫자 목표에는 상한·모양 조건을 함께(P13) | 기준서 K행 + 이 문서 3절 |
| Q4 | **검증 설계** | 무엇을 어떤 화면에서 어떻게 볼지: ① 덮는 범위(맵 전체 위에서 본 그림, 화면 N곳, 이동 연속 8장, 화면비, 상태별) ② 숫자 검사 ③ 두 모델 판독 축과 통과선 ④ 언제(단위 확인 / 단계 마감 / 맨 끝 — 성능은 맨 끝 한 번) ⑤ 바뀐 범위만 다시 보는 규칙 | 완성 계획 3절 + C10 |
| Q5 | **사전 실패 상상** | "사용자가 처음 보고 할 말" 10개를 미리 적는다(레퍼런스와 나란히 놓고). 하나하나를 Q3 금지 항목이나 Q4 검사로 바꾼다 | 이 문서 4절 |
| Q6 | **기획 검토** | Q1~Q5를 다른 모델 계열이 검토: 목록이 코드·에셋을 다 덮는가, 원문 대조에 빈 칸이 없는가, 검증이 "있음"이 아니라 품질을 보는가 | 남은 단계부터 |

## 3. 보이는 품질 기준 — "있음"을 "보임"으로 바꾸는 법

| 요소 | 있음(옛 기준) | 보임(새 기준) | 기계 검사 | 판독 축 |
|---|---|---|---|---|
| 맵 구성 | 재고표 행이 게임에 있음 | 길은 곡선·폭 변화·경계 도트 계단+풀포기, 물은 유기 모양+물가 띠, 나무는 군락·숲 가장자리, 랜드마크(다리·야영지)가 시작 화면 둘레에 보임, 구역 변화(닳은 흙·자갈·꽃밭) | 길 꺾임 각 상한, 직선 구간 길이 상한, 물 윤곽 볼록 사각형 아님, 소품 최근접 거리 분포(뭉침 지수), 같은 무늬 자기상관 상한 | 구성, 반복, 빈 곳 |
| 효과·투사체 | 위치가 3D로 옮겨짐 | 그림이 캐릭터와 같은 도트 밀도·팔레트, 심만 Bloom 문턱 넘음, 0.2~0.5초 효과는 연속 프레임으로 동작이 읽힘 | 텍셀 크기 = 인물 도트, 색 수·채도 범위, 빛나는 픽셀 비율 상한 | 무슨 효과인지 읽힘, 그림체 일치 |
| 캐릭터 8방향 | 파일이 폴더에 있음 | 8방향 걷기·공격이 게임 화면에서 방향대로 바뀌고 다리가 번갈아 나옴 | 방향별 대신 쓰기 횟수, 장 수 | 방향 맞히기, 움직임 |
| UI | 그림이 붙음 | 레퍼런스 결(반투명 판·가는 테·마름모 초상), 5화면비·노치에서 잘림·겹침 없음 | 누름 44px, 글자 9 이상, 안전 영역 | 결 일치, 읽힘 |
| 전체 화면 | 판정 경로 8/8 | "완성된 HD-2D 게임처럼 보이나" | — | 두 모델 판독(C10) |

## 7. studio-kit에 넣을 곳 (A26)

- `director-game`·`director-run` 기획 단계: Q1~Q6을 기획 산출물로, T6 기획 관문을 실행기 앞에.
